# 补充篇 · 第 8 章 · 侧重点地图（时间精力该花在哪）

> 101 集知识很多，但**不是每块都值得平均用力**。这一章直接告诉你：哪里最值钱、哪里最容易翻车、哪里可以快进。
> 用途：纠结「先做啥 / 该多花时间还是少花时间」时，看这张图。

---

## 一、三个「最该花时间」的地方（决定成败）

### 1. 市场研究（方向对了才不白干）
- **为什么最值钱**：方向错了，后面再努力都是白费。花 2 天把「市场有没有机会、对手弱在哪、用户真痛点」搞清楚，胜过闷头开发 2 周。
- **该做什么**：行业分析 → 竞品分析 → 用户调研（别验证自己的想法，去挖真痛点）。
- **一句话**：**先证明「有人需要」，再动手做。**

### 2. 需求定义（排对优先级才不做不完）
- **为什么最值钱**：需求排错了，会范围蔓延、做不完、返工。用 `Kano` + `RICE` 把优先级排对，能省下大量返工时间。
- **该做什么**：需求澄清 → 需求池 → Kano/RICE 排序 → 写 PRD（含验收标准）。
- **一句话**：**需求不是越多越好，是排对优先级。**

### 3. 评测（AI 产品的命门）
- **为什么最值钱**：AI 会「沉默失败」（答错但不报错），不评测就不知道做对没、改差没。花时间建 `评测集`（黄金集），每次改完考一遍。
- **该做什么**：构建评测方案 → 做黄金集 → 跑评测 → 定位→修→再测。
- **一句话**：**没有评测，就不知道做对了没。**

---

## 二、三个「最容易翻车」的地方（必须小心）

### 1. 需求范围蔓延（做着做着失控）
- **翻车场景**：说好做「AI 客服」，客户不断加「要语音、要 App、要报表」→ 没重新谈价 → 越做越多、越做越亏。
- **防法**：需求池 + 优先级排序 + 「加需求就重新谈范围/价格」。

### 2. 上线没灰度没回滚（出事故没法退）
- **翻车场景**：一次性全量上线 → AI 答错（沉默失败）→ 用户投诉才被发现 → 没法退。
- **防法**：灰度上线（先 5%）+ 回滚预案（上线前备好）+ 监控（主动盯质量）。

### 3. AI 沉默失败（最危险的故障）
- **翻车场景**：AI 自信地给了错答案，页面全绿没人报警。
- **防法**：主动评测 + 监控「转人工率 / 不满意率」等质量指标，别只看「有没有报错」。

---

## 三、三个「可以快进」的地方（别陷进去）

### 1. 认知底座（快速过，别钻牛角尖）
- 大模型/transformer 的原理，**理解「能干啥、不能干啥、为什么牛」就够了**，不用啃数学公式。
- 一句话：建立直觉，不做研究员。

### 2. 方案设计（够用就好，别过度设计）
- 一句话问答不需要 Agent，多步骤有分支才需要。别上来就上复杂架构。
- 一句话：**先 MVP，再迭代**。

### 3. 框架细节（用的时候再查）
- LangChain/LangGraph 的具体 API，**用到再查官方文档**，不用背。
- 一句话：理解机制，不背 API。

## 四、一张「时间精力分配建议」总表

| 环节 | 建议投入 | 为什么 |
|---|---|---|
| 市场研究 | 🔴 **多花** | 方向错了全白干 |
| 需求定义 | 🔴 **多花** | 排错优先级会返工 |
| 评测 | 🔴 **多花** | AI 命门，沉默失败 |
| 上线交付 | 🟡 适中 | 灰度+回滚，保命但不复杂 |
| 商业化 | 🟡 适中 | 早想清楚，但别拖延执行 |
| 方案设计 | 🟢 少花 | 够用就好，别过度设计 |
| 开发实现 | 🟢 少花（先 MVP） | 先跑通，再迭代 |
| 认知底座 | 🟢 少花 | 建立直觉即可，别钻公式 |

## 五、落到王昕的业务上（怎么用这张图）

你的业务是「企业 AI 交付 + 获客系统 + 8895 知识库」，这套侧重点地图可以直接用：

1. **接客户时** → 重点做「市场研究 + 需求定义」：先搞清楚客户真痛点、真需求，用 `Kano`/`RICE` 排优先级，写清 PRD（含验收标准），避免范围蔓延。
2. **交付时** → 重点做「评测 + 上线」：给客户交付前先建 `评测集` 证明「能用」，上线用灰度 + 回滚，别让客户「AI 答错了才发现」。
3. **做 8895 知识库** → 重点抓「检索质量」：RAG 是工程问题，切块/向量化/重排做对了，知识库才准。
4. **获客系统** → 重点抓「评测 + 监控」：AI 筛选线索、发消息，要主动监控质量，别「沉默失败」漏掉真客户或发错消息。

---

> 记住这张图的核心：**三个「多花」（市场研究、需求定义、评测），三个「小心」（范围蔓延、无灰度上线、沉默失败），三个「快进」（认知底座、方案设计、框架细节）。**
