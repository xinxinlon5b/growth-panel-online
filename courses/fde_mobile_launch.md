## 引子：这 60 分钟怎么安排

直播开场，卢菁博士直接给出行程单：**前十几分钟把 FDE 这个岗位说清楚（用数据佐证）→ 中间 30-40 分钟现场实操（时间不可控），从一句话需求做到上线、可访问 → 最后几分钟回对 JD、讲课程**。实操使用的数据有两路：**四家大厂官网抓取的真实 JD 数据 + 观众当场投票的数据**——也就是说，现场观众投什么，系统就长什么样。

为此直播开了两个投票（助理发链接 + 公告栏 + 屏幕可见），开播即投、实操开始即截止：

- **投票①**：你公司的 AI 项目走到哪一步？三选一——已经落地在用了 / 卡在试点的 POC / 还没有启动。
- **投票②**：六件事里你最缺哪一件？——把客户一句模糊的话变成方案 / 让 AI 准确回答公司自己的资料 / 让 AI 自己调用工具连接系统 / 把部署做到上线 / 说清楚它到底准不准 / 把客户的原话谈明白。

投票结果被设计成**稍后实操系统的实时数据源**——这是整场直播最有心机的一步：观众不是看客，是需求方和数据提供方。

## 第一章｜FDE 是什么：四个数据 + 一句话定义

**四个数据把岗位热度钉死在屏幕上：**

| 数据 | 数值 | 口径 |
|---|---|---|
| 2026年4月 FDE 相关岗位数 | **5330 个** | 平台聚合 / 领英口径 |
| 一年岗位增长 | **729%** | 领英统计 |
| 国内猎聘月薪区间 | **1万–10万+** | 拉了几十条招聘信息 |
| 大厂普遍区间 | **3万–7万** | 因地区、行业、资历浮动 |

**一句话定义**：在 AI 工具加持下，到客户现场，把客户的需求变成一个**跑得通的、在生产环境可用的系统**。它**不是研究模型的岗位**——模型能力已经过剩，FDE 干的是"让模型在客户的生产系统上落地能用"。

**为什么突然缺人？卡住的不是模型，是"最后一公里"，有四件事：**
1. **需求说不清**——用户想用 AI 提效，但讲不清自己真正要什么；
2. **数据是脏的**——真实生产数据有各种问题；
3. **老系统难连**——原有各种系统很难连接起来；
4. **没人敢负责**——一旦交付上线，没人敢直接拍板负责。

> 这四件事，没有一件是 AI 自己能解决的——这正是岗位存在的理由。

**OpenAI 招聘 JD 原文**给了最权威的定义："Full-arc Discovery, Technical Scoping, System Design, Building"，翻译过来就是**从需求发现 → 技术排定（Scoping）→ 系统设计构建 → 生产上线**的全过程。

**两种从业形态（很多人不知道第二种）：**
- **驻场 FDE**：去客户现场出差驻场；
- **内部 FDE**（有的公司叫 **AI BP**）：不跳槽，在自己公司把 AI 落进自家业务。招聘网站上内部 FDE 薪水基本也在 3-7 万。

> 换句话说：想转 FDE 不一定要离职——你可以成为"你现在的公司里，能把老板的需求、现有业务用 AI 落地的那个人"。这是全片给打工人留的一条隐藏高薪路线。

## 第二章｜FDE 不是什么：三个"不是"

讲完是什么，用三个"不是"做切割（每个都配了大厂 JD 原话）：

**① 不是售前。** 售前是讲方案、签完约就交出去；**FDE 是签完约才开始**，要对结果负责。腾讯 JD 原话：**"主导落地交付、上线护航"**。一句话：**签完合同，才是开始。**

**② 不是运维。** 运维保证系统能跑、别挂掉；**FDE 决定系统该变成什么样子**——有什么功能、长什么样。某大厂 JD 原话：**"独立完成技术架构决策"**。运维是系统挂了去处理，FDE 是让它别出问题。

**③ 不是驻场外包。** 外包按人天出活、听甲方指挥；**FDE 对业务结果指标负责**，某大厂 JD 原话：**"对客户业务结果指标负责"**。行业里确实有人管这岗叫"高级驻场外包"，但主讲给出灵魂辨析：**你是按人天卖时间赚钱，还是对结果负责？** 这两条路的"前途/钱途"完全不一样。

## 第三章｜FDE 的一天：六步 + 谁适合学

**FDE 一天干六步**（也是后面实操演示的骨架）：
1. **把模糊需求变成方案**——客户说"我想要个 AI"，但他到底要什么、做到什么程度算成功，要沟通清楚、帮他书面化；
2. **定契约**——数据长什么样、字段怎么对齐、拿不准的内容谁来拍板；
3. **处理脏数据**——格式不统一、口径打架、缺字段……真实数据从来都是脏的；
4. **把东西做出来**——主讲特意指出：以前这是最麻烦的开发环节，**现在反而是最快的一步，因为 AI 可以自己跑、自己开发**；
5. **检验 / 自测**——AI 可能说"我测好了没啥问题"，实际有没有问题必须人再去检验，也要求它自测，**保证确实没问题才允许上线**；
6. **上线交付**——一切 OK 后上线，等客户验收。

**"未来人人都是 FDE"** 是主讲反复强调的判断：FDE 说白了就是**一个人 = 一个小团队**——以前要一个团队才能交付的事，现在一个人就能搞定，所以薪水要求都高。

**谁适合学（先天优势人群）：**
- **在职开发 / 测试 / 运维**：缺的不是代码，是客户视角；
- **售前 / 解决方案 / 项目经理**：缺的是动手做出来——现在 AI 可以补；
- **传统 IT 集成**：本来就做交付，这是最大优势；
- **自由职业接单 / 创业**：最懂用户想要什么；
- **行业专家（医药、物流、电力、金融等非互联网岗）**：这些行业都在找 FDE，**行业经验就是你的底牌**——AI 落地一定是落进行业业务，而不是通用聊天。

**关于零基础**：在校生、跨专业学生可以学、能学会，但这岗位确实要求经验——**工具几天就能学会，难的是丰富的行业经验与判断力**。想速成不太现实；无经验者学完后，需要靠**多轮真实项目实战锤炼**再去找工作。

## 第四章｜实操开场：案例定义、边界与工具选型

**要做的产品叫「FDE 岗位雷达」**：把抓来的 28 条大厂 JD 能力要求 + 观众投票的"最缺什么"，放进**同一张页面/同一张图**，自动算出"你应该先补哪块、补哪个"。一句话需求 + 真实数据，最后交付一个**公网链接，手机能打开，还能看到自己刚投的票、继续投票**。

**边界声明（今晚不做什么）**：不现场爬招聘网站、生产环境数据不处理、不收集任何个人信息、投票不当行业数据统计——投票只是**定性参考**。

**7 步实操流程（S1-S7）**：成型需求 → 定数据契约 → 处理脏数据 → 做出来（产出公网链接）→ 自测暴露问题 → 交付上线 → 回到验收。

**工具选型**：FDE 课**不限工具**。主讲平时在多工具间切换（口播提到国外的 Claude Code、Codex 类，国内的 Trae 及一款转写音译为"workbody/我个八得"的国产可免费 AI 编程 Agent——主讲明说"平时不用它，是为了大家都能用才用它演示"，并接受它免费版与收费工具的能力差距）。现场用的模型是当时较新的一个版本，并选择"日常办公"模式——因为这次写代码量不大，办公/开发模式区别不大。**选工具的第一原则：不限工具、按场景切换、够用即可。**

## 第五章｜实操全程拆解：S1-S7 逐步入坑与爬坑

### S1｜成型需求：先把一句话需求"澄清掉"

第一步**先不写代码**。主讲把提前写好的提示词整段贴给 AI（现场写来不及，提示词都是预跑过、提前准备好的——这点很重要，后面还会强调），核心结构是：

- **交代背景与需求**：做 FDE 岗位雷达、直播演示页、单文件同源部署；两路数据（JD 侧从某处抓取的 JD 数据稍后发；供给侧是观众投票的两个公开接口——免鉴权、直接 GET 就能拿到 JSON，接口文档稍后发）。**数据两侧都已定死，不需要它猜测。**
- **列明已拍板事项**：全场聚合、不做个人评价、交付形态=单 HTML……这些不要再问、不用论证。
- **核心指令——像 FDE 一样把需求澄清掉**：这东西给谁用？解决什么问题？**不做什么**（哪些功能不做）？给出**三条可验证的验收标准**（能一条条打勾的那种）。
- **执行纪律**：直接在对话里回答、不要写文件、全文不超过多少字、**不要问我问题**；拿不准的直接写一行假设，我事后复核；**不要在内部思考里反复推敲措辞和顺序，想清楚立马给结果**（防止陷入死循环）。

**为什么这么写？** 主讲点破大多数人的两种失败姿势：
- 一句话扔过去让它开干 → AI 会**自己猜、自己做决策**，写出来大概率不是你要的；
- 放开让它随便问 → 预跑时试过，它光想"该怎么问我"就想了**半小时一个字没出来**。

所以取中间态：**不许问，但每处不确定必须留一行假设**。这份假设清单不是废料——**它就是 FDE 要拿去跟客户逐条确认的问题清单**。AI 11 秒给出结果：给谁用、解决什么问题、不做什么（不采集、不做单岗位深度解析等）、三条可打勾的验收标准，条条命中。

### S2｜定数据契约：只产一份 PRD

第二步把两个投票接口文档 + 六个能力选项的"人话说法"发给 AI，要求**只做一件事：产出 PRD 文档**，包含：JD 的 JSON 字段设计、字段映射/枚举表（口播音译"硬色表"，即选项归类与取值设计），**拿不准的归类单独列一栏待复核**——依旧不许反问，不确定写假设，一次性做完。

主讲点评：**这一步"最像 FDE 的内容"**——对外部系统的字段对齐，就是腾讯 JD 里"打通 CRM/ERP/OA"干的同类事，只不过这里是两个投票接口。AI 很快在工作目录下产出 PRD 文档，字段设计、映射表、待复核清单三件套齐活。

### S3｜处理脏数据：识别岗位"马甲" + 产出可审计资产

第三步把**从四家大厂官网抓取的完整 Markdown 原始 JD** 发给 AI（强调：官网抓的，不是第三方），让它**按 PRD 里的契约产出真实的 JD JSON，并统计六项能力的市场分布**。

**为什么说这数据脏？因为同一岗位有四件"马甲"**（这是本场最有求职价值的一段）：
- 有的厂叫 **AI 前沿部署工程师**；
- 海外叫法即 **Forward Deployed Engineer**（前沿部署工程师）；
- 阿里云叫**前沿部署工程师**；
- 蚂蚁叫**客户技术解决方案架构师（FDE 方向）**；
- 智谱（口播音译"制谱"）**根本不叫 FDE**，叫**交付中心**相关岗位。

> 干的活其实一样，叫法五花八门——**在招聘网站上只搜"FDE"三个字母，一定会错过大量岗位；识别同一岗位的不同马甲，本身就是求职能力**。这条对做内容/求职方法论的人都是金句素材。

此外**粒度参差**：有的 JD 是全文、有的只有几个要点；技能点散落在"岗位职责/岗位要求/加分项"三个位置。AI 在沟通过程中已经把活干完，产出 JD JSON 文件并在内置浏览器视图打开。

**为什么数据要较真？** 真实交付里**客户一定会问"这数据哪来的"，你必须要答得上**——这叫**可审计**。大厂 JD 原话是：**每个项目至少要留下一个跨客户可复用的资产**。这份经过清洗、来源留痕的 JD 数据，就是这个项目的可复用资产。

### S4｜构建开发：单 HTML 硬性验收项 + 当场翻车

第四步的提示词写得极细——**四条硬性要求是"验收项"不是"建议"**，主讲逐条强调，全是经验总结：
1. **接口失败要有兜底，而且必须让人看见**（不许悄悄失败）；
2. **绝不允许静默降级**（口播音译"净莫降级"）；
3. **票数为零的格子照常显示，不许隐藏**；
4. **页面必须标明样本数量 N，不允许显示百分比**——因为样本可能很少，百分比会误导；
5. 附加：**手机要能正常读取**（观众很多在手机上访问）。

技术形态：**单 HTML、零外部依赖、PC 和手机双端可打开**，三块面板 + ABCD 对照。麻雀虽小五脏俱全，流程和大型项目一致，只是每步都大幅简化。

**翻车①**：AI 跑完后，打开页面发现**数据没正常显示**——有 bug。让 AI 处理，它**诚实地承认是它自己的 bug，不是接口的问题**（主讲特意测过接口没问题）。主讲借机点题：**现场实操总会有不可控因素，预跑过也会翻车，包括时间会多用一点**——处理完刷新，页面正常：投票①显示 24 个样本（含沿用上一场直播的数据），落地在用/卡 POC/未启动分布清晰；投票②有 9 人投，数据展示得很清楚。

### S5｜自测暴露问题：AI 卡死，果断打断跳过

第五步让 AI **自己挑毛病**，硬要求：**不许编，用真实接口数据列问题**；提示了关心的方向后依旧不许反问，让它一次性跑完、改完汇报。

结果翻车②：**AI 陷入迷茫迟迟不出结果**（主讲判断：免费工具与收费工具能力确实有差距——平时不用它，为观众能上手才选它）。等了一分钟后果断**打断、停掉**，并给出重要判断：**"让它挑错"不是必备环节，挑不出问题也没关系**——因为最后人肉验收会兜底。这本身就是 FDE 式的人机分工：**AI 卡住不耗着，人在关键处接管。**

### S6｜部署上线：沙盒干不了的，人两行命令搞定

部署环节，主讲把命令贴出来自己执行：**AI 工具在沙盒里执行不了云端服务器的部署命令**（翻车③，但主讲说这活儿本来也不需要它干）——单页面上传只需**两行命令**；**只有复杂部署才需要上 Claude Code 这类 Agent 去执行**。命令执行完，第三个链接（公网地址）立即可访问，页面与本地看到的完全一致，**手机上能打开、能投票、能看结果**。40 分钟的交付闭环在公网落地。

### S7｜回到验收：7 步 = 大厂 JD 的浓缩

最后把 7 步回对 JD 原文（这是全片的"对答案"环节）：
- S1 需求澄清 → **"明确目标边界与验收标准"**（阿里系 JD 原话）；
- S2 定字段/对齐 → 腾讯 JD 写 **"MCP 打通 CRM、ERP、OA"**——干的就是对外部系统字段对齐的同类事；
- S5 自测挑毛病 → 某大厂 JD 写 **"构建评估管道和可观测框架"**；腾讯 JD 写 **"客户高管沟通与现场问题拆解能力"**；
- 数据可审计 → **"每个项目至少留下一个跨客户可复用的资产"**。

> 演示的 7 步是这些要求的浓缩版——真做细节，光一步就可能要几十分钟，直播只能简化。**但再小的项目，也是一条完整的 FDE 交付链路。**

## 第六章｜结尾与答疑：金句浓度最高的 20 分钟

交付后进入互动答疑，金句密度极高，择要记录：

- **关于零基础**：学完一个月就想找工作，不适合；但"未来人人都应该是 FDE"——**你可以不做 FDE 岗位，但至少要具备 FDE 的能力**，一个人要具备一个团队的能力，这每个职场人都需要。
- **关于个人服务本地小微企业**：完全可行，"**你一个人就代表一个团队**"，去落地小微企业的各种 AI 需求——这就是主讲自己天天在干的事（一人公司，从需求到交付全包）。
- **关于转型**：做过六年工程师、干过运维的，非常适合。大环境不好、AI 冲击所有岗位，**想胜出就得"一人多岗"——一个人能解决多个人的问题，公司就需要这样的人**，竞争力指数级上升。
- **FDE vs Agent 开发**：一定会是 FDE——**FDE 是综合岗（需求→设计→开发→测试→部署→交付全链路），Agent 开发只是其中一个开发岗**。
- **关于经验**：经验会被 AI 无限放大；没经验就补经验，把 7 步流程多走几个真实项目就成长起来了。反之，现在只会手撸代码找"Java/大厂开发"岗，几乎没机会。
- **工资逻辑**："一个人干四五个人的活，老板给你发三个人的工资——老板省了钱，你也赚了钱。" 所以大厂 FDE 三五万都算少的。
- **工具与提示词**：不同人用同一个 AI 工具，产出和效率完全不同——**提示词都是提前准备好的，现场写来不及**；不是 AI 工具强大到人人一样。

# 下篇 · 方法论精华（可迁移框架）

## 1. FDE 岗位认知速查卡

| 维度 | 结论 |
|---|---|
| 定义 | AI 加持下到客户现场，把需求变成生产环境可用的系统 |
| 为什么缺人 | 最后一公里四件事：需求说不清 / 数据脏 / 系统难连 / 没人敢负责 |
| 全链路 | Full-arc：需求发现 → 技术排定 → 系统设计构建 → 生产上线 |
| 三不是 | 不是售前（签完才开始）、不是运维（决定系统长什么样）、不是外包（对结果负责非卖人天） |
| 两种形态 | 驻场 FDE / 内部 FDE（AI BP，不离职内转路线） |
| 转型优势人群 | 开发测试运维、售前方案 PM、IT 集成、自由接单、行业专家（行业经验=底牌） |
| 隐藏求职点 | 同一岗位多马甲（前沿部署/客户技术解决方案架构师/交付中心…），只搜 FDE 必漏 |

## 2. 七步交付法（S1-S7）——可复制的主干流程

| 步骤 | 输入 | AI 产出 | 人的动作 |
|---|---|---|---|
| S1 成型需求 | 一句话需求 | 给谁用/解决啥/不做什么/可打勾验收标准 + 假设清单 | 写清背景、拍死决策、执行纪律 |
| S2 定契约 | 两侧数据接口文档 | PRD（JSON 字段设计+枚举/映射表+待复核清单） | 核对假设清单 → 对客户逐条确认 |
| S3 处理脏数据 | 原始抓取数据 | 按契约的干净 JSON + 能力统计 | 来源留痕（可审计）、沉淀可复用资产 |
| S4 构建开发 | PRD + 硬性验收项 | 可运行产物 | 把验收项写进提示词当硬约束，人工验证 |
| S5 自测 | 产物 + 真实数据 | 挑错并修复（可中断跳过） | AI 卡死即接管；人肉验收兜底 |
| S6 部署上线 | 产物 + 服务器 | —— | 简单部署两行命令人执行；复杂部署交给 Agent |
| S7 验收 | 上线链接 | —— | 逐条打勾验收标准，回对原始需求 |

## 3. 可复用提示词模板（直播核心干货）

**需求澄清提示词五件套**：
1. **背景 + 数据定死**：要做什么、交付形态、两路数据从哪来——已定的不要它猜；
2. **要澄清的四问**：给谁用 / 解决什么问题 / 不做什么（显式列"不做清单"）/ 三条可打勾的验收标准；
3. **执行纪律**：直接对话回答、不写文件、限制字数、不问问题；
4. **假设留痕**：拿不准必须写一行假设——假设清单 = 你对客户的确认清单；
5. **防死循环**：禁止在内部思考里反复推敲措辞顺序，想清楚立即给结果。

**两种反模式**：一句话开干（AI 瞎猜、自作决策）；放开随便问（预跑实测：想怎么问想了半小时零产出）。正解是中间态：**不许问 + 假设必留痕**。

**构建提示词的验收项写法（数据诚实四原则，可直接抄进任何数据页需求）**：
- 接口失败要有兜底且必须让人看见（fail loud，禁静默降级）；
- 零票格子照常显示不隐藏；
- 样本量小必须标 N、不许显示百分比；
- 交付物要手机可读（移动端优先验证）。

## 4. 翻车清单（RCA + 处置）

| 翻车 | 根因 | 处置 |
|---|---|---|
| 首版页面数据不显示 | AI 自身 bug（非接口问题，接口已预测） | 让 AI 修 + 当场刷新验证；接受现场不可控是常态 |
| 让 AI 自测时卡死无输出 | 免费工具与收费工具能力差距 | 等一分钟果断打断；自测环节可跳过，人肉验收兜底 |
| 沙盒执行不了云端部署命令 | 工具运行环境限制 | 人执行两行命令；复杂部署才上 Agent |

**人机分工总原则**：构建/写码是最该交给 AI 的一步（最快）；需求澄清、契约、验收、决策必须人做；AI 卡住不耗着，人在关键节点接管；演示/交付选"大家都能用"的工具，日常干活选自己顺手的工具，多工具按场景切换。

# 借鉴篇 · 我们能借鉴的点（结合我们的业务）

我们是企业 AI 落地咨询 / 智能体交付团队，本质就在做 FDE 式交付。这场直播几乎是把我们的活法公开演示了一遍，可直接借鉴六条：

**1. 把交付流水线固化成一模一样的 S1-S7 + 提示词五件套，接到每个客户项目上。** 我们常犯的毛病是"需求没澄清就开写"。直播给的解法极实用：每步提示词都写"背景拍死 + 不许问 + 不确定留一行假设 + 假设清单 = 对客户确认清单"。落动作：做一套《客户项目 S1-S7 交付模板》（含每个 S 的提示词、输入输出、人要做的事），小项目照抄执行，大项目逐 S 展开——既提速又防"AI 瞎猜返工"。

**2. 验收标准必须"能打勾"，且把数据诚实约束写死进提示词。** "接口失败必须让人看见、禁静默降级、样本少就标 N 不显示百分比"这几条，正好治我们交付看板/数据页的老毛病（接口挂了页面静默、样本少却给百分比结论）。落动作：把 fail-loud、标样本量等条款做成**交付验收检查项**，进我们的交付清单与黄金集评测标准。

**3. 人机分工：AI 卡死不耗着，人在关键节点接管。** 直播三连翻车（AI bug、自测卡死、沙盒不能部署）都被"人接管"化解。落动作：项目交付预跑时就要有 Plan B——AI 自测不行就人肉验收，部署命令人手一份、随时接管；同时给客户演示时工具选"客户也能上手"的，降低信任门槛。

**4. 每个项目至少沉淀一个"跨客户可复用资产"，且来源可审计。** 客户问"数据哪来的"必须答得上。落动作：交付时同步产出数据清洗稿/PRD/提示词模板三类资产入库（对应我们的黄金集/评测集体系），来源留痕；下次同类客户直接复用，边际成本递减——这正是我们从小项目走向产品化交付的杠杆。

**5. "识别马甲"双向用在销售上。** 直播说只搜 FDE 会漏掉岗位——反过来说，客户嘴里的"AI 落地、智能化、数字化转型、效能提升"全是同一需求的马甲。落动作：谈单第一轮别急着报价，先用需求澄清四问（给谁用/解决啥/不做什么/怎么算成）把"马甲"扒开；对接客户决策人时，优先找"对业务结果负责"的人，而不是"按人天买时间"的人。

**6. 一人一团队的全链路交付，就是我们对小微客户的产品化报价模型。** 直播金句"一个人干四五个人的活"正是我们接小项目的商业模式。落动作：报价单从"开发 X 功能"改为"从一句话需求到手机可访问的公网系统"的整包叙事，并把**公网链接手机可开**设为标准验收物——客户在自己手机上打开的那一刻，比任何 PPT 都有说服力；这也可以做成获客钩子（免费 40 分钟演示场，复刻本直播的"投票定需求+当场上线"玩法，比宣讲转化率高得多）。

**7.（内容弹药）实操型直播 = 最好的获客内容样板。** 本场把"真实数据 + 观众投票 + 当场翻车修复 + 公网可访问成果"组合成 65 分钟高信服内容，结尾顺势带货课程。落动作：我们做内容/直播时，别只讲方案，直接现场从一句话需求做到可访问产物；翻车不剪掉，当场拆解修复——真实感就是转化率。
