# 补充篇 · 第 3 章 · SOP 详拆① 市场研究与需求（阶段 1-2）

> 做产品最怕「方向错、需求乱」。这一章把「怎么判断该不该做 + 怎么把需求理清楚」拆成一步步。
> 对应：第一册第 1、2、3 章（行业分析/竞品分析/用户调研/需求分析/PRD）。

---

## 一、市场研究三步（阶段 1 · 最值钱的一步）

做产品前，先花时间搞清楚三件事：**市场有没有机会、对手强不强、用户真需要吗**。顺序别乱：

### 第 1 步 · 行业分析（看大盘）

**做什么**：判断这个行业「值不值得进、趋势往哪走」。

**怎么做（4 小步）**：
1. **看规模**：这个市场有多大、增速多少（用公开报告，别拍脑袋）。
2. **看趋势**：是上升期、成熟期、还是衰退期（用 `PEST` 框架：政策/经济/社会/技术）。
3. **看竞争格局**：是蓝海（没几个对手）还是红海（拼杀激烈）。
4. **看技术成熟度**：AI 在这个行业「现在能不能落地」，还是「概念阶段」。

**小白例子**：你想做「AI 帮跨境电商写俄语文案」。
- 规模：中俄跨境电商在增长（中俄班列/珲春口岸，地利）。
- 趋势：上升期，政策支持。
- 竞争：有做翻译的、有做文案的，但「懂俄语 + 懂电商场景」的少。
- 技术成熟度：大模型写多语文案已经成熟，能落地。
→ **结论**：有机会，值得深入研究。

**侧重点**：这一步别贪多，回答一个问题就够了——**「这行业值得我花时间吗？」**

### 第 2 步 · 竞品分析（看对手）

**做什么**：拆解对手，找「差距」和「机会」。

**怎么做（4 个维度）**：
1. **他做什么**：功能清单（核心功能 + 次要功能）。
2. **他强在哪**：体验？数据？渠道？价格？
3. **他弱在哪**：用户吐槽什么、缺什么场景。
4. **我能学什么 / 差异化什么**：不是抄，是「他哪里没做好，我能补上」。

**小白例子**：继续「俄语文案」这个产品。
- 竞品 A（翻译工具）：强在准确，弱在「不懂电商场景」（不会写卖点/促销语）。
- 竞品 B（文案模板）：强在模板多，弱在「不会根据具体商品定制」。
- **你的机会**：做「懂电商场景 + 能按具体商品定制」的俄语文案，正好补两者的弱。

**侧重点**：竞品分析最容易犯的错是**只列功能表**，不分析「对方为什么这么做、用户为什么买账」。重点挖「对手的弱 + 用户的痛」。

### 第 3 步 · 用户调研（看真实用户）

**做什么**：别猜用户要什么，去问真实用户。

**怎么做（3 小步）**：
1. **找到真用户**：谁会用你的产品（跨境电商卖家？）。
2. **问对问题**：问「现在怎么做的、最烦哪步」，别问「你要不要这个功能」（用户会客气说「要」）。
3. **挖真痛点**：他愿意为「解决这个烦」付多少钱？

**小白例子**：问 10 个做中俄电商的卖家：「你现在怎么写俄语文案？」答案可能是「找翻译，一条 20 块，还经常翻得不像人话」。→ **真痛点**：贵 + 不像人话。

**侧重点**：**用户调研是「挖痛点」，不是「验证你的想法」**。别问「你要不要 AI 写文案」，要问「你现在写文案最烦什么」。

## 二、需求定义四步（阶段 2 · 最容易翻车的一步）

调研完，你会收到一大堆「我觉得要做这个、那个」。这时最容易乱——**需求不排优先级，就会范围蔓延、做不完**。

### 第 1 步 · 需求分析（把模糊问清楚）

**做什么**：把「客户/老板/用户」嘴里模糊的话，问成能落地的话。

**怎么做**：三个来源的需求会打架——**老板要的、客户要的、用户要的**。你要做的是「问清楚 + 平衡」：
- 他说「要个机器人」→ 问「是自动回客服，还是自动发广告？」
- 他说「要高级点」→ 问「高级 = 什么功能？谁在用？」
- 三方需求冲突 → 回到「用户要什么」这个原点。

**小白例子**：老板说「做个 AI 客服」。你要问清楚：是「自动回复常见问题」，还是「能查订单、能退款」？前者简单，后者复杂 10 倍。

**侧重点**：**需求澄清是产品经理的第一能力**——问不清楚，做出来一定不是人家要的。

### 第 2 步 · 需求池（先收集，再排队）

**做什么**：把四面八方来的需求，先扔进一个「池子」，别急着做。

**怎么做**：
- 建一个表/文档，每条需求写：**谁提的、想要什么、为什么、优先级（先空着）**。
- 不删任何需求，但也不立刻做——先收集。

**小白例子**：销售说「要个报表」、客服说「要自动回复」、老板说「要做成 App」。全扔进需求池，然后进入第 3 步排序。

**侧重点**：**需求池的价值是「别被最新一条需求牵着走」**——先收集，再统一排优先级。

### 第 3 步 · 优先级排序（Kano + RICE）

**做什么**：决定「先做哪个、砍掉哪个」。

**怎么做（两个工具）**：

**① Kano 模型**（分三类）：
- **必须有**（基本型）：没有它产品没法用。例：AI 客服「答得准」。
- **加分项**（期望型）：做了更好，不做也还行。例：「能语音回复」。
- **惊喜项**（兴奋型）：做了用户「哇」。例：「主动预测客户想问啥」。

**② RICE 评分**（量化打分）：`RICE = 触达人数 × 影响程度 × 信心 ÷ 成本`
- 触达人数：这个需求影响多少用户。
- 影响程度：影响大不大（1-3 分）。
- 信心：你有多确定（百分比）。
- 成本：做起来要多少时间/钱。

**小白例子**：
- 需求 A「答得准」：影响所有人（1000 人）→ 必须有，先做。
- 需求 B「能语音」：影响少部分人（200 人）→ 加分项，后做。
- 需求 C「主动预测」：影响所有人但成本高 → 惊喜项，最后做。

**侧重点**：**Kano 分「必须/加分/惊喜」，RICE 算「先做哪个」**。两个一起用，需求就不乱了。

### 第 4 步 · 写 PRD（把需求写成文档）

**做什么**：把「做什么」写成一份开发能照着做的文档。

**怎么做（PRD 至少写清 4 件事）**：
1. **做什么**：核心功能一句话 + 详细说明。
2. **为什么做**：解决谁的什么痛点。
3. **给谁用**：目标用户画像。
4. **怎么做**：功能点拆解 + 验收标准（什么样算「做完了」）。

**小白例子**（AI 客服的 PRD）：
- 做什么：自动回复 80% 常见问题。
- 为什么：客服每天被重复问题淹没，人工成本高。
- 给谁用：客服部（辅助）+ 客户（自助）。
- 怎么做：接知识库 → 识别意图 → 检索回答；验收标准 = 常见问题答对率 ≥ 90%。

**侧重点**：**PRD 的核心是「验收标准」**——写清楚「什么样算做完」，否则开发说「做完了」其实不是你要的。

## 三、这一章的小结（一张卡带走）

```
市场研究（先证明有人需要）
  ① 行业分析 → 这行业值得做吗？
  ② 竞品分析 → 对手弱在哪、我能补什么？
  ③ 用户调研 → 用户真痛点是什么？（别验证自己的想法）

需求定义（再写清楚要什么）
  ① 需求分析 → 把模糊问清楚
  ② 需求池   → 先收集，别急着做
  ③ 排序     → Kano 分三类 + RICE 算先后
  ④ 写 PRD   → 做什么/为什么/给谁用/怎么做 + 验收标准
```

> 记住：**方向对了（市场研究），力气才不白费；需求排对了（需求定义），才不会范围蔓延做不完。** 这两步是产品「从 0 到 1」最容易省、也最不该省的两步。
