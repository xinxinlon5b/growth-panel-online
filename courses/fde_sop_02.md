# 补充篇 · 第 2 章 · SOP 总流程（做 AI 产品从 0 到 1 的 8 阶段）

> 把 101 集的方法论，收成一条「从接到想法到产品赚钱」的完整流水线。
> 用途：真动手做一个 AI 产品/项目时，照着这条线一步步走，卡在哪一步就翻哪一步的详拆。

---

## 一、先记住：这套 SOP 的两个原则

1. **顺序不能乱**：先想清楚「做什么、给谁用」（阶段 0-2），再动手「怎么做」（阶段 3-4），最后「证明做对了」（阶段 5-6），收口在「怎么赚钱」（阶段 7）。**很多人一上来就写代码，结果方向错了全白干。**

2. **每阶段有「侧重点」和「坑」**：不是每一步都平均用力——有的阶段最值钱（市场研究、评测），有的阶段最容易翻车（需求定义、上线）。下面每张卡片都标了。

## 二、8 阶段总览图

```
 阶段0        阶段1        阶段2        阶段3        阶段4
认知打底 →  市场研究  →  需求定义  →  方案设计  →  开发实现
(懂原理)   (给谁做)    (做什么)     (怎么做)      (做出来)
              ↓
 阶段7 ←  阶段6  ←  阶段5
商业化    上线交付    测试评测
(赚钱)   (交付)      (证明对)
```

## 三、8 阶段详细卡片（每阶段：做什么 / 怎么做 / 侧重点 / 坑 / 产出物）

### 阶段 0 · 认知打底（别跳步）
- **做什么**：先搞懂「AI 产品经理是什么」「大模型/transformer/提示词/RAG/Agent 是什么」。
- **怎么做**：读第二册第 1 章（入门认知）+ 第 2 章（提示词），建立技术直觉。
- **侧重点**：**技术四件套**——算法、算力、数据、场景。这是你区别于传统产品经理的底牌。
- **坑**：跳过认知直接学工具 → 后面看什么都像黑盒子，被技术忽悠。
- **产出物**：脑子里一张「AI 能力边界图」（AI 能干啥、不能干啥）。

### 阶段 1 · 市场研究（最值钱的一步）
- **做什么**：搞清楚「这个产品给谁做、市场有没有机会、对手是谁」。
- **怎么做**：① 行业分析（看大盘）→ ② 竞品分析（看对手）→ ③ 用户调研（看真实用户）。
- **侧重点**：**先证明「有人需要」再动手**。行业分析看趋势、竞品分析找差距、用户调研挖真痛点。
- **坑**：拍脑袋「我觉得用户需要」→ 做出来没人用。竞品分析只看功能不看「对方为什么这么做」。
- **产出物**：一份「市场判断」——目标用户是谁、痛点是什么、竞品差距在哪、值不值得做。

### 阶段 2 · 需求定义（最容易翻车的一步）
- **做什么**：把模糊的想法，变成「写清楚、能排优先级」的需求。
- **怎么做**：① 需求分析（三方需求打架要平衡）→ ② 需求池（先收集再排序）→ ③ 用 `Kano 模型` / `RICE 评分` 排序 → ④ 写 `PRD`。
- **侧重点**：**需求不是越多越好，是排对优先级**。用 Kano 分清「必须有/加分/惊喜」，用 RICE 量化「先做哪个」。
- **坑**：范围蔓延（客户不断加需求不重新谈价）；需求不写清，开发出来不是你要的。
- **产出物**：一份 `PRD`（做什么、为什么做、给谁用、怎么做）。

### 阶段 3 · 方案设计（把需求变成蓝图）
- **做什么**：画出产品长什么样、技术怎么搭。
- **怎么做**：① 画原型（低保真 → 高保真）→ ② 设计提示词 → ③ 设计 RAG/Agent 架构。
- **侧重点**：**原型先对齐再开发**（一张图顶十页文档）；架构选型要「够用就好」，别过度设计。
- **坑**：原型画太细浪费时间；架构上来就上最复杂的方案，结果 MVP 都做不完。
- **产出物**：原型图 + 技术方案（提示词怎么设计、RAG 怎么搭、Agent 怎么编排）。

### 阶段 4 · 开发实现（把蓝图变成能跑的）
- **做什么**：动手把产品做出来。
- **怎么做**：① 搭 RAG（切块 → 向量化 → 检索 → 生成）→ ② 用 `LangChain`/`LangGraph` 编排 → ③ Agent 核心机制（`ReAct`/记忆/工具调用）→ ④ 实战跑通。
- **侧重点**：**RAG 是工程问题**（检索质量是命门）；**Agent 是编排问题**（`ReAct` = 想一步做一步）。
- **坑**：一上来追求「全自动 Agent」，结果不可控；不写测试就上线，后面修 bug 修到死。
- **产出物**：一个能跑通核心流程的 `MVP`。

### 阶段 5 · 测试评测（AI 产品的命门）
- **做什么**：证明「这个产品真的有用、真的没做错」。
- **怎么做**：① 构建评测方案 → ② 做评测集（黄金集）→ ③ 跑评测 → ④ 看核心指标 → ⑤ 数据分析 + 复盘。
- **侧重点**：**评测是 AI 产品的第一优先级**——没有评测，你就不知道改完有没有变差。用「黄金集」做标准考题，每次改完考一遍。
- **坑**：只测「快乐路径」不测「恶意路径」；评测集太宽松，掩盖了问题。
- **产出物**：一份评测报告（答对率、核心指标、哪里还不行）。

### 阶段 6 · 上线交付（最容易出事故的一步）
- **做什么**：把产品安全地交给真实用户。
- **怎么做**：① 灰度上线（先 5% 流量试）→ ② 监控（可观测性）→ ③ 出问题回滚 → ④ 复盘。
- **侧重点**：**灰度 + 回滚预案**是保命的两件事。AI 会「沉默失败」（答错但不报错），必须监控。
- **坑**：一次性全量上线，出问题没法退；没有回滚预案，改坏了只能硬扛。
- **产出物**：上线 + 监控 + 回滚预案 + 复盘记录。

### 阶段 7 · 商业化与迭代（收口在赚钱）
- **做什么**：让产品赚钱，并持续变好。
- **怎么做**：① 商业化路径（订阅/按量/按结果）→ ② 找方向 → ③ 迭代（用数据驱动）→ ④ 职业路径。
- **侧重点**：**商业化是收口**——产品再好不赚钱就是白干；**迭代靠数据不靠感觉**。
- **坑**：只会做不会卖；做完就扔，不迭代。
- **产出物**：商业化方案 + 迭代计划 + 职业方向。

## 四、一张「侧重点总表」（哪些最值钱 / 最易翻车 / 可快进）

| 阶段 | 值钱程度 | 翻车风险 | 建议 |
|---|---|---|---|
| 0 认知打底 | ★★☆ | 低 | 快速过一遍，别陷进去 |
| 1 市场研究 | ★★★ | 低 | **最该花时间**，方向对了后面才不白干 |
| 2 需求定义 | ★★★ | **高** | 花时间 + 小心范围蔓延 |
| 3 方案设计 | ★★☆ | 中 | 够用就好，别过度设计 |
| 4 开发实现 | ★★☆ | 中 | 先 MVP，别求全 |
| 5 测试评测 | ★★★ | 中 | **AI 产品命门**，必须做扎实 |
| 6 上线交付 | ★★☆ | **高** | 灰度 + 回滚，保命 |
| 7 商业化 | ★★★ | 中 | 早想赚钱，别做完再想 |

## 五、下一章怎么读

上面是「总览」，每阶段只给了一张卡片。**真动手时**，翻后面 4 篇「SOP 详拆」，把 8 阶段拆成「一步步怎么做 + 侧重点 + 小白例子」：

- 第 3 章 · 详拆 市场研究与需求（阶段 1-2）
- 第 4 章 · 详拆 设计与开发（阶段 3-4）
- 第 5 章 · 详拆 评测与上线（阶段 5-6）
- 第 6 章 · 详拆 商业化与职途（阶段 7 + 全程）

---

> 记住这条主线：**先证明有人需要（研究）→ 再写清楚要什么（需求）→ 再动手做（设计+开发）→ 再证明做对了（评测）→ 再安全交付（上线）→ 最后赚钱（商业化）。** 顺序乱了，力气就白费。
