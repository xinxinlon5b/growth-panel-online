# 上篇 · 书籍内容（原文结构化精读）

## 引子：这半年，大家不聊模型了

这是三个做了多年 AI 产品与内容的人坐在一起的一小时半闲聊。话题从一个很具体的感受开始：

**过去半年，比的不是功能，是服务。**

以前大家见面会问：你这个产品比 WorkBuddy 强在哪？跟别的 Agent 功能差在哪？现在问不出来了——因为**差的那一点，其实不在功能上**。

一个产品卖到一家公司，对方买了账号、买了 Token，不会自动就带来好结果。它跟你买飞书、买企业微信完全不一样：那些是软件，买回来大家聊天就能用；而 Agent 这个东西的**使用是因人而异的**。同一款产品，不同的人来用，差异大到离谱。

于是就有了一个必然的**落差**——模型能力和你的业务中间有一个 GAP。谁来填？填这个 GAP 的，就是现在所说的 **FDE**（前线部署工程师）。这句话再翻译一遍：

> **是服务裹着能力，而不是能力裹着服务。**

对谈里反复出现的一句总结：**很多做产品的公司要重新思考这件事**——不是「我要做一个培训团队去培训我的客户」，而是你要有这个意识：我把产品交付出去并不算完，中间还有一段落差要做。

## 第一章 · 落差从哪来：产品交付 ≠ 结果交付

嘉宾的解释链条很清楚：

1. **SaaS 时代**：用户买了 SaaS，点那几个按钮，任务就完成了。他其实根本不理解按钮背后的流程和方法，他的任务只是「把按钮点完」。
2. **AI 时代**：AI 能做的下一步，是让他**少点几个按钮**。人的认知在这件事上不可能被普遍填平。
3. **结论**：不要指望剩下 70% 的员工都拥有很好的 AI 使用方法和能力——**不可能**。你只能尽可能让那个**用得最好的 5%**，去给其他人提供自动化。

这带来一个很关键的推论：**Agent 产品要在设计里内置一套逻辑，让普通用户能用起来，才是 AI 产品的本质。** 用嘉宾的话说——「AI 的本质就是要做成一个服务」。

### 中外在产品路线上的一处明显分岔

- **海外**：做软件的人同时在输出软件的使用方法、输出实践服务，**在做的时候同时在教你用**。
- **国内**：很多大厂的认知是「砸钱推广就行」「运营/教育用户就行」；它们自己在宣传上还在**比大小**（我的功能比你多、我上了新功能），但**自己也不知道这个功能对各行业用户具体有什么作用**。

嘉宾的判断是：这是割裂的。**你不能指望拿钱做推广的人会帮你把生态服务或内容做起来**；首先得自己把这件事做起来，才能给渠道素材，生态才能转起来。

> 一个业务专家，和一个真正懂这个 Agent 产品的人，**双方得相遇**。

## 第二章 · 填平落差的三条路（对谈的核心框架）

顺着上面的逻辑，对谈提炼出了三条路径。**三条路做的是同一件事**：把「Agent 产品 + 你的业务」中间那个落差填上去。

| 路径 | 做法 | 代价 / 边界 |
| --- | --- | --- |
| ① 5% 用户外溢 | 让用得特别好的那 5% 先跑通、做自己的系统优化，其他人用他优化后的结果 | 依赖「有 5%」，且只覆盖愿意用的人 |
| ② 培训 | 提升大家对 Agent 产品的认知和使用体验 | 不可能人人培训，但「有比没有好」；原来可能只有 1%，培训能帮你把 5% 挑出来 |
| ③ FDE 进场 | 产品带着服务直接进来，现场把业务摸排一遍，摸索出一条最佳实践之路 | 培训来不及、自己的人还没长出来时用它；最贵也最快 |

**成本视角的另一层含义**：那条「5% 的路」之所以跑得起来，往往是因为有产品用**任务奖励/免费额度**的方式，让用户以极低成本、极小时间投入换取「尝试的资格」，供应充足，用户能从完全不会长到懂一点。用户量大了，总会浮现出几个**超级用户**，生态就起来了。

对谈把它形容成一个**漏斗**：先让大家装上 Agent → 先用起来 → 但「用起来」还没有带来生产力提升和结果交付 → 走到深水区，**服务还是得进去**。

## 第三章 · FDE 被偷换了：外包 ≠ FDE

对谈里有人引了一位从业者的吐槽：**国内很多所谓 FDE 是换汤不换药，纯粹是外包的脏活累活。** 真的既懂服务又懂模型、能做最后一公里落地的人，没有那么多。

嘉宾给出了一个非常干净的**判定标准**：

| | 外包式「FDE」 | 真 FDE |
| --- | --- | --- |
| 做的事 | 你公司有需求 → 我带团队来开发这个功能 → 开完就走 | 把「组织用不好 Agent 产品」这个**落差填平** |
| 结果 | 落差还在：团队走了，人还是不会用，不同人用起来差异依旧 | 组织在使用 Agent 产品时对自己的业务有了更深理解，清楚 Agent 进来之后如何运作 |
| 留痕 | 代码 | 方法与最佳实践（组织自己的脑子） |

### 一个被点名表扬的实践范本

嘉宾提到访谈过的**零一万物（转向 To B 垂直服务后）**，其对标的正是 **Palantir 的模式**——恰好就是上面「路径 ② + ③」的组合：

1. **先做公司内部培训**，培训时直接带着他们的产品在用；**培训完转化率大约 75%**；
2. 培训之后再**驻场 FDE**；
3. 他们公司里的 FDE **很多是有股权的**；
4. **FDE 的考核不是销售指标，而是「把自己抽离掉」**——衡量 FDE 成不成功的唯一指标，不是陪伴客户越久越好，而是**你走了之后，客户还能带着你的脑子运转**。

这套打法的商业结果：**每年毛利非常高，而且很多是复购。**

## 第四章 · 越土的行业，AI 越吃香

对谈中一个反直觉但被反复确认的观察：

- 过去大家以为提效最快的是**内容行业**（内容、影视），因为它们天然离 AI 近。
- 但零一万物、Palantir 这类公司**全部挑传统行业**——甚至去跟**养鸡行业**合作。

原因是结构化差异：

| | 内容行业 | 传统行业 |
| --- | --- | --- |
| 甲方自身能力 | 落地非常快，你进去发现**你用得还没他们好** | 相对慢，需要外力 |
| 链条长度 | 短 | 短、清晰 |
| 反馈速度 | 极快，飞轮容易转起来 | 建效容易、更容易出效果 |
| 付费意愿 | 已经在自我进化 | **越容易产出效果，越容易让甲方为服务付费** |

> 一句话：**越传统、越土的行业，越容易出效果。**

## 第五章 · 速度差：技术在快跑，组织在慢走

对谈里出现了全书最好用的一个比喻：

- **技术发展特别快**——两三个月就出一个新东西；
- **组织变化的速度不可能这么快**——技术一出来，组织不可能马上调；组织中的制度、利益分配、商业结构，还要更落后一点；
- 中间是一层一层的**齿轮**：小齿轮转得快，大齿轮转得慢。

**服务，就是填平这个速度差的东西。** 你拿着快的东西进到一个转速慢的企业里去，任务是「把你的速度提上来，配合最新的技术发展」。

### 一个灰头土脸的实例：OPC 的一天

有位嘉宾吐槽自己做产品时要办的事：**钱打到对方账户上花了两个月**；因为对方在搞新公司、新方式。而一旦走上正规的交付与支付渠道，「所有东西你都需要重新学」——

- 资质、公司、开票、合同、盖章，全得自己跑；
- 签 8 份合同、120 张纸、盖 84 个章，**没有一次是对的**；
- 去银行或某个窗口，**一天就过去了**，这一天你什么都干不了。

而有意思的是，**大厂也一样卡在流程里**：去年 8 月某大厂要采购一个软件许可，开始走入库流程，**到今年上个月才终于入完库**，而入完之后那个项目可能都已经不存在了；还有人辛苦两个月把主体做进库，结果因为主体承载能力不够**得换主体、全部重来**。（台湾企业采购也是先入库。）

> 所以，**这些代理和服务公司不会消失**——「做不了这些东西」正是它们存在的理由。制度是非常慢而稳定的，技术是特别快在变化的，**服务填的就是这个速度差**。

对比之下，**Coding 为什么快**？一是学习曲线的东西，二是 **coding 这件事不依赖这些**：你做完产品就好了，产品之外的分发、付费、政府关系、安全，它都不需要。所以才这么快。（谈到工具的极致时，对谈举了 Stripe 在支付、收款、财务对接上做到自动化极致，以及更顺的银行服务体验。）所以为什么有人从内容转向做产品？——因为**以前 AI 做不到，现在能做到了**：录完视频就不用管，处理完直接发，**只占 5-10 分钟**，生产力带来了非常强的变化。

## 第六章 · Skill 的困局：卖 Skill 给个人用户，是伪生意

这是全片观点最锋利的一段。

### ① C 端没法向 C 端收费（悖论）

- 用户本身用 Skill 就是「小老头啃」——小白式的尝鲜；**你还要收费，他就试都不试**；
- 所以你必须让他用**非常低的成本 + 非常多的渠道**去用到这个东西，产品才能更快扩散；
- 同时 **Skill 的架构决定了它无法付费**——它下来就是开源的、不保密的；「开源才开源」，不开源的才谈得上收费。

嘉宾判断：**Skill 后面的形态一定还会有一个新的东西出现**——以前是提示词，后来是 Skill，再往后是另一种形态，现在还不知道。

### ② Skill 本身是一套「没有界面的软件」，学会用非常难

- 有人现场吐槽：昨天用了一个很强的 Skill，输入一篇文章让它处理，**它给出来的下一步比上一步更难**，最后只能放弃；
- **一个 Skill 本身就是一套软件，而且没有界面**；
- 而且**每个人也不需要那么多 Skill**——重点还是「你要想清楚自己需要什么」；
- 真实需求是非常复杂的：PPT 场景看似简单（「我就是要 PPT」），但**真正要落到自己工作里就必须定制**。

> **别人的 Skill 再厉害，也进不了你的工作流。** 你要进入自己的工作流，就不可能用「别人的 Skill」——必须做**个人化**。

### ③ 那 Skill 的正确姿势是什么？

对谈给出了一个「平台视角」的答案：

1. **把优质 Skill / Plugin 筛出来、内化进产品**，让用户快速感知到 Agent 的能力和价值；
2. 用户用这些优质 Skill 做出结果时，**会把能力和结果归因到你的产品上**（「是你这个产品厉害」），而不去想「是那个 Skill 厉害」；
3. 所以做 Agent 的一方**应该主动去笼络优质创作者**，在这方面下功夫。

变现方式上，目前比较主流的是：**一次性买断 + 授权 + 赞助**并存（因为本身开源，赞助开源与授权可以同时进行）。

## 第七章 · Agent + X 还是 X + Agent：以谁为中心

这是对谈中一条清晰的**路线之争**（原话叫「Agent+IM 大于 IM+Agent」，意思是以谁为中心）。

有两种形态：

| | X + Agent（旧结构上叠 AI） | Agent + X（Agent 做入口） |
| --- | --- | --- |
| 谁在中心 | 原来的软件（Office、微信）是基本盘，Agent 住进去 | Agent 是跟用户接触的界面与入口，所有 X 都往里装 |
| 体验 | 在软件里开个对话框，右图右表随聊生成 | 一句话说清楚要什么 → 直接出结果，**不用打开任何软件** |
| 例子 | 微信里的小微：Agent 进到微信里，读上下文、给建议 | 飞书现在的方向：以它为核，所有东西往里装，X 稀释为零 |
| 主要阻力 | 成本（旧产品靠广告等免费服务养，现在每个 Token 都是成本）、旧组织结构/基建跟不上、能力水平跟不上 | 原来用户的负担、习惯迁移 |

嘉宾的直观判断：**「以前 x+agent 感觉是原有结构上长了一个 AI 能力，这个升维和原来的体质有点别扭，不够原生。」** 而 agent+x 的个人体感更丝滑——「你习惯了这个入口之后，你不会再想到我要打开一个软件再去排版、再要求换图。」

### 手机思想实验：一块屏 + 一个目录

一段往回推的思想实验：三年五年后模型很先进、Agent 的 Harness 做得又很好，**我为什么还要解锁手机、点开一个个 APP？** 为什么不能就是一块屏，直接跟它说话，事就干完了？

结论落在一个反直觉的点上：

> **人的记忆力不足以支撑这件事。** 定了票明天会忘，上千个笔记要靠看见才能想起来——**人类永远需要那个目录和界面。**

所以最终的形态不是「只有 Chat」，而是：

- **Chat 解决一切问题，但你需要看着仓库才能想起来要干嘛**；
- 所以每个 AI 产品都会做一块**大的 Dashboard**，把所有对话里的待办、遗留、没完成的工作全部呈现出来；
- 它其实回到了以前的 UI，但**是一个动态的 UI**。

## 第八章 · 下一张网：一半节点不是人

对谈最后一段视野拉得很开：**如果每个人都有自己的 Agent，那么除了人与人之外，还会多出人—A、A—A 的连接。**

- 你跟你的 A 说一句「提醒橘子，明天下午我们要聊个事」，**你的 A 去找他的 A 对时间、发邀约**，最后橘子在自己的入口里看到自己 A 转达的事情——**这段对话已经脱离了原来人与人的交流网**；
- 那么这张 A 与 A 的网，是在原有的网**之外**，还是**之内**？这是值得思考的问题。

### 为什么现在做不出来

1. **心智门槛**：跟一个人聊天时「想到要引入另一个人」这件事，你得**拉个群**——这是个心智，很难学（群聊在中国之外都不流行）。在跟自己的 Agent 聊天时 **@ 一下别人的 Agent**，这个行为很难学；
2. **用户学不会**：试过让两个 Claude 互相聊天，用户学不会，没有人用——**太抽象了**，两个东西在聊天，看不见；
3. **上下文不通**：没有上下文的两个 Agent 没有「距离」概念，有上下文的又很难拿到；很多人**根本不知道自己的上下文在哪**；
4. **接受度的不对称**：**人们对自己 AI 生成文字的接受度比较高，对别人 AI 生成的接受度很低**——大家都觉得别人的 AI 写的是 AI Slop，自己的 AI 写得还行。所以中间会**经历一次「翻译」**：别人的 Agent 转述之后再给你。

### 人对语言极度敏感（这段挺重要）

- 为什么大家都觉得某个模型（4.6 那一代）好，之后越来越差？**因为它说人话**，后来的模型不说人话了；
- **语言的排列背后都有一个心理模型**：一句话里多一个字、少一个词，传达的东西完全不一样；
- 所以当某家给模型输出加水印、并声称「不会更改输出质量和文案」时，有员工写示例演示水印怎么工作，结果**上水印前后的文案完全不同**——「每个字都不对，意思完全变了」。在严肃场景（如法律合同）里换个词就全变了。

### 期待的画面

期待的不是「更高效的软件生成器」，而是**钢铁侠的贾维斯**：一直在你旁边，知道你的健康数据、每天的聊天上下文，理解你跟别人的关系、你的认知模型和世界观，你想讨论时能陪你碰撞；人与人之间的连接是**辅助身份**，帮你完成更高效的连接和更深刻的看见。

**但现在还没到**——现在的 Agent「**更像是一个更好的锤子**」。以前拉一张网线过来，我们成了互联网公司；现在拉了一个 AI 进来，我们要成为 AI 公司，**但还是把它视为工具**。

对谈给出的本质区别：**这一次真的出现智能了**（当然没有意识）——拉网线是没有智能可言的，它只是让信息传递更高效。

## 第九章 · 最割裂的地方：两个世界彼此看不见

对谈里有一段非常现实的观察：**做效率的人和做消费的人，活在两个互不相见的世界里。**

- 一边（从业者圈）天天讨论 Agent、Coding、生产力与工作效率；
- 另一边是大量「不需要用 AI 工作」的普通人：他们的工作要么很简单，要么本来活都干不完——**有没有 AI 都一样**。他们想象中 AI 带来的最大影响是：**AI 换脸、AI 视频**，以及内容消费。

数据体感：**AI 短剧的渗透已经超过 8 亿**。以前很多人不看短剧（嫌劣质、无脑），现在越来越多**对内容有要求**的人也在看，而且质量在提升：

- 剧情架构仍然是**人来搭**的（世界观还是人来的），但**生产效率巨高**；
- 短剧变长剧化：每一集都有爽感，可以日更，同时又有长篇剧情和复杂架构；
- 嘉宾亲测：刷到一个短剧，明知剧情像小学生写的，**但那钩子一级钩一级**，「我清晰地知道有人在引导我，我也顺着他的引导走」——很微妙。

延伸到游戏：很多人开始用 AI 做游戏，Steam 上增长很快。

### 三维轴：原子世界 / 比特世界 / Token 世界

一个很好用的思考框架：

| 世界 | 内容 | 现在发生的事 |
| --- | --- | --- |
| 原子世界 | 现实物理世界 | 与 Token 世界结合：会飞的救生衣（无人机把救生圈送到头顶）、大疆在洪灾里投救援物资，效率比过去高一万倍 |
| 比特世界 | 我们熟悉的互联网基建 | 与 Token 世界结合：帮你写小说、做短剧、提效——**但互联网 2.0 的基建是高度封闭的**，核心驱动力是「你最好别在我这儿发产品，别抢我的用户」，所以生态在防御 |
| Token 世界 | 模型能力 + Harness + Agent | 同时在向另外两个世界渗透 |

第三类结合点最让人兴奋的是**科学**：AI 带来的药物革命——现在的问题是**临床试验排队、药物研发变快**，形成错配；而 2021-2022 年基因编辑与蛋白质结构发现之后大量人投入，**今年的临床实验陆续做完，未来三五年会出现一个爆发点**：相当多疾病被治愈或延缓。（国内实验动物都涨价的侧面印证。）

### 内容生产与「被看见」的机会

- 门槛继续下降：**你给他一个种子，他给你生长出一棵树**；
- 发布侧基建很好（短剧平台海量涌现），里面必然有大量 60 分，也会冒出 80、90 分；
- 好故事跟时长无关：两小时的电影是好故事，两分钟的短剧如果讲的是好故事，**也是好故事**；
- 所以：**很多擅长讲故事的人只是没被看见，现在有机会被看见了。**

## 第十章 · 上下文才是真正的主角

这是全片信息密度最高、也最「可以马上照做」的一段。

### ① 上下文获取，是最核心却最被忽视的一环

- 国内的问题：**数据不开放**，上下文拿不到；
- 一个很神奇的现象：**官方自家的连接（连自家服务）反而做得不好**——读你的邮件、读你的网盘，做得**还不如第三方好**；而它的 MCP 接到「非自己的服务」时反而做得很好；
- 海外是另一种状态：大多数人已经完成了「Agent 的线上化」——界面在 Notion、Obsidian、GitHub、推特，而且**这些全都有 MCP**；在国内点开连接列表，往往**只有寥寥几个能连**。

### ② 医疗案例：上下文 + 推理 = 医生做不到的事

三个真实故事串起来就是同一个结论：

- **慢性病十年**：病人找了至少 10 个医生，**没有一个听完他的话**——每次听一点就说「我知道差不多是什么」，开个药就让走。他把 13 年得病的感受都告诉自己的 AI，AI 推理出可能的病症和用药，他拿结果去找医生确认，**医生说「还真是」，之前没有任何医生给过这个选项**。用药后病治好了。
- **缺铁性贫血**：一位嘉宾长期睡不醒、非常累、以前一周跑三次步现在一跑就想吐。自己一直以为是甲状腺（家人有甲减），每天跟 AI 聊，有一天让 AI「结合我的上下文判断我可能是什么病」，AI 判断**可能是缺铁性贫血**，建议去查；真去查了，指标符合，吃铁片后好了。
- **胰岛素抵抗**：另一位的女朋友老问题久治不愈，医生一直按激素方向调；后来从一位做药的人那里得到提示——**可能是胰岛素抵抗**。做糖耐量实验（而非常规体检的空腹血糖）才发现，胰岛素在 2 小时、1 小时段比正常人高了五六倍到七八倍。**如果不去查这件事，她可能永远在「治标」的状态里，一直吃药、一直好不了。**

提炼成两条能力：

| 能力 | 医生的限制 | AI 的优势 |
| --- | --- | --- |
| 上下文阅读 | 只有 10-20 分钟，会忽略你说的很多话 | 你跟他聊一小时他听一小时，**阅读窗口足够大、而且是长期的** |
| 专业推理 | 受经验和时间限制 | 今天的模型推理能力已经足够强 |

**再叠加「上下文获取」，结果就是「潜力无限」。**

### ③ 上下文是一辆要维护的车，不是一个增值的房子

这是全片最值得抄走的一句比喻。配套的是一组**反直觉的经验**：

- **上下文太多，会把你拉回以前的平均值**：当你有了很多上下文之后，即使你在 Prompt 里明确说要怎么做，**它还是会把新思考拉回旧路径**——这就是一种信息茧房；
- **不是「不停往里丢」**：丢太多，聊到新话题时它会把过去无关的那一段直接摘过来，**影响这一次推理的思维结构**；
- **正确的做法（三个人各自的方法）**：
  1. **顶层设计**：决定「什么时候你不要读」「什么时候我需要你读了你再读」；
  2. **进去时先做一次加工/清洗**：说清这次的背景、话题、双方的对话记录，让它提炼，并给一个**边界和约束**；下一次背景变了、话题变了，就不能直接引用旧的那段；
  3. **抽项目**：每个完整项目单独做上下文区域管理，做完就过去；项目是客观信息，认知是主观沉淀，**一层一层抽**；
  4. **精选**：书、笔记、读过的文章会停留下来，**不重要的东西反而是负担**——长文和深度内容才值得留。
- **为什么坚持迭代自己的 Agent**：因为上下文都在里面；上下文在一个 Agent 里沉淀久了，再换一个新 Agent 会很不适应——你只是在看功能，而不是带着上下文去理解。反之，上下文在自己手里，就可以「用任何 Agent」，觉得哪个好就把它加进来。

### ④ 信息茧房的两次觉察

对谈最后收在一个很有分量的提醒上——**每个人都跟自己的 Agent 形成了一个闭环，每个人都玩得很开心**。这里面有两层觉察：

1. **第一层**：应该形成**自己的**闭环，**不应该去抄别人的**（他这么做所以我这么做）；
2. **第二层**：**要意识到自己在一个环中，别被困住。**

嘉宾举的例子很扎心：有人的 Agent 开发了一套「可以解决幻觉问题」的新框架，**他和他的 Agent 互相夸对方**，已经活在闭环里、活在被高估的环境里；当他把这个结论拿来跟真人沟通时，对方只能选择戳破他——而他会很痛苦。**这不是个例。**

怎么破？两条被验证过的方法：

- **把自己的结论发到网上，看有没有人能反驳**——被反驳的地方可能就是茧房；
- **主动去读「Aha 之外」的信源**——不要只喂自己喜欢的东西。

## 第十一章 · 价格、模型与那把「锤子」

### 价格：两条曲线

- 半年前有人赌「最前沿的模型一定越来越贵」（显卡跟不上 Agent 的消耗速度），结果大模型一轮降价把人打脸；最近又有一轮涨价（有人形容为「涨了 12 倍」），大家又觉得用不起了；
- 现在的判断是：**价格已经到一个拐点**——再往下降没有太大区别，中转站甚至已经降到没有利润空间；
- 所以会**分化成两条线**：

| 曲线 | 特征 |
| --- | --- |
| SOTA 模型 | 永远推出最新最强的那个，**价格持平甚至略微上行** |
| 主流模型 | **价格像指数下降**，已经能满足 90% 的需求 |

- 关键判断：**很多人是在为基准测试上 5 分、10 分的差距，付出 50 倍到 100 倍的价格差**——只看基准你会觉得非常亏，**但真的有用处的时候，你会发现非常值**（有人对照过：同样写文章，贵的那个和便宜的那个「天上之别」）。

### Harness 与底座：汽车底盘还是引擎？

- 有一种说法：**Harness 像底盘，底座模型像引擎**。以前觉得 Harness 可以随便插到任何大模型上，现在发现**每个表现最好的组合都是「这个 Harness 配这个底座」，因为它们是联合训练的**；
- 但实际使用下来，**切换基本没有痛感**——早期某个模型只在自家的 Agent 里训过，出了自家环境调用能力很差，但**后训练之后基本在各家 Agent 里都跑得很好，数据一定会回流**，只是有时间差。**大部分用户不必追那一个月的时间差**。

### 模型厂的红皇后效应

一个很锋利的推演：**如果 Harness 与模型解耦（好的 Harness 可以任意切换模型 API），就会出现模型厂的红皇后效应——你只有拼命奔跑，才能停在原地；你落后就是死**，因为用户切换是零成本：昨天你还是 3000 万用户，今天可能就跌到 0。

那模型厂会怎么做？**把 Harness 和模型一起混合训练**，让「我的模型 + 我的 Harness」最好用，你要切效果就变差——理论上它应该往这个方向使劲，才能把用户拴住。但目前的实际体感是切换没什么痛感，**真正被拴住的是 Agent**。

### 一个被低估的黑科技：缓存

- 缓存命中率 **90% 和 95% 是两个重要节点**，成本差可能到两倍——因为「未命中缓存」的价格是「命中缓存」的 10 倍到 100 倍，**缓存率提升 5 个基点，价格一下就下来了**；
- 有产品的缓存率能做到 **96%~100%**（在自家 Harness 里），「充 50 块钱用了半年还没用完」；
- 但反过来：**过度追求缓存率，可能会降低模型输出质量**——有人判断某个产品「现在如此拉胯」的原因，正是为了压成本，把模型和缓存压得过于极端。

## 第十二章 · 收尾：产品就是自己带一套 FDE

对谈最后回到开头那句话，并把它推到了终点：

- **Harness 需要做的事情**：用户进来之后，帮他**找到一个目标**、给一条**路径方法**——就像多邻国：你说我要学英语但不知道怎么学，它说「你来这儿玩游戏就行」；「不管你怎么说，你先走起来」。如果它是一个有智能的 Agent，用户就真的能在这儿学会；
- 因为**只给用户模型没有用**，工具得回答「干嘛用」——**那就是 FDE**；
- 所以——**所谓什么叫产品？产品就是自己带一套 FDE。**

最后一段关于「多样性」的收束：以前大家的产品都差不多（都是同一个模型套不同的壳，做的事情差不多），**以后会越来越不一样**——因为每个产品想做的事、它的 onboarding、它的 FDE，是和**创造者的审美**绑在一起的：他认为用户进来应该往哪个方向走。

> 你证明了这个实践很好，去告诉 100 个人，**能听进去的估计有 10 个**——人就是很多样的。

## 二、通用原则（8 条）

1. **落差优先原则**：任何 AI 交付，先问「用户/客户不会用什么」，而不是「产品还有什么功能」。落差就是你的工作量清单。
2. **5% 杠杆原则**：在一个组织里，先找到那 5% 的超级用户，把他们的方法**产品化成自动化**给其他人用——比培训全员高效得多。
3. **抽离即成功原则**：衡量一次交付是否成功，看你不在了客户还能不能跑。把「抽离率」写进自己的验收标准。
4. **最短链条优先**：选客户/场景时优先「链条短、反馈快、见效快、付费意愿高」的；传统行业常常优于内容行业。
5. **一眼能懂原则**：演示和交流要用「一眼能 get」的场景（如「每天自动帮你抢外卖券」），而不是讲抽象能力；**一个场景被复制，就等于一句咒语被传播**。
6. **上下文治理原则**：上下文不是越多越好；要分项目/认知/日常分层，要清洗、要给边界、要精选；**它是车，不是房**。
7. **破茧原则**：把自己的结论公开接受反驳；主动读「Aha 之外」的信源。
8. **够用线原则**：主流模型已满足 90% 需求；只在「真的有用处」时才为那 5-10 分付 50-100 倍的钱。

## 三、可复用的设计模式

- **漏斗式启动**（安装 → 使用 → 生产力）：先让人低成本用起来，再谈结果交付；不要跳过第一步去谈价值。
- **咒语封装**：把最佳实践封装成一句话可复制的场景（「帮我每天抢外卖券」），让全员能说、能拿到结果。企业里要做的就是把「最佳实践」抽提出来。
- **内置 onboarding + 向导**：产品自己带路径（多邻国式）——给目标、给方法、先走起来。
- **动态 Dashboard**：Chat 之上必须有目录/界面，把待办、遗留、未完成的工作可视化；否则用户想不起来要做什么。
- **落差填平三选一**：5% 外溢 / 培训 / FDE 进场——按客户的成熟度和时间成本选，三者也可组合成「培训 + 驻场」。
- **红皇后防御**：如果你的产品依赖别人的模型，把你的优势放在 Harness 与上下文的积累上（用户切换零成本，唯一被拴住的是 Agent）。

## 四、五个反模式（避坑）

1. **把「有需求我就来开发」当 FDE**——开发完就走，落差原封不动。
2. **把 Skill/工具本身当商品卖**——C 端不付费、开源不保密、还要用户学会用。
3. **指望全员学会 AI**——投入巨大、上限很低。
4. **把上下文当房子，不停往里堆**——你会得到「被拉回平均值」的 AI 和一个信息茧房。
5. **只看基准分数选模型**——为 5 分差距付 100 倍价格，除非你真的用得上。

# 借鉴篇 · 我们能借鉴的点

> 落到我们自己的业务上：企业 AI 落地顾问（FDE 式交付）+ 智能体定制交付 + 中俄跨境获客系统 + 内容 IP。逐条给动作。

1. **销售开场第一句话改成「服务裹着能力」**：以后客户问「你这个智能体/系统多少钱、有什么功能」，先用一句话把落差讲清楚——「Agent 装到您公司不会自动出结果，中间有一段落差必须有人填，我们卖的就是填落差这一段」。这句话比任何功能列表都更能定价。
2. **把交付验收指标从「装好了」改成「抽离了」**：参照零一万物的 FDE 指标，在交付方案里加一栏「抽离验收」——列出「我们撤走后，客户必须能独立完成的事」清单（谁在什么场景用什么入口做什么），逐条实测通过才算交付完成。这一条直接把我们和「装完就跑」的外包区分开。
3. **培训 + 驻场做成标准两段式产品**：第一段现场培训（带着客户自己的场景实操，别讲概念），第二段驻场/远程辅导跑真实业务；把「培训后愿意继续驻场的比例」当作我们的转化率指标持续记录（对标 75%）。这一段可以直接写进报价方案（培训包 + 驻场包）。
4. **客户筛选标准加一条「越土越好」**：把「链条短、反馈快、见效快、付费意愿高」做成书面筛选标准。对我们的适配场景：货代/物流、1688 卖家、传统制造、批发档口——**别优先挑内容公司**（他们自己用得比我们熟，链条太短、不需要外力）。
5. **客户内部先找 5% 的人，再铺开**：进场第一周的目标不是「全员培训」，而是找出客户里那 2-3 个愿意钻的人（财务/仓管/销售里常见），把他们跑通的流程做成「一句话自动化」，让剩下的人用它。汇报给客户老板时，这就是「5% 杠杆」的可视化成果。
6. **演示用「抢外卖券式」的场景**：给客户演示别讲 Agent 能力，讲他们一眼能懂的日常痛点（自动抄单据、自动催款、自动整理询价表、每天定时把报表发到群里），并把它封装成一句话（可复制的「咒语」）。我们现成的素材：阿尔泰物流的线索/跟单、Ozon 选品、9610/报关数据整理，都能封装成这种敲门场景。
7. **把「制度慢、技术快」写成企业落地阻力清单**：入库流程、采购签合同、资质、开票、盖章、主体承载能力——这些都是方案里的**时间表风险项**，报价与排期要显式留出这段（参考对大厂案例：入库走一年，项目都没了）。对客户讲清楚这一点，反而显得我们专业。
8. **上下文治理 SOP 立刻用在自己身上**：把我们的记忆/技能库按「项目区 / 认知区 / 日常区」分层，每个项目单独开上下文区，做完就封存；定期清洗、设边界（什么时候不要读）；新会话只喂该读的。同时把同一套 SOP 打包成给客户的「上下文治理手册」——这是他家 AI 用不动的真正原因。
9. **破茧动作制度化**：把我们的方法论结论（如「5% 策略」「服务裹着能力」「土行业优先」）发到公开平台接受反驳，并**主动读 Aha 之外的信源**（对家方法论、客户行业媒体）。这条同时对内容 IP 有帮助。
10. **内容线学「录完不管」的流水线**：对谈里那条「录完就丢给 AI 处理、只花 5-10 分钟」的流水线，正是我们做「7 天交付级智能体」短视频的模板——**录 → 自动转写/加工/成稿 → 发布**，把人从剪辑里抽出来。
11. **成本纪律：吃透缓存与够用线**：选型时优先看缓存命中率（90%/95% 是成本节点，缓存价是未命中的 1/10~1/100）；执行类任务用主流模型（已是 90% 需求的够用线），只在「真的有用处」时才上 SOTA。这条直接落到我们现有的模型分工（执行牛马用包月/主流，关键判断用好模型）。
12. **产品形态：别只给客户 Chat**：给客户交付的智能体/面板必须有目录与看板（待办、遗留、未完成工作可视化）——Chat 解决一切，但人要靠「看见」才想起来。我们已有的运营看板/成长面板就是这个思路，交付时把它讲成方法论而不是功能。
13. **把这一页的六条观点做成一张客户可带走的「判断卡」**：① 卖服务不卖功能 ② 只搞定 5% ③ 越土越吃香 ④ Skill 不能直接卖 ⑤ 别人的 Skill 进不了你的工作流 ⑥ 下一张网一半节点不是人——这六条既是我们对客户的判断输出，也是我们自己选题、定价、交付时的检查表。
