# 项目档案 · 用法与规则

> 用途：把每一个真实客户项目变成「可复用资产」。新项目来时先找最像的档案，再决定怎么做。
> 规则版本：2026-09-09

## 为什么用档案

以前的经验散在复盘文档、决策卡、交接记录、聊天里。项目档案把它们收拢到一处，并且明确回答三件事：

1. 这个项目现在/最后在哪个阶段、哪一关；
2. 这关真正交付了什么、什么只是做过但没验证；
3. 哪些零件和坑是「已验证、下次可抄」，哪些只是「待验证」。

## 一份档案必须有的内容

| 区块 | 作用 | 缺了会怎样 |
|---|---|---|
| 状态/当前阶段 | 一眼知道这单停在哪 | 下次误以为项目在跑 |
| 关卡进度表 | 按 09 七阶段逐关给状态+证据 | 无法判断哪关要补 |
| 已验证零件/打法 | 哪些被真实项目验证过 | 变成“收藏而不是经验” |
| 已验证的坑 | 每条含背景/后果/下次怎么做/来源 | 坑还会重踩 |
| 可复用判断 | 下次同类项目第一步怎么想 | 有经验但没有判断力 |
| 关联证据 | 复盘、决策卡、交接文档路径 | 无法复核 |

## 诚实规则（对每个档案都生效）

- 状态只写三种：`已停（经验全保留）` / `进行中` / `已交付`；不确定就写 `待确认`。
- 关卡表里 `✅` 必须能写出证据路径或具体日期；写不出就用 `⚠️ 事后补` 或 `❌ 当年没做`。
- 老项目的关卡表是**事后复盘对照**，不是当时的实时门禁，档案开头要写明。
- 每条坑必须可追溯到项目复盘/交接文档/决策卡，不能只写“记得踩过”。
- `_` 开头的说明文件不会被网页当成项目卡展示。

## 新项目怎么用

1. 新建项目档案时先复制最像的历史档案结构；
2. 让 Hermes 按 23/24/25 + 最像档案做开工体检，结论落回该档案；
3. 每过一关，把产出物和证据补进关卡表；
4. 项目结束后填复盘，并把新坑回填成独立条目。
