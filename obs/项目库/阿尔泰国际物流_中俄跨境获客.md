> 项目类型：B 端获客自动化 · 多平台触达

## 一句话

给中俄物流商做多平台获客系统（VK/WhatsApp/Telegram/IG/TikTok/速卖通），验证了「批量触达必须先风控分层」；项目已停，但它是目前“反封号/合规触达”最完整的自有案例。

## 项目画像

- 客户：阿尔泰国际物流（跨境物流/货代）
- 核心业务：自动找俄罗斯 B2B 询盘、AI 筛选、合规触达、转人工
- 交付形态：客户机脚本 + Chrome CDP 9222 + 每日看板 8898
- 参考档位：工作站 ¥15-50k（决策卡 ALT-001）
- 结果：系统曾交付并稳定运营；最终已停，经验全部保留

## 已验证零件/打法（下次可直接抄）

- 分层防误伤：采集 → AI 筛选 → 待联系队列 → 规则触达，四层解耦
- 风控分级：按账号价值设每日上限 + 随机间隔 + 1+1+1 跟进
- 被动统一响应器：只承接未读消息，不主动群发；回复带 `[[TRANSFER]]`
- fail-closed：无登录态/token 时安全跳过，不瞎跑
- 规则审计：每条私信带 rule_chain，可回溯

## 已验证的坑

### 坑 1 · 个人号直接群发模板

- 背景：早期没有精聊/规则分层，直接模板群发
- 后果：3 个号 2 天被封（Korobochki 教训）
- 下次怎么做：先用规则引擎分层 + 小号测试；不拿主号冒险
- 来源：三项目经验沉淀 / ALT-001 / AR-002

### 坑 2 · Token 静默过期

- 背景：VK token 约 24h 失效，凌晨 cron 无人察觉
- 后果：连续 10+ 次失败没报警
- 下次怎么做：token 自动刷新 + 失败次数阈值报警（watchdog）
- 来源：阿尔泰基础设施状态 / AR-002 ADR-ALT-001

### 坑 3 · 多平台同一时段采集

- 背景：6 平台 cron 撞同一时段
- 后果：被平台检测“一个 IP 一秒登 6 平台”
- 下次怎么做：按平台错峰（VK 每小时 / TG 每 6h / IG 每 12h）
- 来源：三项目经验沉淀

### 坑 4 · VK 个人号私信陌生人

- 背景：个人号高价值，直接私信陌生人有合规红线
- 后果：高风险；后来社区号/合规红线才解决
- 下次怎么做：接平台前先查平台自动化红线；个人号只承接不主动
- 来源：ALT-001 反模式表

## 可复用判断（下次同类项目）

1. 先问客户“你打算在平台投入多久、账号资产值多少钱”，再定风控起点；
2. “全自动群发”是危险词，第一步必须翻译成合规触达方案；
3. 批量触达的本质是“发错比不发更糟”，幂等/重试/限流/审计缺一不可。
