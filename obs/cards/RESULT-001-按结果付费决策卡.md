# RESULT-001 · 按结果付费决策卡（Outcome-based Pricing）

> ID: RESULT-001 | 创建: 2026-09-02 v3.0 | 状态: ⭐ 正式  
> 作者: Hermes (M3 队长)

## 这个决策卡在解决什么问题（一句话）

**你是客户，怕付了钱没效果——你想「按效果付费」（每带来 1 个客户付多少 / 每出 1 单付多少）——这张卡告诉你「按结果付费能不能做、有什么坑、怎么避坑、报价多少」。**

## 适用客户

### 画像
- 心态: **「先看效果」型客户**（怕被骗）
- 已有基础: 你的 AI 项目已经在 POC 验证过效果（不是完全没验证）
- 预算: ¥15,000+ 起（按结果分批结算）
- 关键约束: **「不出单不付钱」**（客户掌握主动权）

## 推荐架构：分层结算 + 风险共担

### 模式：基础费 + 结果分成的混合模式

**核心思路：纯结果付费 = 风险全在服务商（不行），纯平台费 = 客户风险全在客户（也不行）。混合 = 双方共担。**

### 3 种结果付费模型（选 1 个）

#### 模型 A：基础费 + 阶梯分成（推荐）
```
基础费：¥15,000（POC 期 4 周）
分成：第 1-10 单：50 元/单
      第 11-50 单：30 元/单
      第 51+ 单：20 元/单
封顶：总费用 ¥80,000（避免超出客户预算）
```

#### 模型 B：纯分成 + 上限封顶
```
基础费：¥5,000（仅覆盖启动成本）
分成：前 30 单：100 元/单
      30 单后：50 元/单
封顶：¥80,000（触顶停止收费）
底线：30 单没成 = 全额退款 ¥5,000
```

#### 模型 C：先免费 + 季度结算
```
前 90 天：完全免费（只付基础云成本约 ¥500/月）
90 天后：按效果分成
  - 触达 1000+ 客户：付 ¥15,000
  - 触达 3000+ 客户：付 ¥30,000
  - 转化 50+ 客户：付 ¥50,000（叠加）
```

### 关键指标定义（**写进合同，不模糊**）

**对「按结果付费」最关键的是：什么是「结果」？**

#### 阿尔泰场景
- **结果 1**: 触达潜在客户数（VK 群发消息数）
- **结果 2**: 客户回复数（客户主动回复的消息数）
- **结果 3**: 加好友成功数（客户同意加好友）
- **结果 4**: 转化数（最终成为付费客户的数量）

**建议付费指标**：结果 3（加好友成功）—— 这是可量化、可验证、不扯皮的中段指标

#### NIFTY 场景
- **结果 1**: 商品图处理成功数（白底/抠图/换背景）
- **结果 2**: 客户日活数（每天打开 app 的次数）
- **结果 3**: 续约客户数

**建议付费指标**：结果 2（日活）—— 直接反映产品价值

#### 中俄轻舟场景
- **结果 1**: Listing 上架数
- **结果 2**: 真实出单数
- **结果 3**: 转化率

**建议付费指标**：结果 2（真实出单）—— 最直接

### 结算机制（透明 + 防扯皮）

#### 数据透明
- 客户每天看到「今天出单 X 单」「累计出单 Y 单」
- 截图 + 数据库导出（客户可查）
- 每月一次账单（详细到每单 ID）

#### 防扯皮设计
- 双方共同认证的工具：GA4 / Mixpanel / 后台数据库
- 不依赖单方数据（避免「我说 50 单你说 30 单」）

#### 退款条件（写进合同）
- 30 天内 0 单 = 全额退款（基础费）
- 90 天内 0 单 = 全额退款（基础费 + 已付分成）
- 服务商主动停止服务 = 全额退款

## 必选组件

### 数据透明度
- **每日报告推送**（09:00 微信/邮件）
- **客户后台看板**（实时数字，可查可截图）
- **第三方数据对接**（GA4 / Mixpanel 双方可信）

### 结算工具
- **账单系统**（每月自动生成账单 PDF）
- **支付接口**（支付宝/微信/对公转账）
- **发票管理**（合规）

### 风险控制
- **封顶机制**（避免失控）
- **退款保险**（客户安全感）
- **数据快照**（月底快照，留证）

## 报价模板（按结果付费 ¥15-80k）

| 模型 | 基础费 | 分成 | 封顶 | 适用 |
|---|---|---|---|---|
| **A 基础+阶梯** | ¥15k | 20-50 元/单 | ¥80k | 风险中性客户 |
| **B 纯分成** | ¥5k | 50-100 元/单 | ¥80k | 「先看效果」强 |
| **C 季度结算** | ¥0-3k | 90 天后按 KPI | ¥50k+ | 长期培养客户 |

## 我们的实战（理论推断 + 实战）

### 阿尔泰（按结果付费的天然场景）
- **现状**: 已用工作站档 ¥30k（按平台费）
- **升级路径**: 客户量大后转 RESULT-001（按真实触达付费）
- **优势**: 阿尔泰 VK 触达数据透明，可量化

### NIFTY（按结果付费不太合适）
- **原因**: 商品图处理是工具类，客户用就付费 ≠「按出图数」
- **建议**: NIFTY 保持订阅制（月费 ¥199），不是 RESULT-001

### 中俄轻舟（按结果付费最佳场景）
- **原因**: 跨境电商核心 KPI = 真实出单数
- **建议**: 中俄轻舟可推广「保底 + 真实出单分成」

## 不推荐（反模式）

❌ **纯结果付费**（服务商亏本风险大）
❌ **模糊指标**（双方对「结果」定义不一致 = 扯皮）
❌ **没封顶**（客户量大时超出预算）
❌ **依赖单方数据**（客户不信你的数字）
❌ **没退款条款**（客户没安全感）
❌ **结算周期太长**（客户等半年看不到钱）
❌ **拆分太复杂**（客户看不懂账单）

## 风险评估

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| **客户扯皮数据** | 高 | 高 | 第三方数据 + 数据快照 + 双方签字 |
| **服务亏本** | 中 | 高 | 封顶机制 + 阶梯分成 |
| **效果差** | 中 | 高 | POC 阶段必须先验证效果 |
| **客户预期过高** | 高 | 中 | 合同明确「结果」定义 + 案例参考 |
| **现金流问题** | 中 | 中 | 基础费覆盖启动成本 |

## 下一步（客户接受报价后）

1. **签按结果付费合同**（明确 KPI + 封顶 + 退款）
2. **双方签字「结果定义」文档**
3. **客户后台账号开通**（实时看数据）
4. **启动 POC**（按平台/账号设置）
5. **每日报告推送**（09:00 微信）
6. **每月账单 + 结算**（双方确认）
7. **封顶触发 = 自动停**（避免超出预算）
8. **季度复盘**（续约 / 降档 / 结束）
