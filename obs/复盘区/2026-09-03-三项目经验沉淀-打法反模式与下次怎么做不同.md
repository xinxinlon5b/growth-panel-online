## 一句话总纲（3 个项目教会我的）

**企业 AI 项目"MVP 容易跑通但极不稳定"，根因从来不是模型不够强，而是：①前期没做需求诊断就开干 ②中期跳过了幂等/密钥/脱敏/审计这些"不性感但保命"的关卡 ③上线后没有可观测和回滚。** 三个项目分别踩了这三类坑。

## 项目一：阿尔泰（中俄跨境电商获客）—— 教训最多，含金量最高

### 做成的事（可复用的打法）

| 打法 | 具体做法 | 下次哪类项目能用 |
|------|---------|----------------|
| **分层防误伤** | 采集 → AI筛选 → 待联系队列 → 规则触达 四层解耦，筛选挂不误发、触达挂不丢线索 | 任何"批量触达用户"的系统（获客/通知/营销） |
| **风控分级** | 按平台账号价值分级设每日上限 + 随机间隔 + 1+1+1 跟进节奏 | 任何操作"高价值账号"的自动化（怕封号/封资产） |
| **统一响应器(被动)** | 只检测未读消息被动接，不主动群发；回复带 `[[TRANSFER]]` 转人工 | 任何"AI 自动应答"需求（24h 值守但不出事） |
| **fail-closed** | 无登录态/无 token 时安全跳过而不是瞎跑 | 所有 cron 自动化（宁可漏跑不可跑错） |

### 踩过的坑（反模式）

| 坑 | 后果 | 下次怎么做不同 |
|----|------|---------------|
| **个人号直接群发模板** | 3 个号 2 天被封（Korobochki 教训） | 先用规则引擎(精聊)分层 + 小号测试，不拿主号冒险 |
| **Token 静默过期** | cron 连续 10+ 次失败没人察觉 | 加自动刷新 + 失败次数阈值报警（watchdog），不能静默 |
| **多平台同一时段采集** | 被平台检测"同一 IP 一秒登 6 平台" | 按平台错峰调度（VK 每小时/TG 每6h/IG 每12h） |
| **VK 个人号私信陌生人** | 高风险（后来社区号/合规红线才解决） | 接平台前先查该平台对自动化的合规红线 |

### 下次做同类项目第一步
**先问客户"你打算在这平台投入多久？账号资产值多少钱？"** —— 决定风控策略的起点。

## 项目二：NIFTY STUDIO 纳福（本地化 AI 商品图）—— 工程化最重

### 做成的事（可复用打法）

| 打法 | 具体做法 | 下次哪类项目能用 |
|------|---------|----------------|
| **双通道计费** | 包月(LibTV) + 按量(火山) 双通道，客户覆盖面翻倍，单通道挂另一通道顶 | 任何"卖 AI 能力给小白"的产品（降低门槛） |
| **路径安全四层防御** | 扩展名+类型校验 / 拒隐藏文件 / resolve+is_relative_to / 二次校验 | 任何"用户上传文件→服务读文件"的系统（防穿越） |
| **任务队列 2 worker + journal** | 慢任务不阻塞全站；重启后任务状态可见("已中断"非"不存在")；取消不双扣费 | 任何"AI 生成耗时 1-3 分钟"的产品 |
| **SOP 版本化+回滚** | 提示词/配置即代码，每次改自动留档，hash 去重，调错一键回滚 | 任何"运营要频繁调提示词/配置"的系统 |
| **冷启动缓存** | CLI 冷启动 3-5s 用 60s 缓存 + 失败 15s 探测兜底 | 任何"外部工具调用慢"的场景 |

### 踩过的坑（反模式）

| 坑 | 后果 | 下次怎么做不同 |
|----|------|---------------|
| **单文件 3500 行** | 架构债重，13 轮审计 bug 集中在交叉引用、多线程锁易错 | 大功能一开始就拆模块（哪怕慢几天），别"先跑通后拆分" |
| **登录态过期(401)** | 客户突然不能出图 | 提前做登录态检测 + 引导重新登录（LibTV CLI 401 教训） |
| **无鉴权裸奔(admin888)** | 安全审计揪出 UI 泄漏密码明文 | UI 永远不写密码明文；服务默认要鉴权 |
| **计费竞态** | 取消任务可能双扣费/不扣费 | 计费状态机 + 云端调用前自检取消标志 |

### 下次做同类项目第一步
**先定"这工具卖谁？小白还是尝鲜？"** → 决定计费通道结构。**同时一开始就拆好模块**，别等 3500 行了再拆。

## 项目三：中俄轻舟（Ozon 卖家向）—— 业务探索型

### 做成的事（可复用打法）

| 打法 | 具体做法 | 下次哪类项目能用 |
|------|---------|----------------|
| **平台 API 打通优先** | Ozon Seller API 打通（Client ID + Api-Key），不走爬虫 | 任何"接平台卖家后台"的需求（官方 API 优先） |
| **本地 SQLite 轻量** | Listing/SKU/订单 4 表，本地跑，无服务器成本 | 个人/小团队工具（别一上来上云） |
| **Listing 批量生成 + 俄语优化** | DeepSeek 批量生成俄语 listing + 优化 | 任何"多语言内容批量生成" |

### 踩过的坑（反模式）

| 坑 | 后果 | 下次怎么做不同 |
|----|------|---------------|
| **1688 自动询价被 block** | 聊天必须真人，自动询价走不通 | 先查平台自动化合规，能自动才自动；不能自动给"3分钟人工操作卡" |
| **密钥生成反直觉** | Seller API key 获取要 computer_use 点半天 | 复杂后台操作先找官方 API 文档/开发者模式 |
| **导入商品 404** | /v1/product/import 才是对的，v1/v2 旧接口 404 | 接新平台 API 先读官方最新文档，别用旧教程 |

### 下次做同类项目第一步
**先查官方 API 文档确认能力边界**（能自动到什么程度），再决定自动化 vs 人工辅助。

## 复盘结论（一句大白话）

**你不是没经验，是经验没沉淀成"判断力"。** 这三张表沉淀完，下次接项目：
- 遇到"批量触达" → 先想风控分级（阿尔泰打法）
- 遇到"卖 AI 工具" → 先想计费通道 + 模块拆分（NIFTY 打法）
- 遇到"接平台" → 先查官方 API + 合规（轻舟打法）
- 任何项目 → 幂等/密钥/脱敏/审计/回滚 一个不能少（09_关卡地图）
