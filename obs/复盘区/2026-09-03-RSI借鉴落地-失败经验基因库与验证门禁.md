## 一句话结论

用户从网上看到「让 AI 加入 RSI 模式，从错误中学习、出错率变低、自我迭代」的
说法，要求去 GitHub 调研是否对我们有帮助。**结论：概念是真的（学术圈+开源界
热门方向），但网上说法营销味重——我们没有去"加入一个新系统"，而是**盘点出
自己已有的经验学习闭环，补齐了两个真实缺口，完成一次进阶。

## 调研：RSI 是什么

- GitHub 检索确认：RSI = **Recursive Self-Improvement（递归自我改进）**
- 代表项目：`Prism-Shadow/penguin-harness`（1947★，自进化引擎）、
  `lobehub/awesome-rsi`（82★，学术研究地图）
- 核心机制（与我们相关的部分）：
  - **Experience Gene / EvolveR**：把失败轨迹蒸馏成可复用原则，下次任务检索复用
  - **Reflexion / Self-Refine**：收到反馈后存自然语言反思
  - **SkillOpt**：改进 skill 只在严格验证有增益时才采纳
- 重要警告（学术共识）：不放控制的自我进化会**模型坍缩 / 目标漂移 / 假性自信**，
  所以必须配外部验证

## 缺口与补法（本次实际做的）

### 缺口 1：失败教训缺结构化 + 主动检索 → 建「失败经验基因库」
- 位置：`~/.hermes/lessons/`（8 个文件、25 条真实教训，从记忆和审计记录提炼）
- 每条四要素：场景 / 症状 / 根因 / 对策 / 来源
- 6 个领域：终端环境、部署容器、测试质检、记忆交付、平台社媒、AI 成本
- 触发器：新建 `preflight-check` skill（开工前 30 秒检索基因库，命中钉成任务红线）

### 缺口 2：改进缺验证门禁 → 建「verified-improvement」
- 新建 `verified-improvement` skill：改进 skill/规则/代码前先写验证计划，
  验证通过才采纳，失败回滚（对应 SkillOpt 机制，防"看起来进化"）

### 把"开工查教训库"变成默认执行
- 用户问：这是默认就会进行吗？（诚实回答：一部分是，一部分靠自觉）
- **把铁律写进记忆**（每轮系统提示注入）：「开工·改进前查 ~/.hermes/lessons 教训库+验证门禁」
- 代价：记忆 99% 满，压缩删掉一条过期 commit 信息腾位置

## 避坑（下次别踩）

1. **别一上来就装外部 RSI 系统**（penguin-harness 等）——它跟 Hermes 是竞争关系，
   装了等于多一套要维护的引擎，违背"禁多建"铁律。先盘自己已有的，缺哪补哪。
2. **"网上说的进化"≠ 我们要做**——先对照用户三铁律（真正好用/别看起来进化/先 v1.0 再迭代）。
3. **记忆满了别硬塞**——用批量操作压缩过期临时信息（commit SHA、已完成状态）腾位置。

## 下一步建议

- 下次真实任务（交付/审计/部署/改码）验证 preflight 是否真触发（用户会看到"任务红线"话术）
- 若某领域反复出错，把该领域教训条目升级为独立 skill 或进规则中心（RuleCenter）
- 教训库稳定后可加一个「定期清理+去重+标注使用率」的维护 cron（先不强上）
