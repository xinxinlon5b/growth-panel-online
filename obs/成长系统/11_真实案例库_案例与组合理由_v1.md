# 真实案例库：案例 → 功能组合 + 理由 v1

> 创建：2026-09-03 | 状态：v1.0（用三个亲历项目反推的第一批案例）
> 用途：这是需求4第2条「成熟成功案例 → N 项组合 + 说明理由」的落地。每个案例 = 真实做过的项目 + 它实际用到的功能组合 + 为什么这套组合适合它。
> 用法：接到新项目 → 找最像的案例 → 参考它的组合 → 用工作台「自由拼装 + 可行性分析」验证。

## 案例一：批量触达类系统（阿尔泰 · 中俄跨境获客）

**项目画像**：多平台(VK/TG/WA/IG/TikTok)触达潜在客户 + AI 筛选 + 跟进。高风险（账号资产值钱，封号=损失）。

### 适合的功能组合（按关卡地图分类）

| 关卡 | 必选功能 | 为什么（这个项目的理由） |
|------|---------|------------------------|
| 可靠性 | 幂等 Idempotency | 触达不能重发（重发=骚扰客户=封号） |
| 可靠性 | 重试 Retry | 网络抖动不能漏发（漏发=丢线索） |
| 可靠性 | 限流 Rate Limiting | 平台风控：同一 IP 高频=封 |
| 安全 | 密钥管理 Secret Mgmt | 平台 token/账号密码必须托管（明文=泄露=被盗号） |
| 安全 | 数据脱敏与合规 | 客户数据（电话/邮箱）隐私保护，跨境有合规红线 |
| 安全 | 审计日志 Audit Log | 发了什么/何时发的可追溯（客户投诉时能查） |
| 风控 | 风控分级（按账号价值） | 主号小号不同策略，新号先测试 |
| 风控 | 触达闸门（fail-closed） | 无登录态/无 token 时跳过而非瞎发 |
| 反模式红线 | 禁批量群发陌生用户 | 平台红线，个人号直接群发=封 |

### 为什么这套组合（一句话）
**批量触达的本质 = "发错比不发更糟"**——所以幂等/重试/限流（防发错）+ 密钥/审计（防泄露）+ 风控闸门（防封号）是刚需，缺一个都可能出事（账号风控封禁教训：触达类系统账号资产值钱，被封=线索管道断）。

## 案例二：卖 AI 能力给小白（NIFTY STUDIO · 本地 AI 商品图）

**项目画像**：本地桌面工具，用户上传图→AI 生成商品图→下载。要扣费、要防薅、用户不懂技术。

### 适合的功能组合

| 关卡 | 必选功能 | 为什么 |
|------|---------|--------|
| 可靠性 | 幂等 Idempotency | 扣费不能重复扣（用户连点=双扣=投诉） |
| 可靠性 | 任务队列 + journal | AI 生成 1-3 分钟，慢任务不能阻塞全站；重启后任务状态可见 |
| 安全 | 路径安全（四层防御） | 用户上传文件=路径穿越高危入口（OWASP 经典攻击） |
| 安全 | OWASP 安全基线 | 对外卖=要防注入/越权/薅羊毛 |
| 计费 | 双通道计费（包月+按量） | 小白买包月不心疼，尝鲜用户不想开月费 |
| 成本 | Token 成本可观测 | 每张图花多少钱看得见（1积分≈¥0.0444） |
| 运维 | SOP 版本化+回滚 | 运营调提示词模板，调错能退回 |
| 性能 | 缓存 Caching | 重复出图请求缓存，降成本提速 |

### 为什么这套组合
**卖工具给小白 = "扣费不能错 + 用户不能搞崩系统"**——幂等/队列/路径安全/成本观测是刚需；小白不懂技术所以 UI 要傻瓜式、出问题能自查。

## 案例三：接平台卖家 API（中俄轻舟 · Ozon 卖家侧）

**项目画像**：把商品/Listing 导入 Ozon 平台销售。轻资产、快速试错、不囤货。

### 适合的功能组合

| 关卡 | 必选功能 | 为什么 |
|------|---------|--------|
| 集成 | 官方 API 优先（不爬虫） | 平台官方 Seller API 稳定合规，爬虫=封店 |
| 数据 | 本地 SQLite（轻量） | 单机跑够用，不上云（省成本） |
| 内容 | 批量生成 + 多语言优化 | 俄语 Listing 批量生成+DeepSeek 优化 |
| 业务 | Go/No-Go 决策点 | 不囤货不借钱不 All-in，到点评估继续或转 |
| 合规 | 平台条款先查 | 1688 自动询价被 block 教训：先查平台自动化边界 |

### 为什么这套组合
**接平台卖货 = "合规活着比快重要"**——官方 API + 轻资产 + Go/No-Go 决策，是用最小成本试错的结构。

## 反模式（案例里踩过的共性坑）

| 坑 | 哪个案例 | 正确做法 |
|----|---------|---------|
| 先跑通后拆分（单文件 3500 行） | NIFTY | 一开始拆模块（哪怕慢几天） |
| 个人号直接群发 | 阿尔泰 | 社区号/小号测试 + 规则引擎分层 |
| 没查平台自动化边界就写爬虫 | 轻舟 | 先查官方 API + 合规 |
| 风控/红线写在文档不写进系统 | 三项目共性 | 红线=代码里的硬约束（fail-closed） |

## 怎么用这个库

1. 新客户来 → 判断他是哪类（批量触达/卖工具/接平台/内部Agent/知识库…）
2. 找最像的案例 → 参考必选组合
3. 去工作台「场景向导/自由拼装」搭 → 「分析可行性」验证缺啥
4. 做完新项目 → 回填新案例（这个库会越用越厚）
