# 28 · 库·脑·脸 三层分工蓝图 v1

> 创建: 2026-09-09 | 定位: 企业成长系统的**架构纲领**（方向级，非单次任务）
> 一句话: Obsidian = 库（唯一事实源），Agent = 脑（唯一动作者），网页 = 脸（只读投影 + 给客户看成品）

---

## 〇、30 秒看懂

以前把「网页」当成了两件事一起干：**知识库 + 展示层**。结果知识存了两份（Obsidian 一份 md，网页一份 JSON/courses），天天费力同步、还总出错（build 相对化、拦截器、CDN 缓存、数据漂移）。

正确分工：

| 层 | 谁 | 管什么 | 铁律 |
|---|---|---|---|
| **库** | Obsidian | 知识、索引、溯源、双链、图谱 | 知识只存这一处 |
| **脑** | Agent | 检索、分类、总结、推理、调用、避坑、写回 | 只跟库打交道，不跟网页打交道 |
| **脸** | 网页 | 给客户看成品、给小白看可视化、渲染 | 只读库，不存知识、不做推理 |

**一句话：知识只存 Obsidian 一处；agent 读库写库；网页是库的投影，给人眼看，不给 agent 用。**

---

## 一、现状诊断（为什么总觉得「差意思」）

不是网页做得不够好，是**三个事实源并存，网页和 Obsidian 之间大量双份维护**。9/9 盘点的实况：

### ✅ 已经做对的（别动）
- **13 个内容 tab**（09 关卡地图 / 01 审核标准 / 10 模板 / 11 案例 / 12 词典 / 15 数据 / 16 调研 / 17 知识库 / 14 装机 / 23 载体 / 24 零件 / 25 全景 / 27 权威调研）全部 `src=/obs/成长系统/*.md` —— **这就是「库的投影」正确形态**，改 md 即改网页。
- **动作管道**：`/api/ask`（调 agent 问答）、`/api/do`（派活）、`/api/collect`（收录）、`/api/save_doc`（写库）、`/api/audit_reports`（读复盘）—— 这是「脸连脑/库」的正确接口。

## 二、三层各自职责（边界）

### 库（Obsidian）—— 唯一事实源
- 决策卡 `cards/`（7 张 + index.json）
- 方法论卡 `foundations/`（FDE/AR/POC/CJ/REL/EVAL/COMP/CRISIS/ECO/PRICE/SALES/ORG）
- 复盘 `复盘区/`（实战复盘 + 审核报告）
- 评测 `黄金集/`（golden v0.1→v1.1 + eval.py）
- 学习 `学习池/`（[学习]笔记 + raw 原文）
- 项目 `项目库/`（阿尔泰/中俄轻舟/NIFTY）
- 成长系统文档 `成长系统/`（00-27 + 本蓝图）
- **以后要收编进来**：视频原始语料、书、学习方向、术语关联

### 脑（Agent）—— 唯一动作者
- 接客户 → 读 `cards/index.json` + 对应决策卡 → 给方案
- 做项目前 → 读方法论卡 + 复盘 + 黄金集 → 分类总结 → 避坑
- 项目做完 → 写回 `复盘区/` → 飞轮转动
- 定期 → 跑 `黄金集/eval.py`、看候选池 ★、读学习池
- **铁律：先读库再开口，禁止凭记忆重生成，每条结论带出处**

### 脸（网页）—— 只读投影 + 成品展示
- 渲染库内容给人看（13 个 tab 已正确）
- 给客户看成品（决策卡、方案）
- 给小白看可视化（关卡地图、术语弹层、读书）
- 动作按钮（调 agent / 写库）—— 这些是「脸连脑」的管道，保留
- **铁律：不存知识数据、不做推理、不维护独立 JSON**

## 三、落地顺序（分 5 阶段，克制推进）

### Phase 0 · 立协议（零风险，最高杠杆，先做这个）
在库内立一份「Agent 知识库调用协议」，把「先读库、禁凭记忆、每句话溯源」从「最好这样做」升级成「不这样做就算错」。
- 吸收 GitHub `claude-obsidian`（14.7k★）的 **Ground（溯源）ledger** 思想：每条重要论断留「出处 + 权威性 + 支持/矛盾 + 置信度 + 审核状态」。
- 不碰网页、不碰代码，纯加一个 md 协议文件。

### Phase 1 · 盘双份（出「双份维护清单」）
把上表「⚠️ 双份维护重灾区」逐一和 Obsidian 对账，产出精确清单：哪些双份、哪个为准、哪些是网页独有。给你拍板用。

### Phase 2 · 收编（消灭双份，分小步，先轻后重）
- **轻的先收**：`learning_paths.json` → 进库；`courses/` 书 → 进库 `读书笔记/`；`method_clusters.json` ↔ `18_v2.md` 合并为单一事实源。
- **重的单独决策**：`videos_library.json`（2.5MB）**不塞进 Obsidian md**（会卡），定成「独立数据目录 + agent 维护 + 网页只读 + 库内留索引」。

### Phase 3 · 网页瘦身（降级）
- 把网页里「推理 / 知识管理」交给「脑」：体检引擎已 v3 接 agent ✅；术语关联、方法论加工逐步由 agent 在库侧维护。
- 网页只留：展示渲染 + 动作按钮。

### Phase 4 · 飞轮闭环（长期）
接客户 → 读决策卡 → 做项目 → 读方法论+复盘 → 写复盘 → 跑黄金集，全走「Obsidian + agent」；网页只在最后「给客户看成品」时出场。

---

## 四、验收标准（做到什么算成）

- [ ] 每个知识只有**一处事实源**（不存在「网页 JSON 和 Obsidian md 各有一份要分别改」）
- [ ] agent 开工前**默认先读库**（有协议可查、可验证）
- [ ] 网页**不再维护任何「知识数据」**，只维护「渲染 + 动作按钮」
- [ ] 给客户看的成品，从 Obsidian **一键渲染**，不手工双写
- [ ] 你置顶会话里批的两个错误（丢出处 / 自己编规则不调库）**不再复发**

## 五、红线（不做什么）

- ❌ 不推倒网页重来（它是「脸」，给客户看 + 小白可视化有价值）
- ❌ 不把 2.5MB 视频库塞进 Obsidian md（会卡死搜索/图谱）
- ❌ 不破坏现有 13 个 tab 的「读 /obs/」架构（那是正确的部分）
- ❌ 不用 Kimi K3 按量（M3 牛马铁律）
