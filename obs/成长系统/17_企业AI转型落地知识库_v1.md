### 1.2 为什么 95% 失败（核心结论）

> 企业 AI 落地**不是技术问题**，而是 **战略 × 数据 × 组织 × 工程** 的复合治理问题。

**一句话共识**：企业 AI 落地 = "以**数据治理为底座**、以**变革管理为驱动**、以**业务价值为目标**、以 **FDE+CoE 为协作枢纽**"的组织级转型工程。

## 🧱 第2类· 前期准备（七项准备工作，接项目先自查） {#c2}

### 2.1 战略对齐（第一优先）

| 检查 | 内容 |
|---|---|
| CEO 亲自参与? | 62% 领先者由 CEO 直接推动；落后者 56% 由 IT 主导 |
| 业务问题驱动? | 先问"解决什么业务问题"，不是"先有锤子找钉子" |
| 可量化目标? | 北极星指标 + 季度 OKR，不是"我们要数字化转型"口号 |
| 三维对齐? | 战略 → 价值 → 能力 → 治理/文化/技术 六维都覆盖 |

### 2.2 数据准备度（四象限检查清单）

| 维度 | 最低标准 |
|---|---|
| 数据可发现 | 80% 核心数据可发现（目录/元数据/血缘） |
| 数据可访问 | SLA ≥ 99%，P95 < 1s（API/权限/实时性） |
| 数据质量 | 准确率 ≥ 95%，缺失率 < 5% |
| 数据合规 | PII 100% 识别，符合 PIPL/GDPR |

**10 项动作清单**：数据资产盘点 → 分类分级 → 质量评估 → 血缘 → 主数据管理 → 脱敏 → 访问治理 → API化 → 向量化管道 → 合规审计。

### 2.3 基础设施准备

- **算力三分**：训练(GPU集群) / 推理(CPU/GPU/NPU) / 边缘
- **云 vs 自建**：中小/快速验证 → 公有云；合规要求 → 私有云；央国企/敏感 → 自建
- **国产替代**：昇腾/海光/寒武纪（性能约 H100 的 40-70%）

### 2.4 团队与人才（见第6类 详细）

**关键角色紧缺度**：AI 产品经理 ★★★★★(50-150万)、MLOps 工程师 ★★★★★(60-120万)、LLM 算法 ★★★★★(80-200万)。

**Build vs Buy vs Borrow**：自建(7-2-1 法则) / 外购 / 外包。

### 2.5 变革管理（最易被忽视）

- **72% 转型失败原因 = 人才和文化，不是技术**
- AI 转型不是裁员：**Augment(增强) > Replace(替代)** 是主旋律
- 78% 员工自带 AI → 提供官方安全工具 + 制度明确，消除影子 AI
- 透明沟通 + 培训 + 跨部门 KPI

### 打法基准（Quick Win 节奏）
建 **10-30 个用例池** → 用"业务价值 × 数据可行性"二维评分 → 选 **3-5 个 Quick Win** → **8 周冲刺**（2 周数据 + 4 周建模 + 2 周验证）。AI 价值需 **18-24 个月**持续投入才兑现，别指望 3 个月见转型。

### 4.3 SOP-A 核心（销售 Agent 9 步法）

**9 步**：①目标定义(任务书) → ②客户旅程分析(旅程图) → ③数据采集(客户+历史对话+异议库) → ④Agent 训练(脚本/异议/触发器/话术) → ⑤试点启动(控客群+监控指标) → ⑥规模化优化 → ⑦人类角色重塑 → ⑧治理/伦理/监督 → ⑨持续改进文化。

**试点关键指标**：联系时间/响应率/线索合格率/成交率/错误率/满意度。

### 4.4 SOP-F 关键发现（AI Coding 助手 90 天）

- outcome-based 训练转化率比 feature-based **高 34%**（Journal of Sales Technology 2025）
- 集成 ≥3 数据源 vs 单一 CRM → **58% 提升**
- Forrester 2025：71% 销售团队采用率（提前设计人机协作协议）

### 4.6 真实客户案例集（给客户讲故事用）

> 以下案例来自调研报告的 SOP 场景,讲给客户听,证明"这条路有人走通过"。

**案例 1 · 母婴电商的客服减负（SOP-D 中文版）**
某母婴电商每天被问 200 次"怎么退货/发错货怎么办"。做法:① 收集近 3 月高频问题 200 条 → ② 分类 + 同义词标签("退款""退货""不要了"归一类) → ③ 按「一句结论+具体内容+下一步行动」模板写答案 → ④ 建知识库 → ⑤ 客服和顾客用同一套(顾客问 AI、座席也问 AI) → ⑥ 每周看"有帮助吗"反馈优化。
**结果**:80% 重复问题 AI 直接答,人工只处理复杂客诉;新客服培训从 2 周缩到 2 天。

**案例 2 · 制造业 AI 销售 Agent 90 天（SOP-C,Threekit）**
某做 B2B 复杂设备的制造商,客户在官网问完总被"转人工没人跟"。做法:Month 1 定架构 + 挑 2 个产品线试点;Month 2 配 Agent 四件套(从最佳销售提问流提取**提问流** + 产品匹配规则 + 提案生成规则 + 经销商路由);Month 3 小范围试点(1 个着陆页 + 1 组经销商)验证 → 修正 → 全量上线。
**关键洞察**:指标不看"聊了多少",看**商业影响**——线索带没带产品线、提案准不准、客户在提问流第几步流失(第 3 题后流失 = 问太技术了)。

**案例 3 · AI Coding 助手 70 人团队（SOP-F 实测）**
某 70 人研发团队推 AI Coding 助手,做法:第 1-2 周给全员权限、零指导观察怎么用 → 第 3-4 周 Prompt 培训 → 第 2-3 月嵌入工作流 + 每周回顾。
**实测结果**:PR 提交 **+28%**、代码 review 轮次 **-21%**、测试覆盖 **+13pp**;最大收益在测试编写/样板代码/文档;代价:复杂逻辑缺陷风险上升、资深开发复杂任务反而慢 19%。
**教训**:AI Coding 适合"搬砖活",复杂架构判断还得靠人——**Augment 不是 Replace**。

**案例 4 · 销售线索筛选 7 步（SOP-B,BizAI）**
某 B2B 公司线索多但销售没空筛。做法:集成 CRM+邮件+官网行为(≥3 数据源)→ 映射客户旅程 → 用**真实最佳成交对话**训练(outcome-based 而非 feature-based)→ 设计人机协作(什么时候升级给真人、带什么上下文)→ 试点迭代。
**实测**:outcome-based 训练转化率比 feature-based 高 **34%**;集成 ≥3 数据源比单一 CRM 提升 **58%**。

## 👥 第6类· 团队建设（FDE 模式） {#c6}

### 6.1 FDE 是什么
**Forward Deployed Engineer** —— 派驻客户现场、写生产代码、对**生产价值闭环**全面负责的工程师（Palantir 2009 首创）。
> 传统工程师为多客户做一个能力；FDE 为一个客户做多个能力。
> "FDE is the product, at least until the product can stand on its own."

### 6.2 FDE 与我们的关系（关键！）
**你做的"企业AI落地顾问/FDE"正是这个模式** —— 你= FDE + DS(Deployment Strategist) 双角色：既写系统又桥接业务。

### 6.3 三种组织模式
1. **FDE in Engineering**（Palantir 原版）：全职工程师，代码进主仓
2. **FDE in Product**：向产品汇报，反馈快速进产品
3. **Standalone Delivery Org**（微软 Frontier）：独立交付组织，可规模扩张

### 6.4 厂商布局（FDE 已主流化）
| 厂商 | 规模 |
|---|---|
| Palantir | 数千（历史最多） |
| Microsoft Frontier | 6,000 人 / $2.5B |
| AWS | 数千 / $1B |
| OpenAI | ~150 收购 + 自建 |
| Anthropic | 大幅扩张 |

### 6.5 薪酬参考（国际）
FDE 中位 $173K-$231K；Staff/Principal $190K-$288K；顶级 $350K-$550K。国内 AI 产品经理 50-150 万/MLOps 60-120 万/LLM 算法 80-200 万。

### 6.6 核心 5 + 7 角色
**核心5**：AI 产品经理(APM) / 数据科学家 / ML 算法工程师 / 提示词工程师(PE) / 领域专家。
**扩展7**：MLOps / 数据工程师 / AI 安全 / SRE / 业务 Champion / 平台工程师 / 解决方案架构师。
**招聘顺序**：先 APM + 1 个全栈（能 POC）→ MLOps（能生产化）→ 领域专家（规模化）→ 安全/合规。

### 6.7 组织治理 CoE 演进
CoE 规模：**8-15 人（中小）/ 30-50 人（大型）**；演进 = 集中(0-12月) → 联邦(12-24月) → 分散(24月+)，明确定四类决策权。

### 6.8 组织模式 & 招聘顺序（OpenClaw v2 补充）
**组织模式**：中心化(早期 <10 人) → 嵌入(核心产品) → **Hub-and-Spoke(>10 人多数推荐)**；CoE 与 FDE 形成 Hub-Spoke(CoE 供平台+标准，FDE 在 BU 交付)。

**最小可行 3 人**：ML 工程师 + 数据工程师 + 产品经理。生产级 5-7 人。完整 7 角色：MLOps / ML / Data Scientist / Data Engineer / 平台架构师 / DevOps / Product&Domain Owner。

**招聘顺序(修正版)**：①数据工程师(打地基) → ②ML+DS → ③MLOps(首次生产部署前) → ④Risk Lead(监管行业) → ⑤AI Product Owner(项目开始就要) → ⑥FDE(与 CoE 同步)。

## ⚠️ 第7类· 避坑清单（问题根因 + 致命错误） {#c7}

### 7.1 六大类问题根因速查

| 层 | 最大问题 | 根因 | 解法 |
|---|---|---|---|
| 战略 | 战略悬浮/盲目跟风 | 技术出发非业务 | 业务问题驱动 + 二维评分 |
| 数据 | **80% 项目在此失血** | 数据孤岛/脏/无标注 | 统一平台 + 数据契约 + 预处理 |
| 模型 | 幻觉/不稳/成本失控 | 缺校验/采样/未压缩 | RAG+溯源 / 调低温度 / 缓存路由 |
| 工程 | **PoC 死(90%)** | 实验室思维 | 工程 Day1 介入，PoC=Mini Production |
| ROI | 只算成本不算收益 | 无 Baseline/对照组 | ROI 四层 + A/B + 半年评估 |
| 组织 | 高管不支持/影子AI | 价值未证/无官方工具 | 季度汇报+QuickWin / 官方工具+制度 |

### 7.2 6 个致命错误（TechOrange）
1. 没有清晰的业务问题
2. 数据基础不够硬上 AI
3. 误把 PoC 当成功
4. 忽视变革管理
5. 没有 MLOps/LLMOps 体系
6. 缺乏长期投资承诺

### 7.3 ROI 计算四层（别只算 Token）
**L1 运营效率**（省多少工时）→ **L2 体验改善**（转化+% ）→ **L3 业务增长**（新收入）→ **L4 战略价值**（新能力）。

**ROI 度量陷阱**：只算成本不算收益 / 只算节省不算增长 / 把所有价值归于 AI（实际是 AI+流程改造）/ 短长期混算。

### 7.4 数据准备最低标准（红线）
- 准确率 ≥ 95%，缺失率 < 5%，80% 核心数据可发现，PII 100% 识别。
