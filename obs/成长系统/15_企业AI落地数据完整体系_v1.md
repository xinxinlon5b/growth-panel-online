## 第一课 · 企业数据全景（四族 + 每族配案例）

> 切法:**结构化程度 × 归属**,四族不重不漏。

### 1.1 结构化数据（行列分明、系统可查）

| 类型 | 具体 | 业务意义（能解决什么 AI 场景） | 散落在哪 |
|---|---|---|---|
| **交易/订单** | 销售单/采购单/订单明细 | 预测销量、对账、回款预警 | ERP（用友/金蝶/管家婆） |
| **主数据** | 客户/商品/SKU/供应商 | 客户 360° 画像、商品推荐 | CRM + Excel 混着 |
| **财务** | 应收应付/流水/发票 | 现金流预测、自动对账 | 财务软件 + 银行导出 |
| **电商平台** | 店铺订单/评价/流量 | 选品、差评归因、客服 | 聚水潭/旺店通/店小秘 |
| **人事** | 员工/排班/工资 | 排班优化（低频） | 人事系统/Excel |
| **生产（制造）** | 工单/质检/BOM | 排产、良率分析 | MES/Excel |

**案例（五金配件厂）**:老板要"回款预警"——应收表在财务电脑 Excel、发货在 ERP、客户信用在销售微信里。三份数据拼起来,AI 才能算出"张总这月该催了"。单看任何一份都不够。

### 1.2 半结构化（有标记但不能直接当表）

| 类型 | 具体 | 业务意义 | 散落在哪 |
|---|---|---|---|
| **Excel 台账** | 各种手工表 | **国内中小企业的"真数据库"** | 个人电脑,一人一份 |
| **JSON/接口报文** | 平台 API 返回 | 表问答/自动合并 | 平台后台 |
| **日志** | 系统运行记录 | 异常检测（少数） | 服务器 |
| **邮件** | 询价/往来 | 商机挖掘 | 邮箱 |

**案例（贸易公司）**:5 个业务员各有一份"客户询价表",格式五花八门(有的叫"客户名"、有的叫"公司")。想让 AI 统一管理询价,第一步不是上系统,是把 5 张表的口径对齐。

### 1.3 非结构化（~80% 信息量,最被浪费）

| 类型 | 具体 | 业务意义（★★★★ 越高越值钱） | 散落在哪 |
|---|---|---|---|
| **微信/企微聊天** | 询价/对账/售后 | ★★★★ 客服+商机金矿 | 员工手机/企微后台 |
| **老师傅经验** | 怎么修/怎么判断 | ★★★★★ 稀缺壁垒,不可复制 | 老师傅脑子里! |
| **办公文档** | Word/PDF/合同 | 制度问答、合同抽取 | 共享盘/微信文件 |
| **图片/质检图** | 产品图/不良品照片 | 商品图、视觉质检 | 手机/相机/系统 |
| **音视频** | 会议录音/培训视频 | 转 SOP、带教 | 个人电脑 |
| **纸质单据** | 送货单/手写报价 | 先扫描才能用 | 文件夹/档案柜 |

**案例（老师傅问答）**:某机械厂最怕老师傅退休——30 年"听声音知道哪坏了"没人能接。把他口述的 200 个判断场景录下来转成文字 → AI 能当"老师傅学徒",新人先问 AI 再上手。

### 1.4 外部数据

| 类型 | 具体 | 业务意义 |
|---|---|---|
| 企查查/天眼查 | 客户背景/风险 | 客户风控 |
| 行情/竞品 | 价格/新品 | 定价、选品 |
| 海关数据 | 外贸流向 | 外贸客户增量 |

### 1.5 哪些数据最值钱（给客户排序的判据）

**判据**:钱流经的数据 > 稀缺难复制 > 高频重复人工 > 内部运营 > 外部公开。**结构化程度 ≠ 价值**——微信询价记录可能比 ERP 报表值钱。

| 最值钱梯队 | 数据 |
|---|---|
| 🥇 第一梯队 | 主数据（客户/商品/供应商统一档案）+ 沟通数据（聊天/询价）+ 流程数据（订单从哪来到哪去） |
| 🥈 第二梯队 | 财务/回款、老师傅经验、质检记录 |
| 🥉 第三梯队 | 内部文档、制度、报表 |

## 第二课 · 数据散落在哪（国内中小企业现实）

> 客户以为"数据都在 ERP 里"——**现实:Excel 是主库、微信是主渠道、纸质是历史、老板的脑子是决策中心**。

| 你以为 | 现实 |
|---|---|
| 有 ERP = 数据都在系统 | ERP 常常只录了该录的一半,另一半在 Excel/微信 |
| 有 CRM = 客户都在 | CRM 里的客户名和微信里的"王总"对不上 |
| 有财务软件 = 账清楚 | 对账靠月底财务加班 3 天拼 Excel |

**给客户的认知对齐话术**:"您缺的不是数据平台,是先把数据变成'能问问题'的样子。前两周我们先拿一张真实表做出您要的答案,再决定要不要买任何系统。"

## 第三课 · 数据加工链（Medallion 通俗版 = 买菜三层）

> Databricks 官方:bronze=原样(raw) / silver=校验过(validated) / gold=按业务口径富化(enriched),逐层让数据"结构性和质量渐进提升"直到适合 BI 和 AI【核:Databricks 官方文档】。

### 3.1 给客户的人话版

| 层 | 人话 | 干什么 | 目的 |
|---|---|---|---|
| **铜层 Bronze** | 菜市场买回来原样扔冰箱 | 原始数据不改一字,先存住 | 将来算错账能回源头查,洗坏了能重跑 |
| **银层 Silver** | 洗菜切菜 | 去重/修格式/补缺/对齐口径 → 干净明细 | 变成"能分析的干净数据" |
| **金层 Gold** | 上桌摆盘 | 按老板口径聚合:本月毛利/客户贡献 | **业务直接看、直接喂 AI** |

**SMB 忠告**:不必上平台,但**必须保留"原样层"**——多数小厂死在"从 Excel 导出来就直接清洗,原表被覆盖"。Excel 三文件夹也能做:原始盘 / 清洗区 / 报表区。用两层起步(原样+可用),脑子里保留三层逻辑,将来上系统不推倒重来。

### 3.2 清洗到底洗什么（六件套,每个给一个中国场景）

> IBM 数据质量七维:准确/完整/有效/一致/唯一/及时/合用;Gartner 转引:**数据质量差平均每年让企业损失 $12.9M**【核:IBM Think】。

| # | 洗什么 | 中国场景 |
|---|---|---|
| 1 | **去重** | 同一个客户微信叫"王总"、Excel 叫"王建国"、ERP 两条记录 → 合并主档 |
| 2 | **格式统一** | 日期(2024.1.1 vs 2024-01-01)、手机号(带不带 86/空格)、单位(件 vs 箱 vs 打)。最常见也最便宜 |
| 3 | **缺失处理** | 没录手机号/空库存 → 补默认/标"未知"/丢弃,**要业务拍板不是技术决定** |
| 4 | **错值/异常** | 库存为负、单价为 0、金额超 10 倍 → 规则校验 |
| 5 | **PII 脱敏** | 手机号/身份证/银行卡 → 涉及个保法;聊天记录喂 AI 前先脱敏 |
| 6 | **口径统一** | 什么叫"成交"(付款=成交?发货=成交?)、"毛利"含不含运费 → **口径只能老板和业务定,是最难最值钱的一步** |

> **口诀**:"清洗不是把脏水倒掉,是把口径对齐;错得整齐的数据比乱的真数据有用。"

### 3.3 非结构化 → AI 可用（四条支线汇成一条主路）

**主路 = 解析成文本 → 切片 → 向量化 → 入库可检索**。按原料分四条支线:

| 原料 | 怎么转文本 | 工具 |
|---|---|---|
| **文档/PDF/扫描件** | 扫描件先 OCR;PDF 转干净 Markdown;版面还原(表格别拆散) | MinerU(上海AI实验室,中文表格强)/ PyMuPDF / PaddleOCR |
| **图片/图纸** | OCR 提字 + 视觉模型理解 + 图像向量(以图搜图找相似缺陷) | VLM 模型 / CLIP |
| **语音/视频** | 录音→ASR 转写→带时间戳和说话人的文本 | Whisper(OpenAI开源)/ FunASR(阿里,中文+说话人分离) |
| **聊天/Excel** | 聊天先脱敏;Excel 先做"结构识别"转成真表,别当文档切 | 导出工具 |

**主路四步**:
1. **切片 chunking**:长文切成有语义边界的块(按标题/段落/表格切,别硬切 500 字)
2. **Embedding 向量化**:每块转成"意思坐标"。中文用 BGE(智源)/ 阿里 text-embedding-v3
3. **入向量库**:Milvus / pgvector(轻)/ Qdrant,每块带元数据(来源/部门/时间/权限)
4. **检索**:用户提问 → 转向量 → 召回相关块 → 交给大模型组织答案

### 3.4 知识库 / RAG 的本质

> IBM 定义:RAG(检索增强生成)在**推理时**把外部/私有/最新数据检索出来喂给大模型再作答——解决"大模型只懂公开数据、不懂你公司";相比微调:成本低、可随时更新、可给出处【核:IBM Think】。

**本质一句话**:知识库 = 把"公司里散落的文档 + 老师傅脑子里的经验"变成"每个员工用自然语言就能查、答案能追到原始文件"的公司记忆。

- 它解决"知道",不解决"会做"。文档问答只是第一层;同一条管道换个数据源(订单→预测、质检图→缺陷识别)就是新 AI。
- 质量取决于三件事:**解析干不干净(烂扫描件=垃圾进)、切片合不合理、检索准不准**。不是把 100 个 PDF 丢进去就自动有知识库。
- 与"微调"分工:先 RAG 解决私有知识问答,不够且要模仿风格再微调,别一上来就微调。

**案例(给客户讲)**:某母婴电商客服每天被问 200 次"怎么退货"。把 50 份售后政策 + 300 条历史问答做成知识库 → 客服在对话框问"发错货了怎么办" → AI 秒回标准处理流程 + 政策原文出处。客服从"翻文档 3 分钟"变"3 秒"。

### 3.5 数据血缘

> IBM:追踪数据随时间流动,弄清它从哪来、怎么被改、最终到哪,用于把错误追到根因【核】。

给客户的用途:① AI 答案错了能倒查源头;② 改字段口径知道影响哪些报表;③ 合规审计有交代;④ **AI 时代:每个 AI 回答都标"基于哪份数据",老板才敢信**。

SMB 起点:**一张"数据地图 Excel"**——每份数据 = 来源系统 + 加工步骤 + 去往哪里 + 谁负责。数据管道超 10 条再上工具(OpenLineage/DataHub)。

## 第四课 · 工具栈选型（上系统前看这课,带案例）

### 4.1 分层关系一张图（从业务系统到 AI 应用,数据怎么流）

| 层 | 装什么 | 代表工具 |
|---|---|---|
| ① 业务系统 | 原始数据在这产生 | 用友/金蝶/Excel/微信 |
| ↓ 存进 | 数据库/数仓 | MySQL / PostgreSQL / SQLite / DuckDB / ClickHouse |
| ↓ 清洗加工 | ETL 同步转换 | DataX / dlt / 脚本 |
| ↓ 向量化 | 向量库(语义检索) | pgvector / Milvus / Chroma / Qdrant |
| ↓ 接 AI | RAG 平台 | Dify / FastGPT / RAGFlow / Coze |
| ↓ 最后 | **AI 应用** | 客服问答 / 经营分析 / 质检 |

### 4.2 第一步到底上什么？（国内中小企业）

| 客户真正要的 | 数据形态 | 第一步该上什么 |
|---|---|---|
| 客服/销售要"翻资料问答" | 文档类 | **不是数仓,是知识库整理 + RAG 问答** |
| "订单/库存/财务对不上" | 结构化流水 | 抽最关键 1-2 张表进轻量库 |
| "让 AI 帮我分析经营" | 结构化 | **前提是数据先干净进库**;脏 Excel 喂 AI = 自信的错答案 |

**Excel 要不要先整理?——要,但只整理"要用的那张表"**,不是全面整理(无底洞)。整理三件事:固定表头字段、统一格式、去重。80% 脏数据清洗发生在这层,不是靠 ETL 工具。

**轻量数仓什么时候上?** 满足 ≥2 条:数据源 ≥3 系统、要跨系统关联查询、月报周报要自动出、要给 AI 结构化事实。不满足就**别上数仓**,用数据库即可。

### 4.3 数据库选型

| 维度 | SQLite | MySQL | PostgreSQL | DuckDB |
|---|---|---|---|---|
| 本质 | 单文件嵌入式 OLTP | 经典关系库 | 功能最全关系库 | 嵌入式分析库(OLAP) |
| 亮点 | 免安装 | 生态/招人最全 | **pgvector 一个库管业务+向量** | 直查 Excel/CSV/Parquet |
| 适合 | 原型/工具 | OLTP 主库 | **新上系统首选** | 数据在 Excel 先看价值 |
| 决策 | 原型验证 | 存量继续 | 一步到位+未来 RAG | Excel→分析跳板 |

**案例**:贸易公司 3 万行订单 Excel,先用 **DuckDB 一条命令直查**验证"哪个客户毛利高";验证有价值后迁 **PostgreSQL 单机**;真到报表量大再谈 ClickHouse。

### 4.4 向量数据库（RAG 为什么需要 + 怎么选）

**为什么需要**:LLM 没学过企业私有知识,直接问会胡编。RAG = 文档切块→转向量→提问转向量→相似度检索→连原文给 LLM。向量库就是"让 AI 秒查的私密词典"。
**什么时候不需要**:文档 < 几百条可全塞 prompt,或 Elasticsearch 关键词够用。

| | pgvector ★22.9k | Chroma ★29.2k | Qdrant ★34.4k | Milvus ★46.0k |
|---|---|---|---|---|
| 形态 | PG 扩展 | 嵌入式 | 单机性能强 | 分布式集群 |
| 部署 | **零新增组件** | pip 即用 | 轻 | 重(要养) |
| 适合 | **中小默认答案** | demo/开发 | 中间档 | 亿级/企业级 |

**选型阈值**：<1000 万条用 pgvector/Chroma；<1 亿用 Milvus/Qdrant；>1 亿用 Milvus/Vespa/Pinecone。

**规则**:有 PG → pgvector;纯开发 → Chroma;千万级以上 → Qdrant → Milvus。**第一天上 Milvus 集群 = 反模式**。

### 4.5 RAG 平台（国内主流 4 选）

| | Dify ★154.9k | RAGFlow ★90.2k | FastGPT ★29.6k | Coze 扣子 |
|---|---|---|---|---|
| 定位 | LLMOps 应用底座 | 深度文档理解 RAG 引擎 | AI Agent 平台 | 零代码智能体(闭源) |
| 最强 | 生态/插件/API 化 | **复杂文档解析**(DeepDoc) | 上手快中文友好 | 最易用插件海量 |
| 短板 | 对小白略重 | 重,非技术累 | 生态不如 Dify | 闭源数据在云端 |
| 私有化 | 社区免费自托管 | Apache-2.0 | 可自托管 | 仅企业版 |
| 适合谁 | 企业私有化+当底座 | 文档复杂要"有据可查" | 非技术团队 | 最快 demo |

**⚠️ 高频误区:RAG 平台 ≠ 数据平台**。Dify 里的"知识库"管的是文档切片,不是订单/客户/库存。要管结构化经营数据仍要数据库/数仓 + BI。

### 4.6 ETL：第一单 = 一个 pandas 脚本,不是一套平台

| | 脚本(pandas/SQL/duckdb) | DataX ★17.3k | Kettle/PDI |
|---|---|---|---|
| 形态 | 自己写 | 离线批量同步 | 图形化拖拽 |
| 适合 | **<百万行,中小默认** | 定时多源抽数仓 | 业务自助复杂转换 |
| 升级时机 | 源≥3 且每日同步 → DataX | 要图形编排 → SeaTunnel | — |

### 4.7 推荐栈（两套直接抄）

| 规模 | 组合 |
|---|---|
| <50 人 PoC | SQLite/PG + dlt + DuckDB + BGE + Chroma/pgvector + **AnythingLLM** |
| <500 人生产 | PostgreSQL + DataX/dlt + ClickHouse + BGE-M3 + pgvector/Qdrant + **Dify/FastGPT** |
| 文档密集(法务/合同/手册) | 同上 + **RAGFlow** 文档解析前置 |
| 信创/国产化 | PG→达梦/KingbaseES;ClickHouse→StarRocks;embedding→BGE |

### 4.8 Obsidian/Notion 定位（直接回答"是不是太初级"）

| 场景 | Obsidian/Notion 够吗 |
|---|---|
| 管**自己的知识**(个人/小团队) | ✅ **够用,不初级** |
| 做**企业级 AI 应用**让全员查 | ❌ **不够**,走 PostgreSQL+pgvector+Dify;Obsidian 只当"数据源之一"(md 导出喂 RAG) |

**一句话**:Obsidian 不是数据库/数仓/向量库,它是**知识沉淀层 + 冷启动素材源**。

## 第六课 · 中小企业六大误区（照镜子用）

| 误区 | 真相 |
|---|---|
| 1. "接个大模型 API,公司就有 AI 了" | 大模型是**最便宜最同质**的部分;AI = 模型×数据×流程。**卡点永远是自家数据喂不喂得进去、干不干净**(数据质量差年均损失 $12.9M) |
| 2. "我们数据都在 ERP 里" | Excel 是主库、微信是主渠道、纸质是历史、老板脑子是决策中心。ERP 只录了一半 |
| 3. "先搞数据治理/上数据平台" | 治理不是前置项目,是长出来的。从**一个业务痛点 + 需要的那条数据链**闭环起步(两周见真章) |
| 4. "AI 就是做个问答机器人" | 文档问答是**最浅一层**。同一条加工链,接订单=预测,接质检图=缺陷识别,接聊天=客服商机 |
| 5. "数据是 IT/信息部的事" | 口径("什么叫成交")只有**老板和业务**能定。清洗最大的坑是口径之争,不是技术 |
| 6. "等数据干净了再上 AI" | 永远等不到。挑**离钱最近、最窄**的数据先做,质量螺旋式提升;历史脏数据能用就行,别为完美主义停工 |
