# 43 · Agent 调度规则 v1

> 创建: 2026-09-10 | 用途: 回答「以后 agent 调度 Obsidian 工作时，什么情况用哪个 SOP、为什么」——把模糊的临场判断变成成文规则。
> 配套: 总图 `master_map.html` · 审计 `42_全景地图收口审计与总图_v1.md`

## 〇、路由总原则（四条线互不串门）

| 你要什么 | 去哪条线 | 典型资产 | 为什么 |
|---|---|---|---|
| **要判断**（这单接不接/报多少） | 决策卡线 | `cards/` 7 张 | 决策卡带档位+价格+适用边界，直接可对外 |
| **要做法**（这事怎么干） | 方法卡 / SOP 线 | `foundations/` 25 卡 + 38 号 8 SOP + 39/40 | 卡是单点深度，SOP 是流程顺序 |
| **要出处**（凭什么信你） | 权威线 | 34 + 36 + 调研2 三份 | 一手源带 URL，对外可查 |
| **要灵感**（找参考/找招式） | 素材线 | 39/40 + 视频库 514 + 方法簇 111 | 素材是原料，不是结论 |

**铁律**：素材 ≠ 结论。拿 39/40 里的内容对外说，必须先经方法卡/SOP 验证或标「来自实战分享，未经验证」。

## 一、场景 → 查什么 → 为什么（主表）

| # | 什么情况 | 查什么 | 为什么 |
|---|---|---|---|
| 1 | 客户刚来、说不清要什么 | **38 SOP-1 PSF 三关** + `REQ-001` + requirement-clarifier | 先杀错误问题——95% 项目死在做错的问题上（MIT） |
| 2 | 客户说「要上 AI」但需求空泛 | **39 方法 1.6 反 AI 幻觉提问清单** | 6 个问题戳破伪需求，避免承诺做不到的事 |
| 3 | 要报价 / 客户嫌贵 | **39 方法 1.3 价值导向报价** + 决策卡 7 张 + 34 轨 C ROI | 按「省多少钱」报不按工时报；McKinsey 双段 ROI 撑腰 |
| 4 | 不知道选什么技术/载体 | **25 阶段 3 载体门** + `23 交付载体怎么选` + `ECO-001` | 载体决策树 + 合规预审，别拍脑袋 |
| 5 | 开始做一个项目 | **总图主轴** → 定位阶段 → 看该段武器 | 一张图定位「我在哪、下一步交付什么」 |
| 6 | 做 POC / 试点 | **38 SOP-2 MVD** + `POC-001` + 25 阶段 4-5 | 周级节奏证明价值，别掉进「概念验证坟墓」 |

| 8 | 上线后出故障 | **38 SOP-5 热修复文化** + `REL-001` + `CRISIS-001` | 按小时计修复 + 战情室，先止血再归因 |
| 9 | 客户要续约 / 谈续约 | **`RESULT-001`** + `MLOPS-001` + 34 轨 C NDR | 持续可见指标=续约筹码 |

## 三、Agent 执行规则（给 Hermes/OpenClaw/dsh 的硬约束）

1. **顺序**：先判断「用户问的是 判断/做法/出处/灵感 哪一类」→ 再进对应线，别跨线硬答。
2. **检索入口**：`~/.hermes/scripts/growth_kb/retrieve_for_project.py --text "<需求描述>"` 拿到命中卡 → 读卡再答。
3. **出处必带**：凡引用「权威/标准/大厂做法」，必须能给出来源文件名（34/调研2）。给不出 = 降级为「实战经验」表述。
4. **不许硬编**：库里没有的领域（如无实战的行业），明确说「库里无卡，需补」——**禁止编造方法卡内容**。
5. **回填纪律**：真实项目跑完后，回填 复盘区 + 对应方法卡的「实战」段；卡越用越准。
6. **模型纪律**：批量执行任务用 MiniMax-M3（包月）；深度梳理/方向判断由 Hermes 主 agent 带完整记忆做。

## 四、维护规则

| 频率 | 动作 |
|---|---|
| 每完成一单 | 回填复盘 + 更新相关卡「实战」段 |
| 每周 | 跑 `eval_retrieval.py`（召回率）+ 看候选池 |
| 每月 | 对照总图检查：哪个阶段武器最薄 → 补卡 |
| 每季 | 重读 34 权威线，看有没有新发布的原厂/机构标准要进库 |
