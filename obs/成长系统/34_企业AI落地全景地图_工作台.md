## 〇、30 秒看懂这张图

```
业务轨 A（FDE 8 段，范冰书权威）——回答「怎么接住一个客户并做大」
 ①解决正确问题 → ②赢得客户 → ③激活部署 → ④守住续约 → ⑤扩大收入 → ⑥规模化复制
                    ↕（每个业务段内部都要走一遍工程轨）
工程轨 B（12 段，软考/SWEBOK/ISO 权威）——回答「把东西做出来的工程质量」
 Discover → Design → Architect → Data → Eval → Build → Test → Deploy → Accept → Operate → Iterate → Retire
                    ↕（贯穿两轨的质量线）
 质量横切：数据/评测（AI 特有）· 安全（OWASP）· 价值闭环（ROI/采用）
```

**专业度 = 你说出的每句话都能指到这张图上的某个位置，且那个位置有权威出处。**

## 二、轨 B：工程交付全流程（12 段，软考/SWEBOK/ISO 权威对照）

> 权威源: 软考系统架构设计师（高级）+ 软件设计师（中级）考纲 + SWEBOK V4 15 KA + ISO/IEC/IEEE 12207:2017 21 过程
> 详见 25 文档（12 阶段详细）+ dsh 调研对照表。以下只列 **缺口洞察**（dsh 对照表结论）：

| 缺口主题 | 权威说该会 | 我们的现状 | 补法 |
|---|---|---|---|
| **B-Discover 需求获取方法学** | SWEBOK KA1 Requirements 全套（获取/分析/规范/验证/管理） | 只有 M-FDE-001/requirement-clarifier，方法学薄 | 补「需求工程方法卡」（用户故事/用例/验收标准/变更管理） |
| **B-Eval AI 评测纵深** | 评测维度/评测集/基线/偏见审计 | EVAL-001/002 有雏形，缺「评测集怎么建/偏见怎么查」 | 补「AI 评测方法卡」（评测集建设 + 偏见审计） |
| **B-Iterate 反馈闭环** | SWEBOK KA8 Process + 改进 | 靠复盘区手工，缺「度量驱动改进」机制 | 补「反馈闭环卡」（用什么度量/怎么 A-B/复盘文化） |
| **B-Retire 退役合规** | ISO 12207 Asset Management + 数据删除审计 | 完全没有 | 补「退役清单卡」（数据删除审计/合同收尾/SLA 终止） |
| **AI 特有数据治理** | CRISP-ML / MLOps（软考暂无独立 KA） | 词条有 Medallion 等，方法卡缺 | 补「企业数据盘问卡」（raw→clean→ready + 数据血缘） |
| **架构治理 ADR/技术债** | 软考讲设计不讲治理 | AR-001 有 ADR 雏形 | AR-001 增强「技术债度量 + 架构漂移」 |
| **MLOps 模型运维** | 模型漂移/反馈环/ModelOps | 词条有漂移，方法卡缺 | 补「模型运维卡」（漂移检测/回滚/反馈环） |
| **传统软件工程基础** | 软考软件设计师（数据结构/OS/网络/数据库/算法） | 我们是 AI 顾问不是软件外包——**需不需要补？** 判断：接「要做软件系统」的单要懂，纯 AI 能力单不用 | 按需，不硬补（诚实标注） |
