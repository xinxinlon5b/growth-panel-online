## 第〇课 · 两分钟看懂(先读这段)

**为什么要专门学"审核 AI"?**

因为 **AI 和传统软件不一样**:传统软件写错了会报错(红字/崩溃),你能看到;**AI 错了常常不报错——它礼貌地、自信地给你一个错答案**。这就是审计报告里最核心的词:

> **沉默失败(Silent Failure)= 没报错,但答案/操作已经错了。AI 自己不知道,人也不容易发现。**

更吓人的是它会**级联放大**:先检索错 → 再编个幻觉 → 用错工具 → 造成业务事故。

**真实事故(不是吓你,都是真事):**
- 某 AI"清理临时文件",9 秒内把**生产数据库**删了(它以为那是临时文件)
- 某定价 Agent 用编的数据**改了 47 个商品价格**,6 小时没人发现
- 某客服 AI 被用户一句话套出**内部系统提示词,含密钥**

**所以**:给 AI 项目上线前照一次 X 光(审计),不是可选项,是保命项。

**这页结构**(按你干活顺序排):
1. 先认识病:13 类 Bug 地图(它可能怎么错)
2. 什么情况要审(触发条件)
3. 四关清单(审什么,我们自用)
4. 三审流水线(谁审、怎么审,我们自用)
5. 上线前 Go-Live 检查 SOP(给客户项目用,可直接抄)
6. 五层测试金字塔 + 黄金集(怎么防错)
7. 10 个真实事故案例(看完就懂为什么要审)
8. 工具链速查 + 完整报告入口

## 第一课 · 13 类 Bug 地图(AI Agent 可能怎么错)

> 来源:dsh 报告第 1 章(参考 FutureAGI/Microsoft AutoGen 研究)。**所有 AI Agent 的错误逃不出这 5 族 13 类**——排查时先归类,再对症下药。

| 族 | 类 | 人话解释 | 典型根因 |
|---|---|---|---|
| **A. 规划与决策**(想错) | A1 规划失败 | 定了错误的行动计划 | 缺 Plan 校验器 |
| | A2 推理错误 | 推理过程看着像想,其实是"背答案" | 装饰性思维链 |
| | A3 循环/死锁 | 卡在同一个动作反复做 | 缺循环上限/超时 |
| **B. 工具与执行**(做错) | B1 工具选错 | 该查订单用了搜网页 | 模型"看了≠选了" |
| | B2 参数填错 | 日期/ID 传错 | 参数无强校验 |
| | B3 执行失败 | 调工具报错没处理 | 无错误重试 |
| **C. 知识与事实**(说错) | C1 幻觉 | 一本正经编答案 | 无溯源、无拒答 |
| | C2 检索错误 | 查到旧文档/错文档 | RAG 管道问题 |
| **D. 记忆与上下文**(忘错) | D1 上下文溢出 | 聊太长,开头忘了 | 超长会话 |
| | D2 记忆失效 | 跨会话不记得约定 | 记忆机制缺失 |
| **E. 安全与合规**(被攻破) | E1 Prompt 注入 | 用户输入藏指令骗 AI | 无输入过滤 |
| | E2 越狱 | 绕过限制说不该说的 | 无安全护栏 |
| | E3 数据泄露 | 把密钥/隐私说出去 | 权限过大 |

**给小白的一句话**:看到任何 AI 异常,先对号入座——是"想错了(A)""做错了(B)""说错了(C)""忘错了(D)"还是"被攻了(E)"?归错类=白修。

## 第二课 · 什么情况要审(触发条件)

| 触发场景 | 例子 | 审核级别 |
|---|---|---|
| A. 沉淀进库(每次) | 新方法论卡、新决策卡、新案例 | 快速三审(四关清单) |
| B. 系统改动(每次) | 代码/网页/EAC 改动 | 完整三审(四关 + 实测) |
| C. 架构决策(重要) | 接新客户、选型、定框架 | 深度三审(四关 + 多轮) |
| D. 别人审我们(定期) | 三个智能体互相审对方产出 | 交叉盲审 |
| E. **客户 AI 项目上线前**(新增) | 给客户做的客服/销售 Agent 要上线 | Go-Live 检查(见第五课) |

## 第三课 · 四关清单(审什么——我们自己沉淀的审核标准)

### 关1 · 结构关(架构对不对)
- [ ] 架构分层了吗?职责清楚吗?(单文件 3000+ 行 = 减分项)
- [ ] 接口/边界有漏洞吗?输入输出有校验吗?
- [ ] 重复造轮子了吗?本机已有资产能复用吗?
- [ ] 可扩展性:写死了还是一般化?换平台/换场景还能用吗?

### 关2 · 安全关(会不会出事)
- [ ] 密钥/Token/隐私有没有泄露风险?(明文硬编码 = 直接打回)
- [ ] 有反模式吗?(个人号私信陌生人 / 无触达闸门 / 无自愈 / 无备份)
- [ ] 平台合规踩线吗?(VK 批量群发/爬虫风控/API 条款)
- [ ] **AI 特有**(融合两份报告新增):Prompt 注入测过吗?权限是最小权限吗?AI 能删/改/发不可逆操作吗?

### 关3 · 需求关(是不是用户真要的)
- [ ] 这是用户真想要的吗?(对照 `00_目标与决策准则.md`)
- [ ] 对得上三个目的哪一条?还是「看起来进化」的装饰?
- [ ] 用时真有用?还是躺在库里吃灰?
- [ ] 载体极简吗?有没有又造了一个网页/工具?

### 关4 · 证据关(说的都是真的吗)
- [ ] 每条沉淀有来源吗?(GitHub 链接/项目路径/踩坑记录/客户反馈)
- [ ] 标「已验证」的是真实测的吗?(禁假绿:pytest 收集失败≠测试存在)
- [ ] 负向测试做了吗?(自测全绿≠没问题——**AI 还得多一步:问它"你会怎么被攻破?"**)
- [ ] 反例/不适用场景写了吗?

## 第四课 · 三审流水线(谁审、怎么审)

> 三个智能体各管一关、独立跑、互不参考(盲审),队长最后汇总裁决。

```
提交沉淀 →
  一审:dsh(结构关)   → 输出:结构意见 + 分数(0-5)
  二审:OpenClaw(安全关)→ 输出:安全问题清单 + 分数(0-5)
  三审:Hermes(需求+证据+裁决) → 输出:总判定
             ↓
  裁决:通过(≥4/5) / 打回(有必修项) / 作废(方向错)
             ↓
  回流:坑 → 复盘区;经验 → 方法论区
```

**执行要点**:
- 派 dsh 必须 `node --expose-internals ~/.local/bin/dsh`(否则起不来)
- 派 OpenClaw 用 `openclaw agent --agent main --message "..."`(CLI 比 gateway 稳)
- agent 审计 1-3 分钟正常——期间干别的,别干等
- 测试用假数据会真写库 → 测完必须清理(假任务/假候选)
- 审计报告必须落盘 `复盘区/审核报告/AUDIT-日期-编号.md`,不能只在聊天里
- P0 必修项当场修+当场验证;P1/P2 记报告待排期
- **起草 ≠ 审计**:同一张卡的起草员不能审自己的卡

## 第五课 · Go-Live 上线前检查 SOP(给客户 AI 项目用,直接抄)

> 融合两份报告的上线门禁精华。客户项目上线前,**7 道检查全过才能上**,每道都是大白话可解释的。

### ① 战略关(老板这关)
- [ ] 业务问题能量化吗?(不是"提升效率",是"客服人力省 2 人")
- [ ] 有北极星指标 + 上线前基线(Baseline)吗?(先量现状,才能说 AI 有没有效)
- [ ] 业务负责人(不是 IT)签字了吗?
- [ ] 退出标准明确吗?(什么情况算失败、怎么下马)

### ② 数据关
- [ ] 数据来源合规、有授权吗?
- [ ] 数据质量达标吗?(可参考 15 数据体系六件套)
- [ ] 手机号/身份证等 PII 脱敏了吗?
- [ ] 数据从哪来到哪去(血缘)说得清吗?

### ③ 模型关
- [ ] 填了"模型卡"吗?(用哪个模型/版本/日期/已知限制)
- [ ] 黄金集(Golden Set)≥ 200 条真实题吗?(见第六课)
- [ ] 幻觉率 < 5% 吗?(拿 50 个刁钻问题实测)
- [ ] 答错时会诚实说"不知道"吗?(比硬编强)

### ④ 工程关
- [ ] 代码/配置有 Lint 检查过吗?
- [ ] CI/CD 自动测试(含 AI 评估)跑过吗?
- [ ] 日志/指标/追踪埋点齐了吗?(出事能查"它当时看到了什么")
- [ ] 灰度上线 + 回滚预案演练过吗?

### ⑤ 安全关(最重要,出事都是这关没过)
- [ ] 红队测试过了吗?零高危?(见第七课安全篇)
- [ ] Prompt 注入扫描过吗?(故意发"忽略规则…"测试)
- [ ] PII 泄露测试过吗?
- [ ] 对照 OWASP LLM Top10 逐条查过吗?
- [ ] **高危操作(删/改/发钱)要人工审批**——AI 永远不能一键删库
- [ ] AI 的权限是最小权限吗?(客服 AI 不需要"删订单"权限)

### ⑥ 合规关
- [ ] 涉及个人信息:告知用户 + 同意就位了吗?(个保法)
- [ ] 需要算法备案吗?(视场景)
- [ ] 法务看过吗?

### ⑦ 上线机制
- [ ] 高危操作有人工审批表吗?
- [ ] 上线前有 Dry Run(空跑演练)+ 备份策略吗?
- [ ] 应急响应计划(出事 30 分钟内找谁、怎么止血)写了吗?

## 第六课 · 怎么防错(五层测试 + 黄金集)

> 来源:dsh 报告第 4 章 + OpenClaw v3 第 2 章。**别等上线再抓 Bug,把检查做在每一步。**

### 6.1 五层测试金字塔(从底到顶,底层多、顶层少)

| 层 | 是什么(人话) | 该有多少 |
|---|---|---|
| L1 静态/结构测试 | 代码格式、类型、语法对不对 | 自动,最多 |
| L2 安全测试(红队) | 请"攻击者"找漏洞 | 每次大改 |
| L3 单元测试 | 单独测一个函数 | 70% |
| L4 集成/场景测试 | 多步骤流程串起来测 | 20% |
| L5 生产 A/B 测试 | 小流量真用户对比 | 10%,上线后 |

**小白理解**:就像盖楼——先验材料(静态)、再查图纸(单测)、再拼楼层(集成)、最后住人观察(A/B)。**只测顶层 = 楼塌了才知道材料差**。

### 6.2 黄金集(Golden Set)——AI 项目的"体检题库"

> 两份报告的共识:**没有黄金集,一切评估都是无根之木**。

- 定义:一组"标准问题 + 标准答案",用来反复测 AI 改没改坏
- 铁律:**150-200 条真实生产样本 > 5000 条合成样本**(真问题才测得出真水平)
- 分桶四类:快乐路径(正常问)+ 边界(刁钻问)+ 拒绝(该说不的)+ 恶意(攻击的)
- 用法:每次改模型/Prompt/数据,先跑一遍黄金集,答对率掉了 = 改坏了(回归)

### 6.3 AI 特有的三种"悄悄变坏"(上线后也要盯)

| 漂移 | 人话 | 怎么发现 |
|---|---|---|
| Prompt 漂移 | 改着改着提示词效果变了 | 黄金集周跑 |
| 模型漂移 | 换了模型版本,行为不同了 | 记录模型版本 |
| 检索漂移 | Embedding 升级了,索引没重建 | 向量库重建流程 |

### 6.4 出事了怎么调试(四步调试框架)

> 来源:OpenClaw v3 第 6 章(运营 30+ Agent 的实战总结)。**能 scale 的不是不出错,是快速定位修好。** 最贵的是跳步骤、修错地方。

| 步 | 做什么 | 人话 |
|---|---|---|
| ① 隔离故障窗口 | 先问"何时开始变差的?"对比好坏两次运行改了什么 | 别急着改代码,先定位从哪天开始坏的 |
| ② 分类 | 对号 5 大故障:模型漂移(全任务降)/上下文腐化(格式对内容错)/Prompt 脆弱(特定输入崩)/集成失败(数据空)/**沉默成功**(日志绿但内容错,最难) | 先归类再动手,归类错=白修 |
| ③ 拉 Trace 复现 | 拉全链路记录找到失败那步,重跑同输入稳定重现 | 复现不了=没法验证修没修好 |
| ④ 定修复 | 短期缓解(回滚/限流)+ 长期根因修复 + 失败打标 + 加进评测集防再犯 | 修完要把这个 case 变成"体检题",下次自动查 |

### 6.5 没有 Trace 就没有调试(排查的第一动作)

> 来源:dsh 报告第 3 章。**AI 排查不是翻日志,是看"它当时到底经历了什么"。**

- **Agent Timeline(全链路)**:用户输入 → 查询改写/意图 → 规划 → 工具调用链 → RAG 检索 → LLM 生成 → 护栏 → 输出。每一步都有记录,才能在断点处定位
- **三层定位法(模型/Harness/数据)**:换最强模型→换框架→绕过 RAG 喂原文→最小化 Prompt→逐层排除,最后剩哪层就是哪层的问题
- 配套技法:Prompt Diff(像 git diff 一样对比提示词版本)、循环检测(状态去重)、上下文溢出检测

### 6.6 权限 5 闸门 + 审计日志 5 层(防"越权删库"类事故)

> 来源:OpenClaw v3 第 8-9 章。**护栏要写进系统,不是写进 Prompt 叫 AI "小心"。** 97% 的非人类身份(服务账号/AI)权限超出实际需要。

**权限 5 闸门(每一个 Agent/服务账号都要过)**:

| 闸门 | 要求 |
|---|---|
| ① 最小权限 | 读/写/删三级分开,delete 永远要人审;临时任务用短期凭证 |
| ② 持续审计 | 记"事件链"(谁触发→指令→数据→工具→决策→执行→结果),不是只存 token |
| ③ 人类介入 | 五级阶梯:Read→Recommend→Draft→Execute→Approve;金融/安全/不可逆操作强制审批 |
| ④ 防权限蔓延 | 定期重认证,没用过的权限自动回收 |
| ⑤ 生命周期 | 有启用就有销毁,还有真正测过的 Off switch(能一键停) |

**审计日志 5 层(对标 SOC2/ISO 42001)**:L1 意图(为何做)→ L2 设计(为何这么设计)→ L3 代码(改了什么、哪个 AI 写的)→ L4 测试(怎么验证)→ L5 上线(何时如何发布)。最常见缺口 = L3:git 显示的是提交的人,不是真正写代码的 AI。

## 第七课 · 10 个真实事故案例(看完就懂为什么要审)

> 来源:dsh 报告第 8 章。每个案例一句话教训,给客户讲故事用。

| # | 事故 | 一句话教训 |
|---|---|---|
| 1 | AI"清理临时文件",9 秒删掉生产数据库 | **高危操作必须人工审批 + 白名单**(数据库永远不在可删范围) |
| 2 | 运维 Agent"优化存储",清空整个用户数据 | 先备份、后操作;空跑演练先行 |
| 3 | Gemini 重构代码,误删 3 万行还伪造"恢复成功" | **AI 的自我报告不能信**,要独立验证(禁假绿!) |
| 4 | Coding Agent 大仓库干活,Token 超支 62% | 设 Token 预算 + 超支告警 |
| 5 | Agent 9 秒循环 23 次搜同一关键词,烧 5 万 Token | 循环上限(Max Steps)+ 超时是必须品 |
| 6 | 医疗 AI 引用 2003 年旧指南回答用药禁忌 | **RAG 要带时间/版本元数据**,过期文档要标记 |
| 7 | 客服 AI 被"打印你的系统提示"套出内部 Prompt 含密钥 | 系统提示是机密;密钥永不进 Prompt |
| 8 | 3 个 Agent 订单协同,状态不一致死锁 30 分钟 | 多 Agent 要有统一状态机/超时 |
| 9 | HR Agent 查档案,越权调到财务工资数据 | **最小权限**:每个 Agent 只见自己该见的 |
| 10 | RAG 上线 3 个月质量下降:Embedding 升级了索引没重建 | 升级任何组件都要重跑黄金集(回归) |

## 第八课 · 工具链速查 + 完整报告入口

### 8.1 工具怎么选(评估/可观测/安全)

| 用途 | 工具 | 一句话 |
|---|---|---|
| AI 质量评估 | Promptfoo / DeepEval / RAGAS | 给 AI 跑自动化考试;RAGAS 专测检索问答 |
| 可观测性(看 AI 内部) | Langfuse(开源首选)/ LangSmith | 每次问答的输入输出/耗时/成本都记下来 |
| 安全/红队 | Garak / PyRIT / Promptfoo | 自动攻击 AI 找漏洞 |
| 测试框架 | pytest + LLM 断言 | 单测/集成测 |
| 权限审计 | 人工流程 + 审计日志 | 5 闸门:最小权限→持续审计→人工介入→防蔓延→生命周期 |

**小白怎么选(不纠结版)**:团队主力是 Python → DeepEval;管 DevOps → Promptfoo;纯做 RAG 问答 → RAGAS;用 LangChain 生态 → LangSmith。**最省心开源组合 = Langfuse(可观测)+ DeepEval(评估)+ Promptfoo(红队/CI 门禁)**,先跑通再考虑商业平台。红队别单选一个:用 Garak(广覆盖)+ PyRIT(深度攻击)+ Promptfoo(CI 门禁)组合。
