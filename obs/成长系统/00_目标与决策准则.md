# 成长系统 · 目标与决策准则（每次决策前读这一份）

> 创建：2026-09-03 | 状态：v1.0（用户确认版）
> 用途：文件系统/代码/网页/审核的任何决策，动手前先对照本文件。凡与本文件冲突的动作，视为跑偏，先停下来对齐。

## 一、一句话目标

做一件**只给我自己用**的「成长系统」：一个 agent（Hermes 智能体）+ 一个网页（镜子）。
它同时是我的知识库、成长库、经验库——帮我服务企业 AI 客户时，**框架从第一天就是对的**。

## 二、三个目的（每次决策都要对号入座）

| # | 目的 | 库里对应区 | 检验标准 |
|---|---|---|---|
| ① | 把框架做对（方法论） | 方法论区 | 接到新场景，第一版架构能跑 3 个月不改 |
| ② | 学企业AI落地的经验案例 | 案例区 | 类似场景，库里翻得出「别人怎么做的」 |
| ③ | 沉淀自己的实战/坑 | 复盘区 | 类似项目能复制、不重踩坑 |

## 三、铁律（违反任何一条 = 立刻停下重想）

1. **载体极简**：只有一个 agent + 一个网页。多一个网页/工具都是负担，禁止新增。
2. **结构先对，不再修补错误结构**：结构想透再动手；发现结构错了就重定，不在歪骨架上打补丁。
3. **真正好用，不是看起来进化**：飞轮必须真转（agent 真学、库真长、用时真有用）。网页上的数字如果是假的，不如不显示。
4. **网页是镜子，不是产品**：不思考、不进化、不接 API、不装智能；智能全在 agent 侧。
5. **任何功能都要有具体方法论和流程**：没有流程的功能不做。
6. **审核是固定环节**：重要沉淀进库前必须过三审（dsh 结构 / OpenClaw 安全 / Hermes 总审），审核结果回流复盘区。
7. **诚实可追溯（禁假绿）**：标「已验证」必须真实测；每条沉淀必须有来源（链接/路径/坑记录）。
8. **私人库**：只给用户自己用，与客户展示无关，不脱敏要求不出库（公开页只放结论）。

## 四、系统架构（v1.0）

```
输入层：你丢碎片 / 抖音 / GitHub / 官方文档 / 项目复盘
   ↓
提炼层：Hermes agent 采集→结构化→分类（三区）
   ↓
审核层：三审流水线
   一审 dsh（结构）→ 二审 OpenClaw（安全）→ 三审 Hermes（总审+对照本文件）
   结果 → 审核报告 → 通过/打回/作废
   ↓
记忆层：EAC 证据库（真相源）+ Obsidian 三区
   ↓
展示层：一个网页（只读镜子）
```

## 五、审核标准清单（沉淀进库前四关）

```
【一】结构关（dsh 主审）
 □ 架构分层了吗？职责清楚吗？边界有漏洞吗？
 □ 重复造轮子吗？已有资产能用吗？能扩展吗？
【二】安全关（OpenClaw 主审）
 □ 密钥/隐私泄露风险？输入输出校验？平台合规踩线？
 □ 有反模式吗（无闸门/无自愈/高危操作）？
【三】需求关（Hermes 总审）
 □ 这是用户真想要的吗？对得上三个目的吗？
 □ 用时真有用？还是躺着吃灰？
【四】证据关（三家都要）
 □ 每条沉淀有来源吗？标已验证的是真实测吗？
```

## 六、三审分工

| 角色 | 审什么 | 借用已有能力 |
|---|---|---|
| dsh | 结构/代码/bug/架构漂移 | awesome-architecture-audit, awesome-bug-fix, awesome-code-review, engineering-audit |
| OpenClaw | 安全/反模式/逻辑矛盾 | skill-security-audit, security-vuln-scanner, code-review-sr, qa-bug-root-cause-analysis |
| Hermes（队长） | 总审/对齐目标/裁决 | arch-code-review, live-system-audit, codex-gate-acceptance, daemon-audit-hardening |
