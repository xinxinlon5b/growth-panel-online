## 三、功能缺口详解（重点看这块）

### 🔴 P0（地基，不补则上层全塌）

**缺口1 · 三区 schema 未定稿**
- 现状：02 文档有草案，等你过目
- 影响：schema 不定，采集/检索/展示都无结构可依
- 决策：你说「行」或改字段 —— 一次定死，不再反复

**缺口2 · 生命周期四态**
- 现状：卡片只有「正式」；候选池刚建但无状态机
- 要补：每条沉淀带 `候选→正式→过期→废弃`，候选不进正式检索，废弃有原因
- 借鉴：EAC 引擎已有不可变+撤销机制，Obsidian 侧补齐即可

**缺口3 · EAC ↔ 存储/网页 未接通**
- 现状：EAC 是自己跑的应用（8765），Obsidian 是另一个库，网页是第三个地方——三个岛
- 要补：定「真相源唯一」：EAC 管证据/检索，Obsidian 管三区沉淀，网页只读 index.json；同步脚本负责搬运
- 影响：不接通，「飞轮真转」永远只是口号

**缺口4 · 审核执行层未跑通**
- 现状：标准写好了，但没真审过任何东西
- 要补：拿第一份真实沉淀（比如刚建的「成长系统」本身）跑一次三审，产出第一份审核报告 → 流程才叫真活

### 🟡 P1（跑起来后自然遇到）

- **采集接通**：抖音账号订阅清单 + 增量逻辑 + 手动丢；GitHub 手动触发
- **网页收拾**：清乱码、定唯一入口（companion.html）、数据源改 index.json
- **黄金集接通**：新沉淀入库时自动跑评测（参考 EAC 的 124/124）
- **沙箱Gate制度化**：交付前真机实测、负向测试变审核清单硬项

### 🟢 P2（有富余再做）

- 把三个 agent 的 15+ 审核 skills + GitHub 上的 mantis/RepoAudit 整理成统一调用手册
- 抖音账号订阅的「知识结构」深化（同一博主多期内容自动织成专题）
