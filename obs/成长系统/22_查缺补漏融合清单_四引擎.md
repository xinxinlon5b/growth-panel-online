## P1 · 引擎之间的"管线"（把4个引擎串成工作流）

用户从备忘录→工具的关键是: 录入项目(E3输入) → 载体决策(E1) → 零件装配(E2) → 生成方案卡(架构+载体+零件+理由+报价) → 存Obsidian → 按关卡地图推进 → 复盘回填。这需要:
- 项目方案模板（输出长啥样: 决策卡+装配结果+载体建议+风险+报价 合并渲染）
- 每张零件卡的「触发条件」字段补齐（E2 数据基础, 51卡逐一补 triggers）
- 术语↔零件卡↔关卡 三向互链（现有词条↔视频, 扩到卡和关卡）

## P2 · 内容级补全（双 agent 额外盲区, 去重合并）

1. **真实项目解剖室**: 3 个高星项目(Dify/FastGPT/Supabase/Cal.com)的完整零件剖面图 — B卷 A.4 已有初稿, 可精化进网页
2. **反模式库**: 公开失败复盘+「不要这样做, 因为...」, 与决策卡联动（现在有可复制打法 r3, 缺反面）— B卷补充
3. **ROI/价值闭环仪表盘**: AI 项目专属结果指标(节省工时/采纳率/GMV), 回流案例库 — A卷补充
4. **报价参考库**: 按场景/规模/复杂度的报价数据库, LLM 报价有依据 — B卷补充（用户决策卡已有价格档, 扩成数据库）
5. **客户旅程×决策点矩阵**: 决策卡按客户旅程(接触→签单→交付→续约→规模化)重新编排 — B卷补充
6. **载体速查/常见反模式**: 载体选型时的坑(如 STARTER 别上容器) — A卷补充

## P3 · 落地顺序建议（结合我们小团队实际）

参考 dsh B.6, 调整为:
- **W1**: E4 工程全景地图(内容+注册 tab) + E2 零件触发条件补全(数据层) —— 先让「看得见」
- **W2-W3**: E1 载体决策树(做成问答或速查表挂技术选型关) + E2 装配问卷 v1(纯 JS 规则)
- **W4-W6**: E3 v2: 项目录入表单 + 问卷输出「方案卡」(架构+载体+零件+理由) —— 不接 LLM 也能用
- **W7+**: E3 v3 接 LLM(M3) + 反馈闭环 → 黄金集评测
- MVP 建议: 先 E4(全景地图, 内容快) + E1+E2 合并成「项目体检/装配向导」(一个交互工具同时回答载体+零件), 用户立刻感到「网页会给我方案了」

## 交付物定位建议（用户核心诉求: 网页别再是备忘录）

最终形态设想: 网页新增一个「🧭 方案工厂 / 项目装配」入口:
1. 填项目信息（10 个结构化问题: 客户/业务/数据/规模/预算/IT能力/合规）
2. 网页即时给出: 推荐载体 + 必装零件清单(9维, 每个可点开看为什么) + 对应关卡位置 + 报价档位参考
3. 一键存 Obsidian 生成《项目方案卡》+ ADR 草稿
4. 后续推进时按方案卡打勾(装配了哪些零件), 复盘时回填反模式
—— 这一步做完, 网页就从「字典」变成「开工前的总工程师」。
