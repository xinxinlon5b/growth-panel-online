# 📦 客户电脑远程装机手册（Hermes 桌面版 + AI 智能体交付包）

> 小白也能照着做。给一台新客户电脑（Mac 或 Windows）远程装：
> **① 你的 AI 应用/智能体**（交付包，例如 AI 商品图工作室、获客系统、客服机器人……你交付什么就装什么）
> **② Hermes 桌面版**（AI 运维助手，装好后客户对它说人话就能改应用/修问题）
>
> 本手册**不绑定任何具体产品**——凡是「交付包 + 安装脚本 + 客户自己的账号」模式的远程装机都适用。
> 2026-09-07 已在首台客户 MacBook Pro 全程实测跑通。
>
> 📌 **读法**：先看「0. 角色分工」→「1. 开工前要 3 样东西」→「2. 基本概念」，
> 再按客户机系统进 🍎 Mac 流程 或 🪟 Windows 流程。每一步都写了：谁做、在哪做、需要什么、看到什么算成功、卡住怎么办。

## 0. 角色分工：谁做什么

这场装机有**两个人、两台电脑、两种终端**，先分清：

| 角色 | 是谁 | 在哪操作 |
|---|---|---|
| **安装方（你）** | 远程操控的人 | 你自己电脑上的「终端」|
| **客户（对方）** | 电脑主人，坐在客户机前 | 客户机上的「终端」或「PowerShell」|

**客户只需要配合 4 件事**（其他全是你远程做）：
1. 在自己电脑装 Tailscale 并登录同一个账号（约 3 分钟）
2. 在自己电脑打开「终端/PowerShell」，把你要他粘的命令粘进去回车
3. 输**他自己的开机密码**（仅装系统组件那几步要授权）
4. 最后填**他自己的**平台账号 key

**全程 8 大步**：
```
① 组网(Tailscale) → ② 打通远程(开远程登录+放钥匙) → ③ 预检环境
→ ④ 传安装包+装应用 → ⑤ 装 Hermes 桌面版 → ⑥ 配账号(客户自己的)
→ ⑦ 验收 → ⑧ 客户现场激活
```

## 1. 准备工作：开工前先跟客户要 3 样东西

**动手前先问清、先要到，别装到一半才发现缺**：

| # | 要什么 | 为什么 | 怎么拿 |
|---|---|---|---|
| 1 | **客户机是什么系统？** | 决定走 Mac 流程还是 Windows 流程 | 直接问客户（设置→关于本机/系统）|

**下载地址（发给客户，让他先装 Tailscale）**
- Tailscale（Mac/Win 通用，国内可直连）：https://tailscale.com/download
- Python（仅 Mac 特殊情况用）：https://www.python.org/downloads/

## 2. 基本概念：终端 / SSH 命令 / 开机密码（小白必读）

### 「终端」是什么、怎么打开

「终端 / PowerShell」是一个能**打字命令让电脑干活**的黑窗口。所有代码都在里面粘。

| 系统 | 叫什么 | 怎么打开 |
|---|---|---|
| 安装方（你的 Mac）| **终端 Terminal** | 按 `⌘ + 空格` → 输入 `Terminal` → 回车 |
| 客户机 Mac | **终端 Terminal** | 按 `⌘ + 空格` → 输入 `Terminal` → 回车 |
| 客户机 Windows | **PowerShell** | 开始菜单 → 输入 `PowerShell` → 回车 |

打开后窗口里每行开头有 `你的用户名@电脑名` —— 这就是**客户机用户名**的线索（见下）。

**用法**：把命令整段复制 → 粘贴进窗口 → 按回车 → 看输出结果。

### SSH 命令怎么读（拆开看就不怕了）

后面 Mac 流程的命令长这样：
```bash
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@客户机IP "要执行的命令"
```
逐段拆解：
| 片段 | 意思 | 换成什么 |
|---|---|---|
| `ssh` | 远程登录工具 | 不变 |
| `-i ~/.ssh/…install` | 用哪把「钥匙」登录 | 不变（M3 生成的）|
| `用户名@客户机IP` | 登录哪个用户、哪台机器 | `用户名` = 客户机 `whoami` 的结果；`客户机IP` = Tailscale 里看到的 `100.x.x.x` |
| `"…"` | 在客户机上要执行的事 | 按步骤给 |

> 📌 全文所有命令里的 `用户名@IP` 都是**占位符**，每次要换成你那台客户机的实际值。第一次操作前把这两个值记在纸上：`用户名=______`、`IP=100.___.___.___`。

### 客户机用户名在哪拿

**Mac**：让客户打开终端，输入 `whoami` 回车，把结果发你（例如 `wzm`）。
**Windows**：让客户打开 PowerShell，输入 `whoami` 回车，取**反斜杠后面**那段（例如 `pc01\wang` → 用户名是 `wang`）。
终端提示符开头 `wzm@xxx` 的 `wzm` 也是用户名，对得上就行。

### 开机密码什么时候用

- 只有**装系统级组件**那几步要用：`echo '开机密码' | sudo -S …`（Mac 的 M2/M4/M7，Windows 的 W2 管理员窗口）
- 密码**只在安装时用一次**，不落盘、不写文档；全部装完提醒客户「可以改开机密码了」

# 🍎 Mac 客户机安装流程

> 客户机示例：MacBook Pro M 芯片 / macOS 26。所有「安装方操作」在你自己电脑终端跑，「客户操作」让客户在对方电脑点。

## M1. 组网：确认客户 Tailscale 已入网 + 记下客户机 IP

**客户操作**（对方电脑）：
1. 打开 https://tailscale.com/download 下载安装 Tailscale
2. 打开 Tailscale 应用 → 登录**同一个账号**（可扫码/邮箱，国内直连）
3. 登录成功后，菜单栏出现 Tailscale 图标 = 入网成功

**安装方操作**（自己电脑终端）：
```bash
tailscale status
# 应看到客户机的名字和 100.x.x.x 的虚拟 IP，例如：
# xxx-macbook  100.111.236.60  macOS  -   online
```
把客户的 `100.x.x.x` **记下来**——后面所有 `用户名@IP` 里的 IP 就是它。

> ✅ 看到 `online` = 组网成功，进 M2。
> 💡 特殊：如果客户登录 Google 账号被卡，用「**设备代码授权法**」——让客户终端跑 `tailscale login`，
> 会显示一个 `https://login.tailscale.com/a/xxxx` 链接，把链接发你，**你在自己浏览器打开授权**，
> 客户机自动入网，客户全程不用碰 Google。

## M2. 打通远程第一步：让客户开「远程登录」（第一次用开机密码）

**客户操作**（对方电脑，打开「终端」→ 粘下面命令 → 回车）：
```bash
sudo systemsetup -setremotelogin on
```
- 回车后会要密码 → **输客户自己的开机密码**（屏幕上不显示是正常的，直接打回车）
- 看到 `setremotelogin:on` 或没报错 = 成功

> ⚠️ 客户说「不知道终端在哪」→ 看「2. 基本概念」的打开方法。
> ⚠️ 报 `command not found` = 粘贴时头尾带空格了，重粘。
> ⚠️ 报 `you need to be root` = 密码输错或不是管理员，重试。

## M3. 打通远程第二步：生成钥匙 + 放公钥（以后免密）

**安装方操作**（自己电脑终端，一次性）：
```bash
# 1) 生成一对钥匙（如果 ~/.ssh/id_ed25519_altai_install 已存在就跳过）
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_altai_install -N ""

# 2) 显示「公钥」整串，复制它（ssh-开头一整串）
cat ~/.ssh/id_ed25519_altai_install.pub
```

**客户操作**（对方终端）：把下面命令里的 `【粘贴公钥整串】` 换成你发他的那串，粘进去回车：
```bash
mkdir -p ~/.ssh && echo "【粘贴公钥整串】" >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
```

**安装方验证**（能连上 = 打通）：
```bash
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@客户机IP "echo hi"
```
- 第一次连会问 `Are you sure you want to continue connecting (yes/no)?` → 输 `yes` 回车
- 返回 `hi` = ✅ 打通，后面所有步骤你直接远程做，不再麻烦客户

> ⚠️ 特殊情况：
> - `Connection refused` = 远程登录没开 → 回去跑 M2 那条命令
> - `Permission denied` = 公钥没放对 → 检查客户机 `~/.ssh/authorized_keys` 内容（`cat ~/.ssh/authorized_keys`）
> - 用户名不对 → 用客户 `whoami` 的真实输出

## M4. 环境预检（全新 Mac 必查 3 件事）

**安装方一条命令查全**（换成你的用户名@IP）：
```bash
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP \
  "/usr/bin/python3 --version; df -h / | tail -1; curl -sI --max-time 8 https://pypi.tuna.tsinghua.edu.cn | head -1"
```

| 检查项 | 正常 | 不正常怎么办 |
|---|---|---|
| Python | `Python 3.9.x` | 全新 Mac 的 `/usr/bin/python3` 是假的（点了会提示装 Xcode），先装 **Command Line Tools**：`echo '客户开机密码' \| sudo -S xcode-select --install`，等 5-15 分钟装完再看（这就是要开机密码的原因）|
| 磁盘 | 有几十 GB 可用 | 空间不够先清理 |
| 清华源 | HTTP 200 | 国内网络 pypi.org 直连会超时（10 秒断），**必须走清华源**才装得快 |

**国内网络必配清华源**（否则装 Python 依赖会卡死）：
```bash
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP \
  "mkdir -p ~/.pip && printf '[global]\nindex-url = https://pypi.tuna.tsinghua.edu.cn/simple\n' > ~/.pip/pip.conf"
```

> ✅ 3 项都正常 = 环境 OK，进 M5。

## M5. 起进度面板（让客户全程看到装到哪）

客户看不到你 SSH 在黑屏操作，会以为卡死。所以**先起一个网页进度面板**，客户浏览器打开实时看。
（你的交付包若自带进度面板组件，直接用；没有就自己写一个 20 行的 http.server + 进度 JSON。）

**安装方操作**：
```bash
# 1) 把进度面板程序传到客户机（交付包里有 install_progress/ 目录）
scp -i ~/.ssh/id_ed25519_altai_install -r 交付包/install_progress 用户名@IP:~/app_install/install_progress/

# 2) 在客户机后台启动进度服务（端口 8896）
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP \
  "cd ~/app_install/install_progress && nohup python3 progress_server.py > server.log 2>&1 & sleep 2; curl -s http://127.0.0.1:8896/api/health"
# 返回 {"ok":true} = 服务起来了
```

**客户操作**：对方电脑浏览器打开 `http://127.0.0.1:8896/` → 看到进度面板（安装方每动一步，数字就跳）

> 💡 方法：进度面板数字只在「每步完成」时跳，遇到下载大文件（几百 MB）中间会看着像卡住。
> 解决：**心跳监控**——后台每 10 秒把「下载缓存涨到多少 M」写进面板描述，客户看到数字一直涨 = 知道没卡。

## M6. 传交付包 + 装应用主体

**安装方操作**：
```bash
# 1) 传交付包（100-300MB，Tailscale 内网约 40 秒）
scp -i ~/.ssh/id_ed25519_altai_install ~/Downloads/XX系统_交付包_20260907.zip 用户名@IP:~/Downloads/

# 2) 客户机解压
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP \
  "cd ~/Downloads && unzip -o XX系统_交付包_20260907.zip -d ~/app_install"

# 3) 后台跑安装脚本（你的交付包自带，步骤数因产品而异：拷贝应用→环境→模型→自启→启动器→验证…）
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP \
  "cd ~/app_install/delivery && nohup bash app/install.sh > /tmp/app_install.log 2>&1 & echo 启动PID: $!"
```

**等装完**（进度面板全程实时显示，装完显示 100% 完成）。

**安装方验证服务健康**（端口以你的应用为准，示例 8901）：
```bash
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP "curl -s http://127.0.0.1:8901/api/health"
# 返回 {"ok":true,...} = 主体装好
```

> ⚠️ 特殊情况：装到「Python 环境」步卡很久不动——那是 pip 在下载大头依赖（几百 MB），
> 不是死了。看 `ps aux | grep install.sh` 进程在不在，心跳面板数字涨不涨。清华源配好就不会真卡。

## M7. 装 Hermes 桌面版（关键！要桌面版不是 CLI）

> 🔴 最容易被坑的一步：很多安装脚本内置的 Hermes 安装器装的是 **CLI 核心**（黑窗口能敲命令，
> 但没有图形界面）。客户要的是 **Hermes.app 桌面版**（Dock 里能双击）。**装错会被客户骂**。
> 正确做法 = 直接搬你自己电脑上装好的成品（**两台都是苹果芯片**才能这样）：

**安装方操作**（同架构 arm64→arm64 直接搬）：
```bash
# 1) 自己电脑打包 Hermes.app（307MB 压成 ~130MB；只打程序，不含你的隐私数据）
tar -czf /tmp/hermes_app.tar.gz -C /Applications Hermes.app

# 2) 传过去（130MB，约 35 秒）
scp -i ~/.ssh/id_ed25519_altai_install /tmp/hermes_app.tar.gz 用户名@IP:~/Downloads/

# 3) 客户机解压安装 + 去掉系统拦截标记 + 启动（要开机密码）
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP \
  "cd /tmp && tar -xzf ~/Downloads/hermes_app.tar.gz && \
   echo '客户开机密码' | sudo -S rm -rf /Applications/Hermes.app && \
   echo '客户开机密码' | sudo -S mv /tmp/Hermes.app /Applications/ && \
   echo '客户开机密码' | sudo -S xattr -dr com.apple.quarantine /Applications/Hermes.app && \
   open /Applications/Hermes.app"
```

**验证（查 .app 在不在 + 进程在不在，不是敲 hermes 命令）**：
```bash
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP \
  "ls -d /Applications/Hermes.app && ps aux | grep '[H]ermes.app/Contents/MacOS/Hermes' | head -1"
# 有路径 + 有进程 = 桌面版装好了
```

> 💡 为什么这么快：这是「**搬运成品**」——把自己电脑验证过能用的 Hermes 整个打包传过去解压，
> 比客户机现场跑官方安装器（下载源码→编译→装依赖，10-30 分钟还可能卡 GitHub）快 10 倍。
> 原理：同芯片架构的程序可以直接复制运行，不用重新编译。
> ⚠️ 客户机是 **Intel 芯片**就不能这么搬（架构不同跑不了），只能官网下载或走官方安装器（会弹 GUI 一步步点，需要客户配合屏幕操作）。

> 💡 隐私安全：打包只含 `/Applications/Hermes.app` 程序本体，你电脑 `~/.hermes` 里的
> API Key/聊天记录/记忆**一个字节都不会进包**。客户拿到的是干净软件，自己填自己的 key。

> 🔑 Hermes 桌面版和 CLI 共用同一个数据目录 `~/.hermes`：如果之前误跑了 CLI 安装器，
> 放进去的 skills/插件**不会白装**——桌面版一启动自动全部读到（日志见
> `Plugin discovery complete: 61 found, 55 enabled`）。先安抚客户：没白装。

## M8. 补 PATH + 启用插件（如果之前跑过 CLI 安装）

**安装方操作**：
```bash
# 1) 确保 hermes 命令能用（SSH 黑窗口不自动加载配置文件）
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP \
  "echo 'export PATH=\"\$HOME/.hermes/bin:\$PATH\"' >> ~/.zshrc; \
   ls ~/.hermes/bin/hermes 2>/dev/null || echo '#!/bin/bash
exec ~/.hermes/hermes-agent/venv/bin/python ~/.hermes/hermes-agent/hermes \"\$@\"' | tee ~/.hermes/bin/hermes >/dev/null && chmod +x ~/.hermes/bin/hermes"

# 2) 启用交付包自带的服务端插件（如有，逐个 enable）
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP \
  "~/.hermes/bin/hermes plugins enable api-balance session-timer completion-dashboard context-meter"
```

**重启 Hermes 让插件生效**（杀进程重开，等 30 秒）：
```bash
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP \
  "pkill -f 'Hermes.app' ; sleep 3; open /Applications/Hermes.app; sleep 30; \
   tail -30 ~/.hermes/logs/agent.log | grep -E 'Mounted plugin|Plugin discovery'"
# 看到 Mounted plugin API routes: /api/plugins/xxx/ 等 = 生效
```

## M9. 配账号（全部客户自己的！）

**通用原则**：客户的应用要用什么 AI 平台/API，就让客户自己注册、自己填 key。
安装方只备好填写位置和格式，**绝不代填自己的 key**（填了客户的机器就绑了你的账号，出事说不清）。

以「AI 出图应用 + Hermes 对话」为例的常见账号：
- **AI 生图平台**（如火山引擎/即梦/其他）→ 客户实名 + 充值 + 创建 API Key → 填进应用设置
- **DeepSeek**（Hermes 对话用）→ 客户注册 https://platform.deepseek.com 充值 → 创建 API Key（sk- 开头）→ 填进 Hermes 设置
- 其他产品按需（客户有什么平台的账号就用什么）

**具体怎么填看你的应用文档。填完重启应用服务让配置生效。**

> 🔴 平台 Key 的通用教训（实测踩过）：
> - **同平台可能有两种 Key 格式**：旧格式可能只能查列表、**不能真正调用**（一调就 AuthenticationError）。
>   拿到 key **第一时间直接测「真实调用接口」**（如生成一张图），别只测「列表能不能查」。
> - **两个不同的功能可能要用不同凭据**：例如「出图用 API Key、看余额用另一对 AccessKey/SecretKey」。
>   先搞清楚你的应用要哪几个，别填错位。
> - 客户注册平台时下载的密钥文件常留在 `~/Downloads/`，先搜它（如 `cat ~/Downloads/AccessKey.txt`），
>   不用让客户重新创建。

## M10. 验收清单（装完逐项过）

**通用验收项**（以你的应用为准调整）：
```bash
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@IP "
echo '== 1 应用服务 ==';  curl -s http://127.0.0.1:8901/api/health
echo; echo '== 2 应用 App ==';  ls /Applications/ | grep -iE '你的应用|Hermes'
echo '== 3 开机自启 ==';  launchctl list | grep 你的服务名
echo '== 4 skills ==';  ls ~/.hermes/skills/ | wc -l
echo '== 5 插件 ==';  ~/.hermes/bin/hermes plugins list 2>/dev/null | grep -E 'enabled|api-balance'
"
```

| # | 查什么 | 正常 |
|---|---|---|
| 1 | 应用服务健康 | `{"ok":true,...}` |
| 2 | 应用 App + Hermes.app | 都在 /Applications |
| 3 | 开机自启 | launchctl 有你的服务 |
| 4 | Hermes skills | ≥20 类（含你交付包的业务 skill）|
| 5 | 插件 | 你交付的插件都 enabled |

**客户最后操作**：
1. 打开你的应用（浏览器/App）→ 确认 AI 账号已连 → 实测一次核心功能（如生成一张图）
2. 打开 Hermes → 确认能对话 → 说一句你的业务指令（如「帮我看看 XX」）测试它认识你的应用
3. 应用的管理员/默认密码 → 建议客户登录后改掉
4. **如果装的过程中用过开机密码 → 提醒客户可以改开机密码了**

# 🪟 Windows 客户机安装流程

> 核心 7 步，与 Mac 不同处：远程通道用 PowerShell、Hermes 数据目录不同、GitHub 被墙需镜像。

## W1. 组网：Tailscale（同 Mac 的 M1）

**客户操作**：下载安装 Tailscale Windows 版 → 登录同一账号 → 看到 100.x 图标 = 入网。
登录卡 Google 时用设备代码授权法（见 M1 💡）。

**安装方验证**：`tailscale status` 看到客户机名字 + `100.x.x.x windows`。
把客户机的 `100.x.x.x` 记下来——后面所有命令里的 IP 都用它。

## W2. 开 SSH + 放公钥（Windows 不自带，要手动开）

**客户操作**（管理员 PowerShell，一条条粘贴等完成）——怎么开管理员 PowerShell：开始菜单搜 `PowerShell` → 右键 → **以管理员身份运行**：
```powershell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0   # 等 1-3 分钟
Start-Service sshd
Set-Service -Name sshd -StartupType 'Automatic'
```

**先拿用户名**（同窗口，把输出发给安装方）：
```powershell
whoami
# 例如 pc01\wang → 用户名是 wang（反斜杠后面那段）
```

**放公钥**（管理员 PowerShell，整段粘贴）——⚠️ 管理员用户公钥必须放这个特殊位置：
```powershell
$key = "ssh-ed25519 【安装方公钥整串】"
New-Item -ItemType Directory -Force -Path "$env:ProgramData\ssh" | Out-Null
Add-Content -Force -Path "$env:ProgramData\ssh\administrators_authorized_keys" -Value $key
icacls "$env:ProgramData\ssh\administrators_authorized_keys" /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"
Restart-Service sshd
echo "完成"
```

**安装方验证**（用户名 = 对方 whoami 反斜杠后的那段）：
```powershell
ssh -i ~/.ssh/id_ed25519_altai_install 用户名@100.x.x.x "whoami"
# 返回 pc-xxx\用户名 = 通
```

> ⚠️ 坑：`administrators_authorized_keys` 权限必须只留 SYSTEM + Administrators，
> 否则 sshd **静默拒绝**（不报错就是连不上）。普通用户才用 `C:\Users\<用户>\.ssh\authorized_keys`。
> ⚠️ Windows 命令在「管理员 PowerShell」里跑，普通 PowerShell 权限不够会报错。

## W3. 装 Hermes 桌面版（Windows 两种路）

### 有 VPN/代理：官方安装器
1. 官网下载 Hermes-Setup.exe（约 8MB）
2. SSH 无法直接弹 GUI → 用计划任务拉起（管理员 PowerShell）：
```powershell
schtasks /create /tn HermesInstall /tr C:\Users\Administrator\Desktop\Hermes-Setup.exe /sc once /st 00:00 /it /f
schtasks /run /tn HermesInstall
# 验证：tasklist | findstr /i Hermes 看到 Hermes-Setup.exe = 弹出安装窗口
```
3. 让客户在屏幕上按提示点「下一步」完成

### 无 VPN/GitHub 被墙：全手动镜像装
核心思路 = 每个组件从国内镜像拿（uv 走清华、Git 走华为云、仓库走 gh-proxy、npm 走 npmmirror、electron 走 npmmirror 二进制）：
```powershell
# uv（Python 管理工具）
# 从清华 PyPI 下载 wheel 解压取 uv.exe → %LOCALAPPDATA%\hermes\bin\uv.exe
setx UV_PYTHON_INSTALL_MIRROR https://mirror.nju.edu.cn/github-release/astral-sh/python-build-standalone
setx UV_INDEX_URL https://pypi.tuna.tsinghua.edu.cn/simple

# Git → 华为云镜像下 PortableGit → 解压 %LOCALAPPDATA%\hermes\git\ + 加 PATH

# hermes-agent 仓库 → gh-proxy.com 下 ZIP 解压 + git init

# 已 clone 的仓库被墙拉不动（git fetch failed 128 = 安装反复重启的真凶）:
cd %LOCALAPPDATA%\hermes\hermes-agent
git remote set-url origin https://gh-proxy.com/https://github.com/NousResearch/hermes-agent.git

# npm/electron 镜像
npm config set registry https://registry.npmmirror.com
# ELECTRON_MIRROR 指向 npmmirror（版本查 apps/desktop/package.json）
```
日志：`%LOCALAPPDATA%\hermes\logs\bootstrap-installer.log`。

> ⚠️ 判断「卡住 vs 在下载」：下载语音模型（onnxruntime ~100MB + faster-whisper ~200MB）可能
> 10-20 分钟没日志。三证据证明在下载：`tasklist` 看 uv 内存增长 + uv cache 目录变大 +
> `netstat -ano` 看到连 CDN 的连接。

## W4. 装完部署 skills/插件（⚠️ Windows 数据目录不一样！）

**Windows 不是 `~\.hermes\`，是 `%LOCALAPPDATA%\hermes\`**（即 `C:\Users\<用户>\AppData\Local\hermes\`）——放错位置 Hermes 完全读不到！

| 内容 | Windows 位置 |
|---|---|
| 服务端插件 | `%LOCALAPPDATA%\hermes\plugins\<名>\` |
| 桌面插件 | `%LOCALAPPDATA%\hermes\desktop-plugins\<名>\` |
| skills | `%LOCALAPPDATA%\hermes\skills\<分类>\` |
| 配置 | `%LOCALAPPDATA%\hermes\config.yaml` |

```powershell
# 打包传输（小文件多用 tar.gz 一次传比 scp -r 快）
# 本机: tar -czf plugins.tar.gz -C ~/.hermes/plugins api-balance session-timer completion-dashboard context-meter
# scp 到 C:/Users/<用户>/Downloads/
cd C:\Users\<用户>\Downloads
tar -xzf plugins.tar.gz -C "%LOCALAPPDATA%\hermes\plugins\"

# 解压后必须递归删 AppleDouble 污染（._ 开头文件，Mac 打包才会带）:
Get-ChildItem -Recurse -Force -Filter '._*' | Remove-Item -Force

# 服务端插件要 enable（用完整路径的 hermes.exe）
"%LOCALAPPDATA%\hermes\hermes-agent\venv\Scripts\hermes.exe" plugins enable api-balance session-timer completion-dashboard context-meter
```

## W5. 重启 + 验证插件真实加载（Windows 特有坑）

**桌面插件文件放进目录 ≠ 一定加载。必须完整重启 Hermes。**
```powershell
taskkill /f /im Hermes.exe /t      # 杀干净全部 Electron 进程
schtasks /run /tn HermesApp        # 重启
# 等 30-40 秒
Get-Content %LOCALAPPDATA%\hermes\logs\agent.log | Select-String 'Mounted plugin API routes'
# 看到 Mounted plugin API routes: /api/plugins/api-balance/ = 成功
```

> ⚠️ 判断「加载没」不能只看 desktop.log 的 register 日志——有的插件不打。
> 权威判据 = agent.log 的 `Mounted plugin API routes`。怀疑某插件没加载时：
> 给插件 register 函数第一行加 `console.error('[xxx] register called')` → 覆盖 → 重启 → 看日志 → 清掉诊断代码再重启。

## W6. 验收（同 Mac M10，但命令用 PowerShell）

```powershell
curl http://127.0.0.1:8901/api/health          # 你的应用健康
dir "C:\Users\<用户>\AppData\Local\hermes\skills" | Measure-Object   # ≥20
"%LOCALAPPDATA%\hermes\hermes-agent\venv\Scripts\hermes.exe" --version
```

1. 打开你的应用 → 客户自己的 AI 账号 key 填进去 → 实测核心功能
2. 打开 Hermes → 填**客户自己的 DeepSeek API Key**

## 附：特殊情况速查（按症状找）

| 症状 | 原因 | 解法 |
|---|---|---|
| 不知道终端在哪 | 没打开对工具 | Mac：`⌘空格` 搜 Terminal；Win：开始菜单搜 PowerShell（管理员要右键）|

| SSH 首次问 yes/no | 正常 | 输 yes 回车 |
| 用户名不对 | 用了猜的名字 | 让客户跑 `whoami` 发你（Win 取反斜杠后那段）|
| pip 装依赖卡死 | pypi.org 被墙 | 配清华源 `~/.pip/pip.conf` 重跑 |
| 进度面板不动 | 大文件下载中 | 心跳监控；`ps aux \| grep install.sh` 确认进程活 |

| 平台 key 能查列表不能调用 | 用了旧格式 key | 去平台重新创建新格式 key，**直接测真实调用接口** |
| 出图正常但余额不显示 | 缺另一对 AccessKey/SecretKey | 找平台下载的密钥文件（~/Downloads/*.txt），两个都填 |
| 平台配置没生效 | 改完没重启应用服务 | 重启应用（launchd unload/load 或重启 App）|
| 应用管理员密码忘了 | 默认密码 | 登录后改掉；会话 token 过期重新登录 |
| Win 插件不加载 | 没完整重启 | taskkill Hermes.exe /t → 重启 → 看 Mounted routes |
| 客户中途改了 macOS 用户名 → 所有软件打不开、Dock 变默认 | 账户名和 home 路径错位（数据在旧目录，账户指向新空目录），软件里存的 `/Users/旧名/...` 绝对路径全断 | ① 别慌，数据没丢。② `ls /Users/` 找数据在哪个目录（一般在旧名残留目录）。③ 把软件里所有 `/Users/旧名` 的符号链接和配置批量改回真实数据目录。④ 系统账户走正规改名（RecordName + NFSHomeDirectory 一起改，见下方教学）⑤ 让客户注销/重启一次 → Dock、软件全恢复 |
| 客户一直改用户名（多次）| 没走正规改名流程，每次只改一半 | macOS 改账户名必须同时改「账户名称 + 个人目录」两个字段（系统设置 → 用户与群组 → 高级选项），系统会自动搬文件夹、改属主、同步钥匙串。**告诉客户：改用户名叫我们远程来，别自己乱改** |

## 附：方法复盘（为什么这套流程快 + 走过的弯路）

2026-09-07 首台客户机（MacBook Pro）从零到全装好，实际手动耗时很短，靠的是：

1. **搬运成品代替现场安装**：Hermes.app 直接打包传（35 秒），不现场编译 —— 省 20-30 分钟
2. **Tailscale 内网直传**：大文件走加密隧道不走公网，国内不卡
3. **清华源 pip**：下载依赖从「10 秒超时卡死」变「秒连」—— 省无限等待
4. **进度面板 + 心跳监控**：客户全程看到数字在跳，不焦虑不催 —— 省沟通成本
5. **实弹测试代替猜**：key 拿到直接调真实接口（真生成一张图 = 铁证），不「看起来对」

**走弯路的地方（下次避免）**：
- 装 Hermes 先跑了 CLI 安装器 → 客户发现没桌面版 → 返工。**先问清要桌面版，直接搬成品**
- 客户机没 brew 还试装 brew（失败 2 次）→ 其实 python.org pkg 一条命令 12 秒就好。**没 brew 别装 brew**
- 平台 key 验证绕圈（先测列表再测调用）→ 应该**一上来就测真实调用接口**
- 手册写成某个具体产品的说明书 → 下次交付不同产品没法复用。**手册要写成通用的**：产品只是「交付包」，流程都一样
- 手册默认读者懂「终端/SSH/whoami」→ 小白根本不知道在哪敲。**要先讲角色分工、要哪 3 样东西、终端怎么开、命令怎么读**，再给步骤
- 客户中途改 macOS 用户名（wzm→zy 且没走正规流程）→ 全软件打不开、Dock 变默认、Hermes 自触发重装。**根因**：macOS 的账户名和 home 路径是绑定的，软件全存 `/Users/旧名/...` 绝对路径；只改一半 → 路径全断。**修复 40 分钟**：633 个符号链接批量改回 + 系统账户正规改名（RecordName + NFSHomeDirectory 同步）+ 客户注销重登一次 → 全恢复。**教训：① 改用户名叫我们远程来，别让客户自己乱改；② 装完机就把「别改用户名」写进给客户的注意事项；③ 出事先 `ls /Users/` 找数据，别慌着重装**
