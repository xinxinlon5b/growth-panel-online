> 与 CJ-001 关系：CJ-001 讲「报价档位对应决策者」，PRICE-001 讲「为什么这么定 + 怎么定得更聪明」

## 这个子领域在解决什么问题（一句话）

定价解决的是「客户付得起、自己赚得到、长期能涨」三方平衡——用一组合适的定价模型 + 心理锚点 + 价值计量，让单笔交易变成长期关系。

## 核心问题清单

1. **「客户付得起」vs「自己赚得到」的天平怎么调？** 启航包怕饿死，工作站怕赶客
2. **定价该锚定成本还是锚定价值？** 成本定价 = 上限低，价值定价 = 上限高但难解释
3. **订阅 vs 一次性 vs 按用量 vs 按结果 = 怎么组合？** 单一模式会被场景淘汰
4. **三档报价的「中间档锚定」原理怎么用？** 60% 客户选中间档（用户实测）——但前提是档位设计对
5. **什么时候该涨价？涨价幅度多大？** 老客户 vs 新客户、价值锚定 vs 阶梯
6. **国内市场的特殊定价约束？** 买断制习惯、关系型采购、对订阅的天然抵触
7. **怎么用「价值指标」替换「功能清单」做报价？** 不是「交付 5 个模块」，是「让客户每月省 200 小时」
8. **涨价失败、议价、退款的政策？** 没有退款政策的报价 = 高纠纷风险

## 标杆答案

### 来自 OpenView SaaS Pricing Benchmarks（2022 年度报告 + 历年方法论）：

> 「Segmented pricing beats single-tier pricing by 2-3x on conversion. The key insight: SMBs and Enterprises have different budgets, different decision makers, and different value expectations.」

> 「Value-based pricing（价值定价）的最大挑战是「测量价值」——客户拒绝付钱 90% 不是因为贵，是因为「没感知到值这么多」。」

OpenView 的核心数据点（行业内多次引用）：
- 70%+ 的 SaaS 公司从单一定价改为分层定价后，营收增长率提升 30% 以上
- 三档定价中，中间档通常占 50-65% 客户分布（与本卡用户实测 60% 一致）
- ARR ≥ $10M 的公司中，80% 已采用「按用量 + 基础订阅」的混合模式
- 定价变更后 6 个月内客户流失通常 < 5%（前提是「老客户保留旧价」）

**理解**：OpenView 的方法论把定价从「拍脑袋」变成「可测量的工程问题」。三档定价不是「随便分三档」，而是「决策者层级 → 预算来源 → 价值感知」三轴映射的结果。

### 来自 CXL Institute 定价心理学（CXL 是 conversion optimization 的行业标杆）：

> 「Charm pricing（$9.99 vs $10）能提升 5-15% 转化，但只适用于「单次决策」的冲动消费；对 B2B 决策者，charm pricing 反而显得不专业。」

> 「Anchoring effect（锚定效应）是定价最强武器：客户第一眼看到的价格决定了他们对「贵不贵」的判断。三档定价的核心不是「中间档」，而是「高端锚点」——让中间档显得「合理」。」

> 「Decoy effect（诱饵效应）：当存在三种选项时，大多数人会选中间那个，因为极端选项让中间选项显得「刚好」。这就是为什么「启航包 / 工作站 / 近企业」三档永远存在——但「启航包」的存在不只是为了「让客户买中间」，更是为了「让客户付得起验证费」。」

**理解**：CXL 把定价当作「心理学实验」——每一种定价结构都是对客户决策路径的设计。三档定价的本质不是「分三类客户」，而是「操控客户的对比心智」。

### 来自 Lenny's Newsletter / pm-skills「Pricing Models」（业内公认参考）：

**8 种主流定价模型**（按客户付费心智排序）：

| 模型 | 适用场景 | 优劣 |
|---|---|---|
| 一次性买断 | 传统软件、私人项目、风险厌恶客户 | 上限低、关系断；适合「客户买完就走」场景 |
| 订阅（per-seat） | SaaS、团队工具 | 稳定可预测；智能体时代被「按结果」挤压 |
| 订阅（per-usage） | API、算力、积分制 | 与用量对齐；客户用得少 = 收入少 |
| 分层订阅 | 主流 SaaS | 简单清晰；问题在「分层标准」难设计 |
| 按结果 | Sierra 模式（按解决的会话） | 价值锚定最强；测量与归因是难点 |
| Freemium | 病毒式工具、个人创作者 | 转化漏斗长；适合「教育市场 + 付费高级功能」 |
| 市场定价（拍卖/竞价） | 广告位、稀缺资源 | 不适合 AI 工具 |
| 价值分成 | 高客单价深度绑定 | 终极模式；需要客户开放财务数据 |

**理解**：pm-skills 强调「没有万能模型，要按场景组合」。本卡三个项目的实践都是「混合制」（订阅 + 按用量 + 一次性 + 增值服务），这就是中国市场「买断制 + 项目制验收」的本地化变形。

### 来自 FDE-002 第 6 章「按结果收费的四档进化链」：

> 「按用量（token）→ 按任务（per-action）→ 按结果（per-outcome）→ 按价值分成（per-value-share）」

> 「Sierra 按'已解决的会话'收费：客户不为软件付费，为'被解决的问题'付费。年合同门槛约 15 万美元起。」

> 「中国市场的注脚：国内'买断加项目制验收付款'仍是主流，FDE 落地的计价往往是中西合璧：按阶段交付验收（顺应习惯）+ 价值指标写入验收标准（注入按结果基因）。纯订阅制在这里是理想，而混合制才是活路。」

**理解**：FDE 的进化链给本卡提供一个时间轴——定价模式不是静态选择，而是「随客户成熟度升级」的动态路径。启航包客户先接受按用量，工作站客户接受按结果，近企业客户接受按价值分成。

### 来自 xdash FDE 书第 1 章 薪酬数据（用于反推定价空间）：

> 「Palantir 前线部署工程师年总薪酬中位数约 21.5 万美元；头部 AI 实验室中级 FDE 约 38.5 万美元、资深约 61 万美元。」

> 「通古兹红线：给一万美元的合同配一个年薪二十万美元的 FDE，账永远算不过来——这个模式，大约在单份合同 10 万美元以上才开始成立。折算到中国市场，这条红线大致对应大几十万到百万人民币级的项目。」

**理解**：FDE 成本是定价的「地板线」。如果单份合同 < 10 万美元（或 < 30 万人民币），强行派 FDE = 亏钱。三档报价的「启航包 ¥3-8k」如果只用 FDE 交付是亏的——必须用模板化/自动化交付来覆盖。这就是「为什么启航包存在」：它不是为赚钱，是为获客。

## 我们的实战

### 阿尔泰获客系统（启航包 ¥3k → 工作站 ¥30k 转化路径）

阿尔泰的三档报价来自 ALT-001 决策卡，是从 3 个项目实战提炼出来的标准化报价：

| 档位 | 价格 | 内容 | 适合客户 | 决策者 |
|---|---|---|---|---|
| 启航包 | ¥3-8k | 单平台 + 基础 workflow | 个人卖家、跨境小白 | 部门经理拍板 |
| **工作站** | **¥15-50k** | **多平台 + 评分 + 触达闸门 + 自愈 + 每日筛查** | **5 人小团队、大公司事业部** | **CTO/CFO 拍板** |
| 近企业 | ¥80k+ | 多团队 + 审计 + 灾备 + 私有化 | 大公司、大集团 | CEO + 董事会 |

**关键打法**：

1. **三档报价 = 60% 客户选中间档（用户实测）**——但前提是中间档「刚好够用」
   - 启航包缺评分/触达闸门/自愈 → 客户用 1 周就卡
   - 中间档必须能解决 80% 场景，留 20% 给上探空间
2. **工作站档要带「免费价值估算」**——给出「按你日均 1000 条线索、触达率 30% 估算，月节省 X 工时 = ¥X」的数字
3. **续约/扩容时不动基准价**——老客户涨价只涨「席位/用量/模块」，不动底价 = 不破坏信任

**阿尔泰教训**：
- 启航包客户最容易「用完就走」——必须有「上探路径」（加评分 + 加自愈 → 自然升中间档）
- 中间档报价要敢于「不打折」——客户砍 10% 你还能赚 5%，但「砍到底」就变成纯外包了

### NIFTY STUDIO · 纳福（本地 + 云端双链路定价）

NIFTY 的定价是「客户买产品 + 自付云成本」的混合模式，是中国 AI 工具的标准解法：

```
NIFTY STUDIO 本地版 = 一次性 + 终身使用（一次性 ¥5k）
  + LibTV 包月会员 ¥499/月 = 客户自付（云成本）
  + 火山引擎按量 ¥0.20/张 = 客户自付（云成本）
```

**关键打法**：

1. **「产品 + 云成本」分离定价**——本地产品一次性买断，云成本由客户直接付给云厂商（我们不赚差价）
   - 优点：客户对成本完全透明、可控
   - 缺点：客户每次用都「肉疼」云费用，反而更克制（对我们是好事，防止过度使用薅羊毛）
2. **双通道（LibTV 包月 + 火山按量）让客户自选**——预算充足的用 LibTV（包月不限量）；预算紧张的用火山（按量付）
3. **人民币换算 ¥499 = 11250 积分**——把抽象积分换算成具体人民币，客户决策更容易
4. **真实成本核算**——14 积分/张 + 2 积分/质检（不是估算，是后台真实记账）

**NIFTY 教训**：
- 「一次性买断 + 云成本自付」适合「客户懂技术、自己能管」——不是普适模式
- 客户最怕的不是「贵」，是「不知道会花多少」——所以人民币换算 + 每日看板是必须的

### 中俄轻舟（货代费 + 平台费 + Listing 优化服务费）

中俄轻舟的定价是「个人项目 = 自己给自己定价」，看似无关，实则是定价思考的最佳训练场：

```
成本结构：
- 1688 拿货价：¥3-25（按品类）
- 货代费：¥18-50/kg（按线路）  
- Ozon 平台佣金：5-15%（按品类）
- 收款手续费：1-2%
- Listing 优化：自己干（如果外包 ¥20-50/条）

利润公式：
售价 - (拿货价 + 货代费 + 平台佣金 + 收款费) = 单 SKU 利润
```

**关键打法**：

1. **选品 = 利润率优先（≥20%）**——v1 分数排序失败，v2 纯利润成功，最终版是「标题相关性 + 利润率」组合
2. **货代费 = 定价的最大变量**——首单试算表专门列出「盈亏平衡物流成本」，要求全部 ≥ 18.7 元
3. **Listing 优化 = 利润放大器**——同样商品 Listing 优化后转化率 2-3 倍提升
4. **平台佣金 = 隐藏税**——不同类目佣金差 3 倍，选品时必须算进去

**中俄轻舟教训**：
- 个人项目没有「定价 vs 报价」——只有「真实成本 vs 利润」——这反而是最干净的定价训练
- 选品命中率假设是「利润率 ≥20%」，30 天后用真实数据验证
- 客户付费意愿 ≈ 客户感知价值 ≠ 实际成本——定价永远锚定感知价值

## 反模式（不该怎么做）

1. **单一报价（one-size-fits-all）**——客户预算分布在 3k-300k，单一报价要么吓跑 80% 客户，要么饿死自己
2. **报价不分档**——所有客户一个价 = 「让客户自己猜应该付多少」= 失去对比心智 = 转化率最低
3. **按次计费（per-call/per-message）**——客户害怕「用多用少不可控」→ 拒绝签约 → 流失
4. **提前收年费**——客户还没验证价值就收年费 = 「先收钱后做事」= 反向激励
5. **「协商价」没有底线**——客户砍价无底线 = 自己陷入「永远赚不到」的恶性循环
6. **报价含「全包」承诺**——「包含一切变更」= 永远在改需求 = 累死自己
7. **客户报价不带「价值证据」**——只列功能清单，不列「能给客户省多少」= 客户感觉是「买工具」不是「买结果」
8. **涨价靠「加功能」**——老客户价值不变就涨价 = 背叛感；涨价必须绑「新价值」或「新客户」
9. **(扩展) 不区分新客户/老客户定价**——老客户应该有「忠诚折扣」或「续约锁定价」，新客户付全价 = 老客户感觉被宰
10. **(扩展) 报价里不写退款/中止条款**——争议时无据可依 = 高纠纷风险

## 验收问题（看完能回答这 5 个问题就算会了）

1. **三档报价的「60% 客户选中间档」前提是什么？**（前提是中间档「刚好够用」，高端锚点设对，启航包「用一周就卡」逼迫升级。三档不是「分三类客户」，而是「操控对比心智」）
2. **价值定价 vs 成本定价的根本区别？**（价值定价锚定「客户感知价值」，上限高但难解释（90% 拒绝付钱是因为「没感知到值这么多」）；成本定价锚定「我们的成本 + 合理利润」，上限低但稳。本卡三个项目都是「混合制」）
3. **中国市场为什么不能纯订阅？**（客户肌肉记忆是「买断 + 项目制验收」，纯订阅被采购科拒。混合制 = 按阶段验收付款 + 价值指标写入验收条款 + 年度运维合同）
4. **NIFTY「产品 + 云成本」分离定价的优势？**（客户对成本完全透明、可控；我们不赚云差价 = 信任；客户每次用都「肉疼」云费 = 防止薅羊毛。适合「客户懂技术、自己能管」的子人群）
5. **涨价时如何不破坏老客户信任？**（老客户涨价只涨「席位/用量/模块」，不动底价；老客户保留「忠诚锁定价」；涨价必须绑「新价值」（比如「老客户加 ¥X 升级到工作站档」），不能纯涨）
