# COMP-001 合规与法律

> 一句话：跨境 AI 项目合规风险的"必须知道"清单——数据出域、隐私、行业监管、开源协议、出口管制五道红线，触一条就停手。

---

## 5-10 个核心问题清单

1. **数据出域**：用户数据是否离开客户所在司法管辖区？服务器在境内还是境外？
2. **隐私法规**：是否触及 GDPR / 中国《个人信息保护法》/ 俄罗斯 152-FZ 的"个人信息"定义？
3. **行业监管**：金融、医疗、未成年人是否在业务范围内？是否需要额外许可？
4. **平台政策**：调用 VK / TikTok / Ozon API 是否遵守平台 messaging-send-safety 政策？
5. **开源协议**：代码依赖是否含 GPL/AGPL？是否对外提供服务导致强制开源？
6. **出口管制**：模型权重、加密算法是否触美国 EAR / 中国《出口管制法》清单？
7. **税务合规**：跨境收款、店铺主体是否完成 VAT / 税务登记？
8. **用户协议**：是否签署隐私协议？是否明示数据用途与保留期限？
9. **数据本地化**：俄罗斯 152-FZ 要求公民数据本地存储，是否已落实？
10. **第三方处理者**：使用的 SaaS（OpenAI、Anthropic）是否签 DPA（数据处理协议）？

---

## 标杆答案（来源标引）

### 1. GDPR（中国《个人信息保护法》/ 俄罗斯 152-FZ）
- **GDPR**：处理欧盟用户数据须有合法基础（同意/合同/正当利益），DPO 强制任命，72 小时泄露通报，数据可携权、被遗忘权。
- **中国 PIPL**：敏感个人信息需"单独同意"，跨境传输须通过安全评估/标准合同/认证三选一，违规最高 5000 万元或上一年营业额 5%。
- **俄罗斯 152-FZ**：公民个人信息必须存储在俄罗斯境内服务器，跨境传输须先在 Roskomnadzor 备案。

### 2. VK / TikTok API 合规政策（messaging-send-safety）
- **VK**：禁止用个人号群发营销信息，社区号（public/groups）需走 VK Messenger API，禁止绕过风控。
- **TikTok**：禁止未授权抓取、禁止伪造用户身份，私信有频次上限。
- 已有 `messaging-send-safety` skill，触发风控立即降速。

### 3. 阿尔泰跨境电商 VK 教训
- 早期用个人号给 VK 用户发私信触达，账号矩阵被批量封禁，损失 200+ 账号与累积粉丝。
- 教训：**永远用平台官方 API + 社区号，不走灰色触达**。

### 4. GitHub awesome-selfhosted 合规清单
- 自托管优先（数据不出域）。
- 开源协议核对（MIT/BSD/Apache vs GPL/AGPL）。
- 日志审计留痕 ≥ 180 天。

## 我们的实战（必填）

### 阿尔泰：VK 合规触达上限（账号矩阵）
- 触达从个人号私信迁移到 VK Community API + 官方消息模板。
- 账号矩阵按内容主题分群，每个群组保持低频（< 50 条/天/账号）。
- 引入 `messaging-send-safety` skill 自动检测触达节奏，触发风控阈值立即降速。

### NIFTY：本地部署 = 数据不出本机 = 默认合规
- NIFTY 本地部署（macOS launchd + 本地 SQLite），用户合同与生产数据全程不出本机。
- 默认满足俄罗斯 152-FZ 与中国 PIPL 的"本地存储"要求，无需额外跨境合规。
- 备份加密后仅同步到本地硬盘与 Baidu 网盘个人版，不上传境外云。

### 中俄轻舟：Ozon 卖家 API 合规（店铺主体+税务）
- Ozon 卖家以独立法人主体注册，俄罗斯本地银行收款账户 + 当地税务登记号（INN）。
- API 调用走 Ozon Seller API 官方 OAuth2，不抓取非授权接口。
- 财务流水按月导出至本地存档，便于俄罗斯税务局（ФНС）核查。

## 7 个反模式

1. **违规收集数据**：未告知用户就收集位置/通讯录/生物特征。
2. **绕过风控**：用代理/虚拟号绕过平台手机验证。
3. **未签隐私协议**：直接上线产品，ToS 与 Privacy Policy 全无。
4. **强依赖境外 SaaS**：所有用户数据经过 OpenAI/Anthropic，无 DPA。
5. **忽略开源协议**：集成 GPL 库却闭源分发，被起诉才知。
6. **数据无保留策略**：用户注销后数据继续保留 5 年，违反被遗忘权。
7. **单点合规审计**：只在交付前做一次合规检查，无持续监控。

## 5 个验收问题

1. 数据流图是否标注每条数据出境路径与目的国？
2. 是否为每个司法管辖区（EU/CN/RU）准备合规检查表？
3. 调用第三方 API 前是否阅读并记录平台 messaging 政策？
4. 开源依赖清单（SBOM）是否随每次发布更新？
5. 一旦发生数据泄露，是否有 72 小时通报机制与联系人清单？
