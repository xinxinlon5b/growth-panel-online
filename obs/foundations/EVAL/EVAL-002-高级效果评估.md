# EVAL-002 高级效果评估（v2.0 增强版）

> ID: EVAL-002 | 创建: 2026-09-02 | 状态: ⭐ 正式（v1, EVAL-001 增强版）
> 起草原模型: minimax/MiniMax-M3 | 任务来源: Hermes M3 队长派单
> 与 EVAL-001 关系：EVAL-001 讲「怎么判断真有用」（基础评估 + 黄金集 + 103 回归）；EVAL-002 讲「怎么从'能用'升级到'真有用 + 好用 + 续约'」（北极星指标 + JTBD + 业务指标）

## 这个子领域在解决什么问题（一句话）

高级效果评估解决的是「AI 项目从 demo 跑通到客户愿意续约、愿意付更多钱、愿意推荐给同行」的全链路度量——用北极星指标牵引方向，用 Jobs-to-be-Done 校准真实价值，用业务指标体系量化客户终身价值。

## 核心问题清单

1. **「能用」和「真有用」差多远？**——能用 = 跑通 demo；真有用 = 客户改变行为；愿意续约 = 客户离不开
2. **北极星指标（North Star Metric）怎么定？** 不是一个，是「一个核心 + 几个支撑」
3. **「客户买的不是产品，是进步」—— Jobs-to-be-Done（JTBD）怎么用？** 不是「客户要 X 功能」，是「客户要完成 Y 任务」
4. **离线评估 vs 在线评估 vs 业务指标的关系？** 离线是「准入证」、在线是「资格证」、业务是「终极裁判」
5. **怎么避免「指标过拟合」？**——团队优化 GMV → 客户买 1 元退 1 元 = 数字漂亮业务亏
6. **用户活跃度 vs 客户付费意愿的关系？**——日活高 ≠ 续费率高，可能「白嫖日活」反而骗自己
7. **北极星指标的「领先指标」与「滞后指标」怎么配？**——日活是领先，续约是滞后
8. **怎么用「指标」指导产品迭代？**——不是「所有指标都优化」，是「找瓶颈指标重点突破」

## 标杆答案

### 来自 北极星指标（Amplitude / Mixpanel 产品分析方法论）：

> 「North Star Metric（北极星指标）= 一个公司 / 产品 / 功能当前阶段最关键的成功指标。北极星指标不直接等于营收，因为它通常是一个'客户成功的领先指标'。」

**经典案例**：
- Airbnb： Nights Booked（订房晚数）—— 不是 GMV，是「客户实际住宿数」
- Facebook： Daily Active Users（每日活跃用户）—— 早期不是营收，是「用户黏性」
- Spotify： Time Spent Listening（收听时长）—— 不是订户数，是「用户价值感知」
- HubSpot： Weekly Active Team（每周活跃团队）—— 不是 MRR，是「团队黏性」

> 「**核心原则**：北极星指标 = 「**客户价值** × **使用频次**」的乘积。它必须是「客户感知到的价值」的可量化度量。」

**理解**：北极星指标不是「营收」——营收是滞后指标，是北极星指标被优化后的结果。北极星指标必须是「客户为什么留下来」的可量化表达。

### 来自 Jobs-to-be-Done（JTBD，Clayton Christensen + Tony Ulwick 框架）：

> 「客户买的不是产品，是'进步'。他们'雇佣'产品来完成一个 Job；当 Job 被更好地完成，他们就'解雇'旧产品、'雇佣'新产品。」

> 「**核心问题**：当客户'解雇'你的产品时，他用什么替代？——这才是真正的竞争对手。」

> 「**Job 的三要素**：
> - **功能性**（Functional）：客户要完成什么具体任务？
> - **情感性**（Emotional）：客户想感受什么？（安全感、被尊重、成就感）
> - **社交性**（Social）：客户想被他人怎么看？」

> 「**Job Story 模板**：「当我（情境）时，我想（动机），以便（结果）」——比 User Story 更聚焦客户真实需求。」

**理解**：JTBD 是 EVAL-002 的「评估校准器」——不是评估「功能用了没」，而是评估「Job 完成了没」。NIFTY 的客户「雇佣」NIFTY 是为了「3 分钟出套电商图，省美工外包费」——「省美工外包费」是 Job，「3 分钟出图」是 Job 的衡量指标。

### 来自 intellagent 评测框架（EVAL-001 已引用，本卡深化业务指标维度）：

> 「intellagent 的 Multi-dimensional Evaluator 同时测量：任务完成率、工具调用准确性、对话连贯性、安全合规性、成本效率。」

**intellagent 的 6 维评估矩阵**：

| 维度 | 指标 | 业务意义 |
|------|------|---------|
| 任务完成率 | Task Success Rate | Job 是否被完成？ |
| 工具准确性 | Tool Trajectory Accuracy | 过程中是否走对路？ |
| 对话连贯 | Dialogue Coherence | 客户感知是否自然？ |
| 安全合规 | Safety & Compliance | 是否违反规则？ |
| 成本效率 | Cost Efficiency | 每次成功花多少钱？ |
| 客户满意度 | CSAT | 客户是否满意？ |

**理解**：intellagent 的 6 维矩阵正是「北极星指标的支撑指标体系」——北极星指标是「客户终身价值」，这 6 维是「价值被创造的过程指标」。

### 来自 NIFTY 实战：103 项回归 + EVAL-001 黄金集（EVAL-001 的深化）：

**NIFTY 的三层评估金字塔**（EVAL-001 已讲，本卡补充业务层）：

```
业务层（终极）：客户续约率 + 客户日活 + 出图耗时
  ↑
在线层（资格证）：评估达标率 + 解决率 + 接受率
  ↑
离线层（准入证）：103 项回归 + 4 项 e2e + 真烧积分
```

**业务层具体指标**：
- **客户日活** = 每日登录的客户数（黏性）
- **客户续约率** = 90 天后还在用的客户比例
- **出图耗时** = 从「上传」到「生成完成」的时间（用户体验）
- **每客户日均出图数** = 单客户的活跃度（深度使用）

**理解**：NIFTY 的三层评估是「EVAL-001 基础评估 → EVAL-002 业务指标」的过渡桥——基础评估保证「不破」，业务指标保证「客户离不开」。

### 来自 xdash FDE 书 第 6 章「按结果收费的四档进化链」（EVAL-002 的商业对应）：

> 「按用量 → 按任务 → 按结果 → 按价值分成——越往上越贴近客户价值，定价天花板越高。」

**理解**：定价档位 = 评估成熟度的镜像。
- 按用量 = 你能算清楚「调用了多少次」（最基础）
- 按任务 = 你能算清楚「完成多少个任务」
- 按结果 = 你能算清楚「创造了多少价值」
- 按价值分成 = 你能算清楚「客户省了多少 / 赚了多少」

客户愿意为更高档位付钱 = 你能证明更高档位价值 = 你的 EVAL 体系达到了那一档。这是 EVAL-002 的「商业意义」。

### 来自 Amplitude 产品分析经典案例：

> 「指标优化的最大陷阱：优化局部指标 = 伤害整体业务。」

经典反例：
- 优化「点击率」→ 标题党盛行 → 客户点进去发现上当 → 留存暴跌
- 优化「GMV」→ 客户买 1 元退 1 元 → 数字漂亮业务亏
- 优化「日活」→ 推送骚扰 → 客户不胜其烦 → 卸载率上升

> 「**北极星指标的纪律**：
> - 它必须是「**因果链**」上的关键节点（不是结果，是原因）
> - 它必须「**领先**」于业务结果（不是滞后）
> - 它必须与「**客户价值**」同向（不是与公司利益同向）」

**理解**：北极星指标选错了 = 团队往错误方向狂奔。EVAL-002 的核心是「选对指标」。

### 来自 Mixpanel「Funnel + Cohort」分析方法：

> 「**Funnel（漏斗）**：从「注册 → 激活 → 首次价值 → 留存 → 付费」逐级转化分析。每一级的转化率是健康度指标。」

> 「**Cohort（队列）**：同一时期进入产品的客户群，随时间推移的留存/付费曲线。Cohort 比「整体平均」更能反映真实产品力。」

**理解**：Funnel 找「哪一步卡住」（优化对象），Cohort 找「哪批客户是真爱」（优化方向）。两者结合 = 「北极星指标的诊断工具」。

## 我们的实战

### 阿尔泰获客系统（触达率 + 账号健康指标 + 客户回复率）

阿尔泰的业务指标 = 「客户通过我们的系统获得了多少有效销售线索」：

**业务指标三层**：

1. **客户侧指标**（北极星候选）：
   - **客户回复率** = 客户在 VK/TG 上回复我们精聊消息的比例（领先指标，领先「签约」3-7 天）
   - **客户日活** = 客户每天打开看板的次数（黏性指标）
   - **客户签约率** = 从「试用」到「签约」的比例（转化指标）

2. **平台侧指标**（账号健康）：
   - **触达率** = 已读 / 已发送（每个平台不同：VK 50-70%，TG 80%+，IG 30-50%）
   - **账号健康** = error 984 触发次数 + 风控告警次数
   - **DNC 拦截率** = 100%（永不触达黑名单）

3. **业务侧指标**（终极）：
   - **意向线索数 / 月** = P0 + P1 等级（最有价值）
   - **成交线索数 / 月** = 真正付费的客户
   - **AI vs 人工占比** = 自动化率（成本效率）

**阿尔泰的「北极星」候选 = 客户签约率**——这才是客户真正感知价值的指标。其他都是支撑指标。

**阿尔泰的「指标陷阱」预警**：
- 「日均线索数高 ≠ 业务好」——可能是无效线索（同行/僵尸号）混入
- 「转人工率高 ≠ 业务好」——可能是 AI 答不上来（能力缺陷）
- 「触达率高 ≠ 业务好」——可能是「读但不回」（无效曝光）

**阿尔泰的教训**：**只看单一指标 = 必被骗**。必须三层指标互相对照（业务 + 平台 + 客户）才能发现真相。

### NIFTY STUDIO · 纳福（出图耗时 + 客户日活 + 续约率）

NIFTY 的业务指标 = 「客户每天用我们生成多少张图，多快生成」：

**业务指标三层**：

1. **核心业务指标**（北极星候选）：
   - **出图耗时** = 从「上传」到「生成完成」的中位时间（用户体验）
   - **每客户日均出图数** = 单客户的活跃度（深度使用）
   - **客户续约率** = 90 天后还在付云成本的客户比例

2. **产品健康指标**：
   - **103 回归通过率** = 100%（EVAL-001 离线层）
   - **生产评估达标率** = GVLM pass 比例（EVAL-001 在线层）
   - **客户日活** = 每日登录的客户数（黏性）

3. **商业指标**：
   - **客户终身价值（LTV）** = 单客户年消费（云成本 + 可能的升级费）
   - **客户获取成本（CAC）** = 销售成本 / 新客户数
   - **LTV/CAC** = 健康线 3+，NIFTY 早期可能 < 2 必须配 NRR 读

**NIFTY 的「北极星」候选 = 客户续约率**——这是「客户真正离不开」的硬指标。出图耗时和日均出图数是支撑指标。

**NIFTY 的「指标对齐」纪律**：
- 「客户日活高 ≠ 续约率高」——客户可能「白嫖」免费功能，活跃但不愿付费
- 「生成数高 ≠ 客户满意」——可能生成后下载就丢，没真正用
- 「103 回归全绿 ≠ 客户成功」——内部完美 + 客户失败 = 项目失败

**NIFTY 的教训**：**评估指标必须分层**——离线层（103 回归）保「不破」，在线层（GVLM 评估）保「质量」，业务层（续约率）保「客户离不开」。三层缺一不可。

### 中俄轻舟（Listing 转化率 + 出单率 + 退款率）

中俄轻舟是个人项目，业务指标最朴素也最有效：

**业务指标三层**：

1. **业务北极星**：
   - **出单率** = 9/22 第一单目标 → 9/30 回款目标 → 月度出单数
   - **Listing 转化率** = 下单数 / 浏览数（Listing 质量）
   - **退款率** = 退款数 / 出单数（Listing 与商品质量）

2. **选品指标**：
   - **选品命中率** = 30 天后出单的 SKU 数 / 上架 SKU 总数
   - **利润率** = (售价 - 成本 - 物流 - 佣金 - 收款费) / 售价（≥20% 才合格）

3. **过程指标**：
   - **询价回复率** = 1688 供应商回复 / 询价发出
   - **货代报价速度** = 询价发出到收到报价的小时数
   - **上架成功率** = 成功上架的 SKU / 计划上架 SKU

**中俄轻舟的「北极星」 = 出单率**——这是「业务真实成立」的硬指标。其他都是支撑。

**中俄轻舟的「指标陷阱」预警**：
- 「上架数高 ≠ 业务好」——可能是低质铺货（Listing 转化率会暴露）
- 「曝光数高 ≠ 业务好」——可能是定价错误（高曝光低点击 = 贵了）
- 「利润率 ≥20% ≠ 真实利润」——可能没算退税、隐藏佣金、汇率波动

**中俄轻舟的教训**：**个人项目的指标必须简单**——出单率 / 转化率 / 退款率 三件套足够。别为了「指标体系完整」搞复杂指标，导致每天花 2 小时看数据而不是 2 小时做业务。

## 反模式（不该怎么做）

1. **只看 demo 通过**——demo 数据 ≠ 真实场景（EVAL-001 反模式 1）
2. **不量化的「好」**——「用户反馈挺好」没价值（EVAL-001 反模式 2）
3. **「用户说好用就行」**——主观满意度 ≠ 客观指标（EVAL-001 反模式 3）
4. **指标过拟合到单一北极星**——只优化北极星 = 局部最优 = 整体崩溃
5. **「虚荣指标」（vanity metrics）陷阱**——日活、下载量、注册数 = 容易看但难行动；优先选「可行动指标」（actionable metrics）
6. **指标自评（团队自己评自己）**——「老板说做得好」≠ 「客户用得好」；必须有外部信号（续约、转介绍、复购）
7. **北极星指标选错（优化点击率却伤害留存）**——必须做「因果分析」而不是「相关性分析」
8. **没有 Cohort 分析**——只看「整体平均」会掩盖「老客户 vs 新客户」的差异
9. **指标太多 = 没有指标**——每个项目核心指标 ≤ 5 个，否则团队无所适从
10. **(扩展) 指标更新太频繁**——北极星指标是「季度级」的，不是「周级」的；频繁切换 = 团队失去方向

## 验收问题（看完能回答这 5 个问题就算会了）

1. **北极星指标不是「营收」是什么？**（北极星指标是「客户成功的领先指标」= 「客户为什么留下来」的可量化表达。营收是滞后指标，是北极星指标被优化后的结果。Airbnb 用 Nights Booked、Spotify 用 Time Spent Listening——都不是营收，而是「客户价值感知」的度量）
2. **「客户买的不是产品，是进步」怎么用？**（JTBD 框架：客户「雇佣」产品完成 Job；当 Job 被更好地完成，他们就「解雇」旧产品。NIFTY 客户「雇佣」NIFTY 是为了「3 分钟出套电商图，省美工外包费」——评估的不是「用了几个功能」，是「Job 完成了没 + 省了多少 / 赚了多少」）
3. **「虚荣指标」vs「可行动指标」的区别？**（虚荣指标 = 容易看但难行动（DAU、下载量、注册数）；可行动指标 = 难行动但能改（激活率、首次价值时间、7 日留存）。前者让团队自我感觉良好，后者让团队知道「下一步该做什么」）
4. **北极星指标的「领先性」为什么重要？**（北极星指标必须「领先」于业务结果。续约率是滞后指标（要 90 天才知道），回复率是领先指标（领先「签约」3-7 天）。看领先指标 = 实时调整；看滞后指标 = 90 天后才知道错在哪）
5. **怎么避免「指标过拟合」？**（三个纪律：① 核心指标 ≤ 5 个，太多 = 没有；② 必须做 Cohort 分析（不只看「整体平均」）；③ 季度级更新（不频繁切换）。阿尔泰教训：只看单一指标 = 必被骗；必须三层互相对照（业务 + 平台 + 客户））
